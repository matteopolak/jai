# Executable object and container parsing

The `executable_formats` facade loads independently authored ABI declarations and
bounded object/container algorithms under `internal/executable`. Work began from
independent candidate `ad575d16`. No original implementation, reference, corpus
library bodies, quarantined integration or repository history was consulted.

The reviewed declaration audit is **467/508 present, 41 remaining**. The original
507-row scope gained the reviewed `Arch_File` declaration. These are declaration
counts, including constants and types, not algorithm counts or a full-module
completion claim. [Exact remaining rows and source state](implementation-scope.json)
are generated by `tools/audit_executable_scope.py`. Four raw ABI declarations and
37 lexer/TBD declarations remain. [Public questions](worker-inbox.md) track the
incomplete nested nlist shape, absent canonical Debug_Info.Guid dependency, a
reviewed ELF endian constant discrepancy, and unspecified lexer/TBD behavior.

## Implemented object workflows

| Format | Supported independent implementation |
| --- | --- |
| Mach-O | Native little-endian 64-bit headers, command envelopes, segment sections, relocation ranges, symbol names/types/flags and DWARF section discovery. Signature probe also recognizes 32-bit/swapped magic; parsing rejects those layouts. |
| ELF | Little-endian ELF64 headers/programs, section tables and extended table counts, static/dynamic symbols, RELA metadata, strings, section names and DWARF sections. ELF32, swapped data, REL and extended symbol section indices reject. |
| COFF | Ordinary i386/amd64/arm64 object headers, packed 18-byte symbols and 10-byte relocations, auxiliary-symbol counts, short/long names, sections and string tables. BigObj and overflow relocation tables reject. |
| PE | PE32 and PE32+ optional headers, bounded data directories and debug directory RVA mapping, plus the COFF section/symbol workflows. |
| Universal | Fat32 and Fat64 in either byte order, checked entry counts/ranges/alignment, reserved words, duplicate architecture identities and overlapping payloads. Architecture bytes need not themselves be Mach-O. |

All parsers check bounds before constructing borrowed typed views. Mach-O and ELF
require naturally aligned native record locations; unaligned memory-input layouts
reject. Ordinary COFF symbol/relocation records use their packed wire alignment.
COFF unwind/pdata helpers decode into aligned allocations because genuine clang
objects place these payloads at unaligned file offsets. The APIs return empty
aggregates on failure and clean temporary derived arrays. Path overloads release
their file buffer on failure. Signature predicates are not full validation.

Mach-O raw bitfield helpers use exactly the reviewed stored words and masks;
setters preserve unrelated bits and truncate the assigned value to field width.
The separate reviewed raw and typed Mach-O record names are retained. No compiler
format-name exceptions, duplicate replacement parser models or stub procedures
were introduced.

## Object ownership and relocation policy

These are chosen independent policies because reviewed declarations do not
promise historical ownership behavior:

- Memory parsers borrow input bytes. Headers, sections, symbol/string tables and
  section data remain valid while that input remains alive and unmodified.
- Successful path parsers transfer `content` to the caller; free it only after
  all borrowed views are finished.
- Mach-O owns the `load_commands`, `sections` and `symbols` array storage.
  Universal owns `files`. COFF owns only the outer `section_relocations` array;
  its inner relocation tables borrow the input. ELF metadata allocates no arrays.
  Release owned arrays with Basic's `array_free` under the matching allocator.
- `get_pdata` returns an owned array. Successful `get_xdata` returns owned
  `unwind_codes` and, when present, one owned union payload pointer. Free those
  with `array_free` and `free`. Version 1 unwind data is supported; the frame
  offset field reports its encoded four-bit scale value. Handler/chained tails
  are bounded; unsupported versions/opcodes fail.
- Symbol and string lookup results borrow input. Value-taking fixed-name helpers
  (`get_section_name` for Mach-O/COFF and `get_segment_name`) return temporary
  allocator copies, so they never expose pointers into a returned stack frame.
  `string_from_zero_padded_array` borrows its supplied array.
- Basic checked allocation behavior applies; allocation exhaustion is not
  promised to recover as a false parse status.

Relocation application validates all patches before writing, rejects overlapping
patches and leaves output unchanged on failure. Coordinates are metadata section
addresses, not arbitrary process load addresses. ELF handles defined/absolute
symbols, amd64 64/PC32/PLT32/32/32S and arm64 ABS64/32/16 and PREL64/32/16/PLT32.
COFF amd64 handles ADDR64/32/32NB, REL32 through REL32_5, SECTION and SECREL.
Undefined symbols, unsupported kinds, overflow and unresolved GOT/runtime work
reject; 64-bit calculations currently require signed-64-representable addresses.
The ELF API returns false; COFF's reviewed void API prints a rejection diagnostic.
Neither API resolves external symbols or acts as a dynamic linker.

## Verification

Build source tools under the assigned T7 `CARGO_TARGET_DIR`:

```sh
cargo build -j2 -p jaic-cli -p jailint
"$CARGO_TARGET_DIR/debug/jaic" jaifmt/main.jai -O2 -exe target/jaifmt
python3 tools/check_executable_formats.py
```

The runner passes interpreter and **native Mac arm64 O0/O2 execution** for objects,
bitfields, relocation arithmetic and the unchanged archive regression suite.
Formatting and warnings-denied lint pass. Linux and Windows x64 **cross type
checks** pass; those targets were not executed. The ELF/Windows object fixtures
are cross-compiled data consumed on Mac, not evidence of target execution.

Original C source produces actual Mach-O/ELF/COFF objects. SDK clang, otool and
native header static assertions, lipo and lld-linked ELF/PE images, and LLVM
readobj independently inspect the format data. The fixture generator authors
all four fat byte encodings and malformed command/count/offset cases. Tests cover
every truncated prefix of real objects and PE images, each synthetic fat variant,
borrowed pointers, array cleanup with a tracking allocator, packed ABI sizes,
actual symbols/DWARF/unwind data, and atomic relocation failure. Generated native
tool outputs may carry platform metadata and are intentionally untracked.

Official format inputs are native SDK `mach-o/loader.h`, `nlist.h`, `fat.h`,
Microsoft's [PE/COFF format specification](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format),
and the ELF gABI [symbol](https://gabi.xinuos.com/elf/05-symtab.html) and
[relocation](https://gabi.xinuos.com/elf/06-reloc.html) descriptions. Parser bodies
were independently authored.

Read-only clean-room review identified and reproduced three issues before commit:
relocations used output capacity rather than section extent, Arm narrow absolute
relocations used unsigned-only ranges, and ELF interpreted undefined null-program
fields. Regressions first failed, then passed after repairing both relocation
paths and the segment validation policy. Arm ranges follow the official
[AArch64 ELF ABI](https://github.com/ARM-software/abi-aa/blob/main/aaelf64/aaelf64.rst);
unused program records follow the [gABI program-header contract](https://gabi.xinuos.com/elf/07-pheader.html).
The same regressions execute in the interpreter and native O0/O2 runs. Expected
COFF rejection diagnostics are asserted in full rather than suppressed.

## Preserved archive workflow

The archive parser bounds every member/header/padding/name/index read. It supports
ordinary names, BSD embedded names, GNU newline and COFF NUL long-name tables,
32-bit big-endian GNU/first linker indexes, little-endian COFF second indexes and
32-bit BSD ranlib indexes in either byte order. Symbol offsets must identify an
actual returned member header; a binary search checks the ordered member list.
Special index/name-table members are represented through metadata rather than
ordinary files. Thin, 64-bit-index and unknown archive formats return failure.
The BSD format has no endian tag: little endian is attempted first, then big
endian after bounded validation. Ambiguous interpretations require contract review.
The COFF second index supplies returned ordering; both indexes are validated,
but their symbol sets are not cross-compared. Empty symbol names reject.

`parse_ar` borrows its input bytes, member names/data and symbol names. The caller
owns the three separately allocated result arrays and frees them with Basic's
array deinitializer under the matching allocator. `parse_ar_file` also transfers
its allocated `content` to the caller on success; failure releases that buffer.
Failure returns a fully empty aggregate after cleaning temporary arrays. The
reviewed API has no archive deinitializer or allocator field, so none is invented.
Exact special-member visibility, diagnostic text, endian selection and returned
ownership conventions need review. Allocation failures currently use Basic's
checked allocation behavior rather than promising recoverable false status.

The existing universal predicate recognizes the four native fat magic byte
sequences. The newly reviewed `Arch_File` shape now supports the real universal
parsers described above.

Format facts were checked against official native SDK `ar.h`, `ranlib.h` and
`mach-o/fat.h`, the [GNU ar manual](https://sourceware.org/binutils/docs/binutils/ar.html),
the [LLVM native archive header](https://github.com/llvm/llvm-project/blob/main/llvm/include/llvm/Object/Archive.h)
and Microsoft's [archive format documentation](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#archive-library-file-format).
No parser implementation bodies were copied.

`tools/build_portable_archive_fixtures.py` builds original wire fixtures and a
real native object/archive from original C source using host tools. Tests check
borrowed pointers, layouts, all supported index variants, native symbols,
malformed counts/offsets/strings/headers/padding, every truncated simple-member
prefix and zero outstanding allocations. Tests run interpreter/native; the
previous File dependency no longer prevents Windows cross type checks in this
checkout. Fixture regeneration is deterministic for original wire
data; host native archives may carry tool/platform metadata.
