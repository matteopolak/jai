# UI and drawing

## What it is

`Simp` provides independently authored immediate drawing, CPU bitmap rendering, native OpenGL submission, bitmap/texture helpers, and FreeType text layout. `GetRect` implements the maintained OpenJai button, slider, dropdown, theme, and frame APIs. `GetRect_LeftHanded` preserves historical UI layout contracts and supplies authored widget, editing, layout, subwindow, and color-editor flows with downward-positive coordinates. Declaration presence and source bodies remain separate from behavior acceptance.

The maintained GetRect input has empty or fixed-answer UI bodies. This implementation supplies real state and interaction behavior; those original bodies are not copied or used as tests. Simp follows the newer Focus module API. The older GetRect font protocol is retained through explicit additional Simp overloads rather than changing the maintained `Dynamic_Font` layout.

## How it works

### Drawing and resources

Simp stores its immediate vertex buffer in `context.simp`. Shader, texture, render-target, and scissor changes flush queued triangles before changing state. Quads become two triangles; the CPU backend uses half-open edge ownership to avoid blending shared diagonals twice. CPU targets store top-first RGBA8/BGRA8 rows while draw coordinates are bottom-first. Images flip their texture V coordinate; glyph atlas coordinates already include their row orientation.

`Texture_Format` sizing supports byte formats, floating/integer formats, depth formats, and block-compressed formats. Unsupported formats and overflowing dimensions return zero sizes. Bitmap mipmaps use tightly packed levels after level zero, box averaging, and approximate gamma conversion for the sRGB flag. Actual texture upload supports a narrower set: CPU sampling uses 8-bit component formats; OpenGL upload supports R/RG/RGB/RGBA/BGRA8 and R/RG/RGBA16F/32F. A size calculation for a compressed or depth format does not imply upload or rendering support.

The software backend draws colors, sampled images, grayscale glyph coverage, rounded rectangles, and RGB/HSL gradients. Rounded-rectangle `size` is the half extent, matching the maintained calling convention. Gradient `rect` is `(x,y,width,height)`; the low nibble selects R/G/B/H/S/L, with `0x10` vertical and `0x20` horizontal one-dimensional variants.

The OpenGL backend compiles its own GLSL 330 sources, checks compilation/link status, uploads vertices through a VAO/VBO, uploads textures, and checks framebuffer completeness. The application must make a trusted native context current and pass initialized `GL.GL_Procedures` to `initialize_opengl_renderer`. Simp does not invoke the unavailable native context-creation adapters or assume shader compilation succeeded. `opengl_make_window_current` optionally switches a caller-owned context between windows.

`clear_render_target` flushes drawing and clears the selected CPU/native target, honoring the current scissor. `backend_init` selects the host-owned window target. Window presentation uses `window_present_sink(window,vsync)` and reports a missing callback or failed presentation. `pixel_read_begin` captures a source texture or the selected render target. The CPU path takes an independent RGBA8 snapshot immediately; the OpenGL path uses a pixel-pack buffer and fence, with a temporary read framebuffer when the source is a texture. `pixel_read_is_done` polls the fence, and `pixel_read_end` waits/maps when needed, creates the caller-owned bitmap, and releases the reader. `pixel_read_cancel` releases an unfinished reader. Begin, end, and cancellation must use the same current native context; complete every reader before destroying its context or target. The native path restores read-framebuffer, pixel-pack-buffer, pack-alignment, and pack-row-length state and checks framebuffer, wait, map, unmap, and GL errors.

Screenshot output supports R8/RG8/RGB8/RGBA8/BGRA8, nearest-neighbor resizing, exact piecewise sRGB transfer, and an explicit row flip. `flip=false` returns bottom-first rows; `flip=true` returns top-first rows. Compressed/depth/float destinations and cube/array/volume/buffer/multisampled sources return a failed begin rather than a fabricated reader. Screenshot state is not thread-safe and has no implicit context-shutdown registry cleanup. Its semantic fixture is blocked before assertions; neither CPU readback nor GPU readback has passed a behavior check.

Bitmap decoding and encoding call the declared stb adapters and return the codec result. A procedure declaration does not establish that the corresponding adapter library exists. No supplied image, font, library, object, compiler, or native executable is copied into this implementation.

### Fonts

FreeType creates a memory-backed face at a requested pixel height. Simp owns a copy of the bytes for the face lifetime. Glyph lookup keys include codepoint, anti-aliasing, hinting, and fallback selection. Stable glyph pointers refer to shelf-packed RGB atlas pages; dirty pages upload before drawing. Layout decodes UTF-8, records byte positions and kerning-adjusted advances, then generates quads from the prepared glyph list.

The maintained font record fields remain unchanged. Private `Font_Record` entries hold prepared positions, source byte offsets, and source bytes. `get_cursor_pos_for_width` returns a UTF-8 byte boundary. `get_prepared_text_width` is an additional accessor for the older GetRect protocol. `Font_Effects` and the memory-only font overload are explicit legacy additions: only zero effects and `NO_KERNING` are implemented; unsupported substitutions assert instead of silently pretending to apply them.

LCD glyphs are rasterized by FreeType, but CPU and OpenGL drawing average RGB coverage into ordinary alpha. This is not the original dual-source subpixel blend. There is no shaping engine or grapheme-aware editing. `draw_code` uses character cells and tabs; full selection tab markers, exact highlight indexing through invisible glyphs, and original dithering are unfinished.

Call `deinit(bitmap)` or `deinit(texture)` to release their resource storage; free heap-created texture descriptors afterward. `deinit(font)` releases a font's face, bytes, glyphs, and prepared storage but leaves descriptor ownership to the caller. `deinit_fonts()` destroys the remaining live font descriptors and shared atlas pages. Flush pending drawing before destroying external render targets or shutting down a native context. `shutdown_opengl_renderer()` destroys shader programs and immediate buffers, so it must run while their context is current. Texture registry records and per-thread immediate state currently persist; complete application teardown is still an API gap.

### Right-handed GetRect

`stdlib/GetRect` is the standard right-handed GetRect (y-up, float32 `Rect`, `Window_Type` windows). It is the former historical right-handed implementation promoted to the default module; the earlier small float64 module and its `interaction.jai` were removed. Details are in [right-handed GetRect](getrect-legacy-right-handed.md) and [right-handed UI](getrect-legacy-right-handed-ui.md). `ui_per_frame_update`, pointer coordinates, scissors, text baselines, and quads convert at the Simp boundary so widget code stays y-up. Note `dropdown` returns `(changed: bool, Dropdown_State)` as in the standard module.

The right-handed and left-handed modules still carry parallel copies of most files; the real differences are orientation helpers (`orientation.jai`, `geometry.jai`), `regions.jai` scroll/divider/subwindow math, `colors.jai`/`color-surfaces.jai` row order, `text-flow.jai`, and a few `ui.jai` baseline/popup/scissor lines. When fixing a shared bug, apply it to both directories.

### Historical left-handed GetRect

`legacy-layouts.jai` and `advanced-layouts.jai` contain public type/layout/default contracts normalized from the read-only supplied API. This includes the complete `Overall_Theme` fields, referenced themes, and the additional region/subwindow/editor state records. Declaration presence is not counted as an implemented widget. The independently selected preset palettes share the public preset names and field layouts; their appearance does not claim original palette parity.

The authored behavior in `ui.jai` covers stable typed state lookup, balanced state/scissor stacks, frame/window input routing, active widgets, tooltips, theme sizing, rounded shapes, labels, buttons, checkboxes/radio buttons, sliders, dropdowns, popup ordering, and bounded UTF-8 text editing. State identity uses caller location plus an explicit identifier; state-table duplicate insertion keeps distinct widget types stable when hashes collide.

Text editing uses the public fixed-size buffer and UTF-8 byte boundaries. The authored flow includes pointer/word selection, drawn selection and caret scrolling, insertion/deletion, word navigation, history, provider-based completion, and clipboard copy/cut/paste. Completion/history strings are copied into UI-owned storage. Number inputs use their real embedded text state and commit through a parse callback or authored string parser; slider text entry uses separate stable editor storage, while spinboxes and drags update the caller value. Integers routed through slider float64 arithmetic can lose precision outside its exact integer range. The relative-drag initial-outside-range clamp option now uses a typed saved initial value and affects drag clamping.

Scrollable regions pair begin/end calls around clipped content and compute scroll extents from the supplied drawn bounds; slidable regions pair a first/second clip switch with `finish`. Subwindows queue callbacks for popup drawing, retain caller-owned `Subwindow_Info`, and handle move, raise, close, edge/corner resize, ratio constraints, and snapping. Widgets under a registered subwindow are rejected by a private topmost-window hit test. Public occlusion helpers keep two frame-buffered record arrays. Drawing registers next-frame coverage; a stable descending-serial scan chooses the preceding frame's topmost blocker for the current window. Scoped child widgets may interact through their owning occluder, and balanced start/finish calls may update a rectangle after layout. This intentionally takes one frame for a newly registered occluder to affect earlier drawing; private same-frame subwindow coverage also rejects a covered registered window. Exact original interaction timing remains unverified.

Color pickers supply a hue ring/SV plane, HSV/RGB sliders, numeric fields, stashes, and apply/revert controls. Hue fields use degrees. Right-click in the circle area toggles an authored radial square-to-disk warp, with an inverse used for dragging and a polar color mesh used for drawing. Right-click in the HSV controls toggles the SV plane and separate sliders; a hue-zoom slider uses the retained zoom center/range. These modes have real bodies, but their geometry and appearance do not claim original formula or palette parity. Cosmetic timing fields are still not fully applied. Color animation editors create, drag, delete, and edit keyframes; sample RGB/HSV/Oklab using linear, quadratic, or Hermite interpolation; and supply color-picker/time-view subwindows and clipboard output. Oklab conversion uses published coefficient data from [the color-space creator](https://bottosson.github.io/posts/oklab/), independently expressed through matrix helpers. Rendering appearance, boundary interpolation, and interaction behavior are unverified.

Text flow preserves borrowed styled/font pieces across UTF-8 width-based hard wraps and newlines. Flowed piece arrays are UI-owned and released by `deinit(flowable_text)`; input text, fonts, and unflowed pieces remain caller-owned. Text display clips/scans visible lines, supports pointer selection, and copies selected text. It does not implement shaping, grapheme movement, or the historical topic/console integration helpers. Caller-supplied `Draw_Procs` are required for custom `Type_Indicator` renderers. Windows and macOS default cursor helpers initialize borrowed stock system cursors through the authored native bindings; `pointer_image_sink` or a supplied callback overrides them. Set cursor requests persist to the frame boundary and the default resets only when no widget requested a cursor. AppKit targets use the closed-hand stock cursor for diagonal movement; a provider can supply diagonal artwork. Other targets require a cursor provider. Native cursor behavior is unverified. `ui_deinit` releases retained widget states, editor/history/completion storage, popup/scissor/input buffers, and private subwindow records; caller fonts, textures, info records, and input pieces remain caller-owned.

The compatibility helpers in `compatibility.jai`, `occlusion.jai`, `cursors.jai`, `color-compatibility.jai`, and `color-surfaces.jai` share the production text, region, and interpolation paths. The new compatibility fixture loads those actual production helpers and covers line splitting/sanitization, selection replacement, typed initial values, reversible warp coordinates, and occlusion order/ownership. All 11 changed/new compatibility source files lex and parse on the same frozen snapshot after repairing an authored aggregate-literal spacing error. The fixture and whole module stop at the GL procedure-table modifier before assertions; this adds no behavior acceptance.

## How to change it

Keep public contracts separate from behavior. Both GetRect modules share `GetRect_Common/` (see [shared implementation](getrect-shared-implementation.md)); change right-handed integration or left-handed behavior in `GetRect_Common/ui.jai` behind the `GETRECT_Y_UP` branches. Preserve legacy field/default contracts in `legacy-layouts.jai` and `advanced-layouts.jai`. Region/subwindow behavior is in `regions.jai`, text editing in `text-interaction.jai`, flowed display in `text-flow.jai`, color controls in `colors.jai`, pure conversion helpers in `color-math.jai`, and preset palette construction in `theme-presets.jai`. Keep paired state/scissor operations balanced, copy retained strings, and leave borrowed callback data untouched. Record any unsupported additions. Rectangle arithmetic and module entrypoints belong to the separate [math and numeric](math-numeric.md) lane.

Simp resource storage lives in `bitmap.jai` and `texture.jai`, batching/CPU rasterization in `immediate.jai`, draw state in `shader.jai`, font preparation in `font.jai`, actual native submission in `backend/gl.jai`, and reader lifetime/conversion in `readback.jai`. Extend both the CPU and OpenGL gradient paths when introducing a mode. Add native formats only after implementing and checking their upload and sampling behavior; arithmetic sizing is a separate contract.

The source fixtures exercise actual production helpers and render/widget flows. They are not acceptance receipts until their `#assert #run` checks finish successfully. Keep the manifest `stdlib/.coverage/ui-drawing.json` current after changes; it separates public declaration coverage, nonempty authored bodies, parser checks, blocked semantic/VM checks, and native behavior.

## Configuration

Import Simp with `render_api=.SOFTWARE` for bitmap targets or `.OPENGL` for a caller-owned GL 3.3 context. `.NONE` and `.METAL` have no backend and fail explicitly if drawing is requested. `window_dimension_query`, `software_window_target`, `window_present_sink`, and `opengl_make_window_current` integrate host-owned windows. A CPU render-target texture needs RGBA8/BGRA8 for framebuffer writes. Color-index text drawing requires `set_color_map`.

`init_fonts(page_width,page_height)` defaults to 2048 by 1024; custom atlas dimensions must be 64..32767. Anti-aliasing defaults to `.lcd`, hinting to true, and selection-tab visibility to true. The selection-tab setting is retained but its full draw-code effect is unfinished. Native codec libraries use the names declared by their authored bindings; consult [codec/native bindings](codec-native-bindings.md) for availability and provenance.

Source-only validation selects the independent tree explicitly:

```sh
JAI_RS_STDLIB="$PWD/stdlib" \
JAI_RS_PRELOAD="$PWD/stdlib/Preload.jai" \
JAI_RS_RUNTIME_SUPPORT=off \
<frozen-jai-rs> check stdlib/Simp/tests/software-render-tests.jai
```

## Dependencies

Authored modules: `Basic`, `Math`, `String`, `Hash_Table`, `Input`, `Window_Type`, and `Clipboard`. Native drawing uses actual `GL.GL_Procedures`; fonts use the declared system FreeType binding; codecs use the declared stb adapter libraries. Compilation still depends on the compiler's module parameters, context additions, generic records/procedures, overlays, procedure-field defaults, and compile-time VM support. No unknown compiler intrinsic is introduced.
