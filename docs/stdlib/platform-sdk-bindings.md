# Platform SDK bindings

## What it is

`stdlib/POSIX`, `POSIX_old`, `Linux`, `macos`, `Android`, `Objective_C`, and the four `Windows*.jai` entry files provide normalized platform API contracts and independently authored wrappers. All 472 supplied wrapper-body occurrences now have independently authored implementations. Native behavior remains unverified.

The rewrite reads `reference/modules` only for API names, types, fields, defaults, constants, signatures, and module structure. It does not execute reference code or load, link, copy, or depend on shipped reference native binaries. Original procedure bodies, generator workflows, compile-time insertion code, and Windows manifest implementation templates are discarded.

## How it works

`tools/rewrite_platform_sdk_contracts.py` uses a position-preserving lexer to mask comments and strings, locate complete procedure bodies, and discard them before emission. It normalizes declaration formatting and maps approved native declarations to system SDK libraries. A declaration inventory excludes procedure parameter names and procedure-local declarations; it includes private declarations, record fields, enum members, and repeated platform branches.

Source-only inventory and frozen-parser results are saved in `stdlib/.coverage/platform-sdk-bindings.json`. The current pass covers 82 reference runtime source files containing 60,946 lines and 32,977 declaration occurrences. Nine independent helper files bring the emitted total to 91 files. Fourteen reference generator, example, test, or build files are excluded.

The emitted sources contain 5,974 direct SDK foreign declarations. All 472 reference procedure bodies were discarded and replaced with independent implementations, and none retain unresolved adapter contracts. These numbers count occurrences across platform branches rather than unique exports. The JSON includes per-file inventories, individual signatures, removed libraries, syntax adaptations, and source authority limits.

Independent implementations cover:

- POSIX thread-local errno access, file-mode tests, Linux/Darwin wait-status interpretation, and Linux `stat` compatibility wrappers over the public libc functions.
- Linux `io_uring` setup, entry, and registration through the trusted libc `syscall` entry; the signal-mask form supplies the kernel signal-set size and the extended form supplies its structure size.
- CoreFoundation string creation/conversion and VM tag construction. Converted Jai strings are allocated through `Basic`; callers free successful allocated results. Created CF strings follow the CoreFoundation Create ownership rule.
- Windows UTF-8/UTF-16 conversion, HRESULT tests, language identifiers, COM vtable calls and safe release, GUID parsing, integer resource identifiers, and registry discovery of Windows Kits roots. Conversion buffers and discovered root strings are caller-owned. Encoding functions retain flags `0`, including the SDK replacement behavior for malformed input.
- Objective-C typed messaging: 311 method wrappers, 49 string/class/reflection and record helpers, and five selector-table initializers. Every native message uses an explicitly typed `#c_call` function pointer. Reviewed plain aggregate returns use `objc_msgSend_stret` on x64 when larger than 16 bytes, and typed `objc_msgSend` on arm64. Generic array object values are constrained to pointer types. NSString conversion copies the length-bearing NSData UTF-8 representation, preserving embedded zero bytes; the resulting Jai string is caller-owned. Temporary NSStrings are autoreleased and require the caller's usual autorelease pool.
- Windows icon and manifest insertion through SDK resource update transactions. ICO headers and every payload range are validated before beginning an executable update. Icon groups replace file offsets with resource IDs; failure before commit discards accumulated updates. `generate_manifest` returns a caller-owned UTF-8 string with a fixed `Jai.Application` identity, selectable UAC level, DPI policy, and segment heap setting. `disable_runtime_console` calls SDK `FreeConsole`.
- Android asset complete reads and logging through NDK APIs. Asset handles close on every return path; partial reads continue until the measured length is satisfied, with optional zero termination. Successful nonempty results are caller-owned. Logging maps local error/warning/verbosity flags to NDK priorities and supplies terminated tag/message buffers.

The final completion batch removes the marker adapter library from all owned outputs. Its bodies are maintained in `tools/platform-completion/*.jai`, inserted by `tools/author_platform_completion.py` only after the original bodies have been discarded. The replacement pass checks every expected normalized declaration and refuses an unexpected remaining adapter. It does not infer or read original implementation code.

Objective-C reflection uses runtime method lists, names, argument/return encodings, class allocation, metaclass lookup, and ivar/method registration. `objc_type_encode` emits the SDK encoding forms for native scalar widths, pointer/object/class/selector values, fixed arrays, records, unions, enums, and C-call function pointers. It rejects unsupported widths, dynamic arrays, nonnative procedures, and unbounded recursion. `objc_func_encode` requires concrete `#c_call` methods with receiver and selector pointer arguments and at most one result. `objc_create_class` requires a full, size-verified native parent prefix embedded with `#as` at offset zero, verifies every SDK ivar offset, and represents any final Jai padding as a real private ivar. It returns an unregistered class; call `objc_finalize_class` after adding methods. Constant procedure members become instance methods, with nonleading underscores translated to selector colons; `@"objc_class_method"` selects a metaclass method and `@"objc_selector:explicitSelector:"` overrides the inferred selector. The metadata source is the independently maintained reflection ABI.

`create_objc_class_member_stub` is a real runtime source-generation utility. It returns caller-owned Jai member source for scalar/pointer methods, using explicitly typed native message calls. Unreviewed aggregate, vector, bit-field or other signatures appear as review comments with their native encoding; no unsafe aggregate wrapper is invented. The framework and class must already be loaded. Generated members describe pointer-only class APIs; they do not reproduce private instance storage.

Android traversal uses the NDK file iterator for flat file-only visits, and Java `AssetManager.list` plus SDK asset-open checks for directories and recursion. Recursive/directory visits require `context.android_app` for the active NativeActivity and a matching asset manager, verified with `AAssetManager_fromJava`. JNI attaches only detached calling threads, balances local references and attachment, and converts UTF-8/UTF-16 without relying on modified UTF-8. Callback names are borrowed for the callback duration; directory callbacks can clear `descend_into_directory`. APK assets have no symlink entries. Recursion is limited to 256 levels.

`egl_create_context` creates and makes current an ES 2 window context with 8-bit RGBA, 24-bit depth and a best available MSAA configuration, retrying lower requests and returning the actual SDK sample count. Failure destroys created contexts/surfaces and terminates the display. A successful tuple transfers context/surface/display cleanup to the caller; unbind and destroy these resources when finished.

Android requires the `queue_input_event(window: Window_Type, event: Event)` and `set_input_focus(window: Window_Type, focused: bool)` overloads. They are present in shared `stdlib/Input/module.jai` at commit `9403cfa73511d09f8687c0cff1217070331f4ed3`, verified when sealing this packet. `Window_Type` is `s64`; `Event` aliases `Window_Event`. Their presence does not establish Android semantic or native validation.

The opt-in `DEFINE_ANDROID_MAIN_AND_CALL_THIS` entry establishes a Jai context and temporary storage on the native glue thread, installs command/input callbacks and the owner-thread Input pump, waits for a window, calls the supplied application procedure, and finishes the activity while processing destruction. Input records carry the actual native window pointer as their `s64` route. Hardware key text uses Java `KeyEvent.getUnicodeChar` with the native device/timing/meta-state fields. Touch, pointer, mouse-button and wheel events use NDK getters. The optional pointer adapter becomes available after a real motion event and clears when focus/window ownership is lost. IME composition and dead-key composition require an application InputConnection. Only one active NativeActivity per module instance is supported. Application-specific looper file descriptors remain the application's responsibility.

The original Android native-app-glue and LightweightRenderingView binaries are excluded. Android applications must independently build trusted NDK `native_app_glue`, initialize the compiled program as required by their host, and provide Android packaging. This is an external SDK/host prerequisite, distinct from missing Jai wrappers. `LightweightOpenGLView` maps to SDK `NSOpenGLView`; context access uses `openGLContext` and flushing uses `flushBuffer`. Generic rendering/Metal compatibility records map to SDK `NSView`; original subclass callbacks and automatic Metal-layer behavior are not recreated and require application setup.

Visual Studio discovery uses genuine Setup Configuration COM interfaces, keeps the caller's existing COM apartment, selects the newest valid instance numerically, reads its default MSVC version file, and checks `vcruntime.lib` and `link.exe`. The returned library directory and complete linker executable path are caller-owned. The implementation supports modern versioned MSVC directories on x64/arm64; older Visual Studio directory layouts are outside this discovery policy. No installed toolchain or unavailable COM service produces empty paths as the documented discovery failure result.

## Current SDK authority and compatibility

The supplied API surface remains the compatibility input. A preserved layout is not automatically a current ABI claim. The configured SDK reported by `xcrun --show-sdk-path` is macOS 27.0. Its headers were checked for errno access, LP64 pthread mutex/condition storage, `stat64` field order, `timespec`/`timeval` widths, wait-status masks, VM tags, and `FSEventStreamContext`. This is a targeted header review, not a complete ABI comparison or native execution test.

Current primary sources caused concrete ABI corrections: `FSEventStreamContext` now follows the configured SDK's `version`, `info`, `retain`, `release`, `copyDescription` order; predefined Windows registry handles sign-extend the SDK `LONG` constant to pointer width. Windows encoding flags use SDK `DWORD` (`u32`), and `UpdateResourceW` resource types use `LPCWSTR`. `COINIT` values match current `objbase.h`, and `GCControllerPlayerIndexUnset` uses the SDK signed value `-1`. Four GameController snapshot initializers return SDK object pointers. Reviewed AppKit methods that actually return `void` use void native calls while retaining the supplied Jai `id` return as null. NSView's selector uses SDK spelling `addSubview:`. The broad historical Linux x64, Android, Windows, Objective-C, and remaining macOS declaration sets have not been comprehensively verified against current target SDKs.

Maintained sources consulted for the independently implemented contracts are [Microsoft's encoding API documentation](https://learn.microsoft.com/en-us/windows/win32/api/stringapiset/nf-stringapiset-multibytetowidechar), [the reverse conversion documentation](https://learn.microsoft.com/en-us/windows/win32/api/stringapiset/nf-stringapiset-widechartomultibyte), [Microsoft's current registry header](https://raw.githubusercontent.com/microsoft/win32metadata/main/generation/WinSDK/RecompiledIdlHeaders/um/winreg.h), [registry query documentation](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regqueryvalueexw), [Apple's Darwin wait definitions](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/wait.h), [glibc wait definitions](https://raw.githubusercontent.com/bminor/glibc/master/bits/waitstatus.h), [glibc's public stat interface](https://raw.githubusercontent.com/bminor/glibc/master/sysdeps/unix/sysv/linux/stat.c), [the current Linux io_uring UAPI header](https://raw.githubusercontent.com/torvalds/linux/master/include/uapi/linux/io_uring.h), and [the maintained io_uring entry documentation](https://man7.org/linux/man-pages/man2/io_uring_enter.2.html). The JSON records the specific checks rather than asserting whole-library currency.

The new bridges additionally follow Microsoft's [resource update](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-updateresourcew), [commit/rollback](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-endupdateresourcew), [icon resource format](https://devblogs.microsoft.com/oldnewthing/20120720-00/?p=7083), [application manifest](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests), and [console detach](https://learn.microsoft.com/windows/console/freeconsole) contracts, plus the Android NDK [asset](https://developer.android.com/ndk/reference/group/asset) and [logging](https://developer.android.com/ndk/reference/group/logging) references. Objective-C dispatch uses the configured SDK's `objc/message.h`, `objc/runtime.h`, and selected Foundation/AppKit/GameController headers. The reviewed x64 plain record return policy also follows [Clang's current X86 ABI classifier](https://raw.githubusercontent.com/llvm/llvm-project/main/clang/lib/CodeGen/Targets/X86.cpp). Header review and source generation do not prove the Jai compiler's native calling convention lowering.

For the frozen parser, placement aliases in `OVERLAPPED` and `FILETIME` are expressed as anonymous unions, platform selection is moved outside the legacy clock enum, private Objective-C selector tables have named record types, and an unsupported advisory reflection-size flag is omitted from those private tables. POSIX target selection uses ordinary conditional loads; unused Basic imports were removed from pure arm64 SDK declarations. Reviewed Objective-C enum backing aliases use equivalent LP64 `u64`/`s64` representations; AppKit event-mask shift operands and maximum-value operands use their verified SDK integers. The nominal enums and public alias declarations remain intact. The Android entry-point program export is attached to the independently authored opt-in definition. `NSModalResponse` and `NSWindowLevel` use SDK-equivalent LP64 `s64` aliases while the public `NSInteger` declaration remains available. Physical-layout and advisory-metadata adaptations are listed separately in the report.

An additional source-only check with frozen snapshot `9508def6f527169083405db10c93d9d377289fecdca749a546eb849ca39d501d` exposed an import/discovery limitation: an imported provider containing a file-level `using` enum leaves its type exports unavailable during the importer's early alias resolution. A provider with the same declarations but no `using` passes the isolated check. Namespace qualification and changing import visibility do not resolve that case. The production AppKit/software-render graph therefore remains semantically unverified; the individual file parser results do not override this failure. `stdlib/.coverage/platform-sdk-source-checks.json` records the isolated sources, exact command, and observations from that frozen snapshot. The compiler task has this reproducer for a resolver repair.

## How to change it

Add independent implementations under `tools/platform-sdk-contract-overrides/`, then register their exported procedure names and load paths in `INDEPENDENT_LOADS`. Keep a whole-file override there when its complete implementation is independently authored, as with `Windows_Utf8.jai`. Regeneration reads these maintained overrides, so it does not overwrite independent work with adapter declarations.

`tools/author_platform_completion.py` reads the separately authored `tools/platform-completion/` bodies and replaces normalized declarations by procedure name and overload order. Keep public replacement declarations before the `// PRIVATE HELPERS` delimiter and private same-file helpers after it. The pass requires every expected unresolved declaration to be present and rejects any marker declaration left in those files.

`tools/author_objective_c_dispatch.py` consumes only the already normalized contracts, infers reviewed selectors from declaration tables, and authors native call bodies. It leaves unknown return layouts unresolved. `tools/author_objective_c_helpers.py` contains independently written bridges that need string ownership, reflection, SDK compatibility names, or record construction. Add SDK signature corrections explicitly and extend the boundary tests when introducing another return ABI.

For a new native API, verify the current target SDK declaration first, then add its normalized contract or a documented correction to the extractor. Preserve target-specific widths, alignment, symbol names, calling conventions, and ownership. A library belongs in `SYSTEM_LIBRARIES` only when it is a trusted system SDK dependency; adding an artifact path is not a way to close a behavior gap. New original-wrapper implementations must change their report status and be validated independently.

Regenerate and parse with:

```sh
python3 tools/rewrite_platform_sdk_contracts.py --parse
python3 -m unittest discover -s tools -p 'test_rewrite_platform_sdk_contracts.py' -v
python3 -m unittest discover -s tools -p 'test_author_objective_c_dispatch.py' -v
```

The four extractor boundary tests verify body removal, ABI field retention, exclusion of shipped libraries, removal of compile-time implementation/template code, and inventory treatment of parameter names. Six dispatch tests cover aggregate return selection, SDK void/pointer return corrections, selector parameter name collisions, private selector prefixes, and preservation of unreviewed aggregate gaps. The final coherent source batch uses frozen snapshot `9508def6f527169083405db10c93d9d377289fecdca749a546eb849ca39d501d`; its results, binary SHA-256, and each output source SHA-256 are recorded in the JSON. `build_inputs_verified=false` explicitly records that the binary has no certified rebuild receipt. Individual parsing is not semantic module compilation. These checks do not establish complete module type-checking, native linkage, native layouts, or wrapper execution. No Cargo builds or original native execution were performed for this pass.

## Configuration

`OS` and `CPU` choose the supplied target branches. POSIX has macOS x64/arm64 and Android x64/arm64 layouts; the supplied glibc/Linux declarations describe the historical Linux x64 ABI. Other Linux architectures require a verified new contract branch before native use. The public libc `stat` symbol wrappers require modern libc; glibc targets need glibc 2.33 or newer, as recorded in [glibc's symbol version map](https://raw.githubusercontent.com/bminor/glibc/master/io/Versions). They preserve the supplied Jai `s64` return type while calling the SDK `s32` function.

The parser is pinned to `target/standard-library-snapshots/9508def6f527169083405db10c93d9d377289fecdca749a546eb849ca39d501d/jai-rs`. `--parse` runs its source-only `parse FILE` command. The authoring script enforces a 2 GiB free-disk floor. It requires Python 3 and has no third-party Python dependencies.

## Dependencies

Direct declarations depend on the selected target's libc/pthread/dynamic-linking SDK, macOS system frameworks and Objective-C runtime, Windows SDK DLLs, or Android NDK system libraries. The wrapper implementations also depend on the independently maintained `Basic` allocation/assertion APIs and their declared platform modules. No marker adapter library remains in the owned outputs. External SDK runtime services and Android application glue/packaging are still prerequisites; source parsing does not verify their presence or ABI.

The completion batch additionally follows Apple's [runtime encoding forms](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/ObjCRuntimeGuide/Articles/ocrtTypeEncodings.html) and configured SDK `objc/runtime.h`, Android's [Java asset listing](https://developer.android.com/reference/android/content/res/AssetManager), [looper](https://developer.android.com/ndk/reference/group/looper), [hardware key mapping](https://developer.android.com/reference/android/view/KeyEvent), and [native glue setup](https://developer.android.com/ndk/guides/concepts), the [Khronos EGL specification](https://registry.khronos.org/EGL/specs/eglspec.1.5.pdf), Microsoft's [COM flags](https://learn.microsoft.com/en-us/windows/win32/api/objbase/ne-objbase-coinit) and [MSVC directory convention](https://learn.microsoft.com/en-us/cpp/overview/acquire-msvc?view=msvc-170), and the [Microsoft-authored Setup Configuration SDK header distributed by maintained CMake](https://raw.githubusercontent.com/Kitware/CMake/master/Utilities/cmvssetup/Setup.Configuration.h). These reviews establish selected declaration and ownership contracts, without asserting comprehensive current target ABI compatibility.

The final cursor SDK review corrects `Windows.SetCursor` to return `HCURSOR`, the previous cursor handle, as specified by [Microsoft SetCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setcursor). [LoadCursorW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-loadcursorw) retains the supplied two-byte `*s16` pointer interface and returns `HCURSOR`; `null` instance plus the reviewed `IDC_*` resource IDs loads SDK-owned stock cursors. The current [Microsoft WinUser.h](https://raw.githubusercontent.com/microsoft/win32metadata/main/generation/WinSDK/RecompiledIdlHeaders/um/WinUser.h) verifies horizontal/vertical/diagonal cursor IDs. Configured macOS 27.0 `NSCursor.h` verifies the existing arrow, I-beam, hand, horizontal/vertical resize getters returning `NSCursor*`, and instance `set` returning `void`. The legacy resize getters remain declared but are deprecated. The macOS 15+ frame-resize method was reviewed but not added during sealing; callers using the existing binding must retain their documented diagonal fallback. The receipt records exact signatures, header/source hashes, isolation proof, and the amended Windows source parse. No native cursor was executed.
