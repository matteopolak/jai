# Basic and collection modules

## What it is

These independently authored Jai sources provide general utilities and in-memory containers. The pinned maintained OpenJai public contracts take precedence when they conflict with the supplied historical distribution; compatible historical helpers remain available where possible.

## How it works

`Basic/module.jai` loads separate allocation, array, string, builder, formatting, 128-bit, and time components. Allocation dispatches through `Allocator_Proc`; the array component captures an allocator in each resizable descriptor and grows by allocating replacement storage, copying live elements, and releasing the previous allocation. Array removal supports ordered shifting and unordered replacement by the final element. The maintained `array_find` overload for resizable arrays returns a boolean, while the historical view overload returns a boolean and index.

`Basic/protocol.jai` exports qualified aliases to the selected independent `Preload` source declarations. `Basic.Allocator`, reflection descriptors, diagnostics, and storage views therefore refer to the compiler's actual protocol types. `Basic.Any` names the builtin dynamic type, and `Basic.Temporary_Storage` aliases the selected `Runtime_Support` declaration. The canonical named-Preload source graph preserves declaration identity through the two-line `stdlib/Preload.jai` facade; these aliases do not create replacement records.

Several maintained example schemas still differ from that compiler ABI. The first three allocator modes agree, but the maintained `FREE_ALL` member is absent and value 3 means `STARTUP` in the selected protocol. Reflection-tag ordinals differ; struct members use descriptor pointers and enum flags rather than maintained `Type` and `s64` fields; struct metadata has a view and additional fields; pointer metadata uses `pointer_to`, while the maintained name is `points_to`. Runtime temporary storage also has different fields. `Basic.Context :: #Context` names the compiler's canonical context nominal; its imported identity fixture still needs semantic execution. Exact maintained schema equivalence is not claimed.

Those differences are now tracked against actual pinned consumers in [selected protocol profiles](protocol-profiles.md). Newer Focus/Vk and maintained Jaison consumers require the current rich descriptor schema, while OpenJai's declared subset needs a separate canonical variant. The private packet contains independently authored alternate declarations and real allocator/storage/reflection adapters; its new source receipts, complete loader and producer admission remain pending. Direct public field conflicts cannot be repaired by duplicating records or casting enum ordinals.

`Bit_Array` has the standard layout (`slots: [] s64`, `count`, `allocator`); bits are read with `bits[i]`, and `for :only_set` / `for :only_unset` are `#bake_arguments` of one iterator. Whole-array operations mask the unused trailing bits. `legacy/Bit_Array` preserves signed `slots`, `count`, and a captured allocator, including the historical whole-word tail behavior. Both expose a boolean and logical bit index during iteration.

`Hash_Table.Table` preserves the maintained `keys`, `values`, and `count` fields and the two type parameters. Its authored lookup scans the packed key vector backward, and mutation reserves both vectors before appending or shifts both vectors together when removing a row. Maintained `table_add` and `table_set` replace an existing value; `table_add_duplicate` returns an inserted pointer. Values remain stable until an operation grows or shifts their vector. `legacy/Hash_Table` provides the old entries, tombstones, counters, custom callbacks, and duplicate-add convention using independent double-hash probing.

`Sort.quick_sort` uses stable bottom-up merging. `IntroSort.intro_sort(array, f: (T,T)->int)` is an introsort (median-of-three quicksort, heap sort past a depth budget, insertion sort to finish); the range variants are file-private as in the standard module. The names preserve the public entry points rather than prescribing an implementation algorithm. `RadixSort` provides the maintained fixed array of 65,536 ranks and sorts those indexes using stable merging without modifying the input. A rank count exceeding the fixed capacity triggers an assertion. `legacy/RadixSort` preserves resizable `ranks`, `ranks2`, `valid_ranks`, and allocator fields. Its stable merge retains prior equal-key rank order until reset or resize. Floating-point NaNs follow numeric values.

`Bucket_Array`, `Pool`, and `Flat_Pool` use source-managed storage rather than importing supplied native allocators. Incompatible historical bucket and flat-pool layouts live under `stdlib/legacy/`; `Treemap` uses the historical stable bucket contract. `Relative_Pointers` encodes address differences into caller-selected integer widths. `Soa` owns per-column storage and packs/unpacks rows through reflection. Their detailed callable and layout limits are recorded in `stdlib/.coverage/storage-layout.json`.

The maintained bucket uses parallel item and occupancy arrays and reuses the smallest vacant slot. Growth can move returned pointers. Its legacy variant allocates fixed buckets and keeps pointers stable until removal or reset. Maintained bucket reset retains capacity; legacy reset releases bucket storage.

Pools reuse linked ordinary heap blocks and release them together. Pool follows the standard layout (block lists, out-of-band allocations, 6,554-byte oversized threshold; see [allocation-memory](allocation-memory.md)) and Flat_Pool preserves its five stored fields; private headers inside real backing allocations retain block links and allocator ownership. Flat pools lazily grow aligned heap blocks and reuse them after reset; they do not commit native pages incrementally. Allocator callbacks retain shrinking resizes, copy growing allocations, and ignore individual frees as required by arena ownership. Initialize backing allocation before selecting that pool as `context.allocator`. Pool charges a pointer-sized prefix in each block; on a 64-bit target, a 128-byte block leaves 56 bytes after allocating 64 bytes.

The legacy pool preserves exact fields and defaults. Its logical `Memblock` has `next` and `data: void`, giving an eight-byte header on the selected 64-bit target; a private ownership header adds physical heap overhead beyond logical usage accounting. Reset preserves used-list reuse order. The legacy flat pool preserves its five stored fields; a private header before `memory_base` saves the real raw pointer and allocator. Reservations round to 4,096 bytes and eagerly acquire heap storage, so `first_uncommitted_page` reaches the reservation limit. Both legacy allocators acquire a replacement for resizing and copy the smaller byte count. Native virtual reserve/commit and unmapping remain unavailable.

Treemap nodes borrow names, sum leaf weights into parents, and lay out descending-weight siblings in squarified rows. Border callbacks shrink content bounds. Set `treemap.dirty` after changing leaf weights; use display dirty/force when callback behavior changes. A private registry keyed by real tree and display addresses tracks generations without adding public record fields. Call `free_treemap` and `free_treemap_display` before retiring owners so their metadata is released. Removal, cyclic trees, and rendered geometry remain outside the verified contract.

Soa generates actual named fixed arrays, such as `soa.x`, from physical row members through source insertion. Constant/imported members are skipped; overlapping storage uses one representative member. Index reads reconstruct a row, writes scatter it, and pointer iteration writes its temporary row back after the body. Generation needs the compiler to admit declaration strings in the actual specialized `T,N` source scope. Relative-pointer storage uses signed displacements with the sign bit toggled: zero represents null, self-pointers remain representable, and the most-negative displacement is reserved. Relative strings borrow their target memory.

Struct printing follows the standard rules: constant, imported, zero-size and overlapping (union / `#place`) members are skipped; member names appear only in long form (more than `use_long_form_if_more_than_this_many_members` members), and the long-form separator follows every field. Procedure types print as `procedure (...) -> ...`; `void` values print as `void`. An instance of a polymorphic struct prints with its parameters (`Entity(Payload=s64)`) from the runtime `specified_parameters` / `constant_storage` the compiler emits (`typeinfo.rs`). The memory debugger exposes only the standard `make_leak_report(...) -> Leak_Report` / `log_leak_report(report)` forms.

Formatting, numeric parsing, time conversions, and 128-bit arithmetic are authored in the separate Basic components. Formatting adds a source context field for `Print_Style` instead of reproducing the maintained example's incompatible `Context` declaration. Clock acquisition lives in `Basic/platform-time.jai` and uses independently declared host clock APIs. Allocation and temporary storage have their own coverage report from the allocator family.

Current utility limits are explicit: character classification is ASCII, integer parsing supports bases 2–36 and at most 64 bits, and float parsing accepts decimal exponent notation. Float formatting extracts exact IEEE mantissa/exponent rational digits using 36 radix-2^32 limbs and a 344-digit buffer, then rounds finite results to nearest even. Requested precision is capped at 18. Maintained `SHORTEST` uses general notation at significant precision, defaulting to six digits; `DECIMAL` stays fixed even for large finite values but keeps at most 18 significant digits, printing the rest of the whole part as zeros like Jai (`5.97219e24` prints `5972189887017193070000000`), while `SCIENTIFIC` uses fractional precision. The explicit `formatFloatRoundtrip(float64, width:=0)` extension selects up to 17 significant digits through adjacent representable midpoint intervals and preserves signed zero. These new digit bodies remain behaviorally unverified; the approximate public float parser is not their oracle. Union formatting is unavailable, and pointer formatting displays addresses without dereferencing them. Output byte counts report bytes attempted because the runtime output sink returns no count. The maintained `Calendar` identifier has no declaration in the pinned module; calendar conversion cannot be claimed complete from that source alone.

The memory debugger dispatches through the five allocator hooks after allocation/reallocation, before free/destruction, and after heap creation. Dynamic arrays use the same captured-allocator wrappers. A real procedure callback is default-initialized in the synthesized context, so default Basic instances and runtime page retirement reach the selected debugger without import cycles. Runtime dispatch validates the actual member type and reads the callback at its published byte offset. A context reentrancy flag suppresses debugger-owned allocations, and a compare-and-swap gate serializes registry updates. Historical registration/frame helpers reuse the gate only when its actual owner context address and thread index match and an atomic check confirms it is active; copied flags alone do not grant ownership. The registry retains real allocation addresses, allocator procedure/data pairs, lifecycle indexes, copied stack nodes, and frame events until `deinit_memory_debugger`. Temporary and fast bump allocations are excluded; their ordinary backing heap allocations remain tracked. Runtime finalization marks its real backing-retirement events explicitly: the default tracker retires known history, while pages acquired before observation or during reentrancy suppression do not produce a false unknown-free diagnostic. Ordinary caller frees remain strict. Custom replacement callbacks receive those real finalization frees and retain responsibility for their own history policy.

The maintained zero-argument `make_leak_report()` returns temporary text valid until temporary storage is reset, and `log_leak_report()` writes that text. Tracking disabled returns an explicit disabled-policy message. Explicit `Leak_Report_Options` selects the historical owned `Leak_Report`; the old defaulted-options overload is retained, with zero-argument selection still awaiting typed proof. Leak reports own copied trace data through a legacy pool. Explicit annotations and compiler-supplied global segments seed reachability; pointer-word scanning propagates ownership from marked live allocations. An acyclic ownership forest combines child leaks while retaining a root for cycles. Reports group equal traces and requested calls, sort by total bytes, and trim displayed leaves/roots. Scanning currently recognizes aligned allocation-base pointers, so interior and unaligned references remain a limitation. The selected stack metadata has no module field; optional module matching uses exact source-path components or a `.jai` basename.

`deinit_memory_debugger` is a quiescent boundary for the shared tracker: it releases retained history under the gate and clears only the current context callback. Copied contexts retain a program-lifetime procedure and can subsequently start fresh history. Retire user allocations and reports before this boundary; deinitializing while other contexts still use tracked live memory loses that prior history.

Visualization uses the existing shared-memory channel and wire records. Each committed update sends a reset/version, strings, procedure metadata, actual trace addresses, live summaries, and frame events. Full snapshots allow retry after queue pressure; frame counters advance only after a usage message commits. `memory_visualizer_per_frame_update` switches from timed updates to explicit frame updates. No connected-client or concurrent-native behavior has been verified yet.

## How to change it

Extend array behavior in `Basic/Array.jai`; keep descriptor counts and allocator ownership consistent when changing growth or removal. Extend the Basic utility files through their existing loader entries. Float digit policies and capacities live in the private `__float_*` kernel/renderers in `Basic/Print.jai`. Preserve the public mode defaults when changing rounding or notation. If adding a new file, update `Basic/module.jai` and the documentation index.

Keep `Hash_Table`'s key and value vectors synchronized. Directly resizing one vector bypasses that invariant. Add new comparison or ranking behavior through the sort comparators; changing only the algorithm should preserve comparator ordering and duplicate stability where documented.

Preserve the default maintained field names and signatures. When a historical layout or return convention cannot coexist with them, provide an explicit legacy module or helper and record the incompatibility. Add protocol aliases through the selected source namespace in `Basic/protocol.jai`; preserve its canonical `Preload` import and the stable two-line facade. Do not duplicate protocol records to hide a schema conflict.

## Configuration

`Basic` retains `MEMORY_DEBUGGER`, `ENABLE_ASSERT`, `REPLACEMENT_INTERFACE`, `VISUALIZE_MEMORY_DEBUGGER`, and `TEMP_ALLOCATOR_POISON_FREED_MEMORY` parameters. `MEMORY_DEBUGGER=true` selects the authored tracker. `REPLACEMENT_INTERFACE` selects actual replacement callbacks; its sentinel exposes constant procedures, preserving the historical zero-storage interface shape. `VISUALIZE_MEMORY_DEBUGGER` enables local shared-memory snapshots and defaults to true. `ENABLE_ASSERT` controls source assertion expansion. Temporary-storage poison policy is implemented by the allocation component.

The default `Hash_Table` has no module parameters. Its legacy module accepts `COUNT_COLLISIONS`; its template retains custom hash/equality, `LOAD_FACTOR_PERCENT=70`, and `REFILL_REMOVED=true`. `RadixSort.MAX_RADIX_COUNT` is 65,536. Collection allocations otherwise use the array descriptor's allocator or `context.allocator`.

`Pool.memblock_size` defaults lazily to 65,536 bytes. `Flat_Pool` defaults to eight-byte alignment; set its block size before lazy acquisition or call `init` with a reservation size. The legacy pool likewise keeps its 6,554-byte oversized threshold, custom alignment, reset stamping/free policy, and allocation logging. `USE_UNMAPPING_ALLOCATOR=true` rejects explicitly. Legacy flat-pool module parameters retain a 256 MiB default reservation and `OVERWRITE_ALL_POOLS_ON_RESET=false`.

For source-only checks, select the authored module root and independent prelude. The integration owner runs `tools/stdlib_api_inventory.py` with a frozen repository-built CLI. Module parsing alone does not establish typed execution, host service availability, or ABI equivalence.

## Dependencies and verification limits

These modules depend on the independent prelude descriptors, `Runtime_Support`, and the authored host clock declarations. The memory debugger additionally uses legacy pool/hash declarations, canonical `compare_and_swap`, and `legacy/Compiler.get_runtime_info` for genuine global-data segments. Its default global scan requires that compiler provider; missing metadata traps instead of returning a successful unfiltered report. Visualization depends on `Shared_Memory_Channel` and `Protocol_For_Memory_Visualization`. `Treemap` additionally depends on vector math and historical stable bucket storage. No reference compiler, supplied native library, or original implementation is used as execution input.

The authored behavioral smoke source is `tests/stdlib/basic-collections.jai`. Additional fixtures exercise legacy bit/hash/rank contracts, generated Soa columns, pool ownership, and multi-display treemap invalidation. Protocol fixtures probe qualified descriptor and context identity. Earlier frozen checks with verified compiler `017353c4` stopped Basic consumers at the genuine `#caller_location` qualified-alias provider gate. Those receipts predate the newest formatter/debugger bodies; current collection behavior remains unverified pending the integrated compiler sweep. Historical caller-reference and baked-expansion forms also need their respective compiler provider admissions.

The 20-case `tests/stdlib/int128-arithmetic.jai` fixture passes semantic checking, compile-time VM assertions, and newly generated native programs at O0 and O2 under that compiler. Carry/borrow uses bounded 32-bit limbs, and baked shift normalization avoids checked underflow while specializing inactive branches. Exact receipts are under `artifacts/stdlib-rewrite/basic-utilities`. This evidence covers the arithmetic fixture, not the entire library.

`tests/stdlib/memory-debugger-core.jai` prepares 26 lifecycle/failure checks, including history-storage exhaustion after confirmed heap destruction or a moved realloc. `memory-debugger-tracking.jai` exercises wrapper/report ownership; `memory-debugger-shared-context.jai` starts with a default-instance allocation before any debugger call; text and disabled-policy fixtures cover the maintained zero-argument signatures. `memory-debugger-retirement.jai` exercises actual observed and unobserved backing releases through the real runtime notifier. A retained historical core check under verified compiler `017353c4` exposed a readiness panic before execution. The latest module/core/array/runtime/visualization sources and fixtures pass parsing; the exact public `Preamble` caller-reference expression remains a parser-provider gap in that snapshot. Context callback default admission, ordinary descriptor-to-Type certification, genuine global-range publication, overload selection, VM/native reports, concurrent hooks, and connected-client behavior await paired compiler validation. The new ten-case float conversion fixture also parses without behavioral proof.

Machine-readable evidence is in `stdlib/.coverage/basic-collections.json`, `basic-utilities.json`, `storage-layout.json`, and `memory-debugger.json`. These reports distinguish authored bodies, source parsing, known API differences, and behavior that has not been executed.
