# Notices from the owning conda SDK package

Intel Mac CI now reaches libclang development headers, then fails while packaging `libclang.13.dylib`: its conda prefix has no top-level license file. Missing downstream binding/coverage files are retained setup consequences, not additional verified library outcomes.

The official conda-forge osx-64 `libclang13-23.1.2-default_h3065a3b_0.conda` archive was downloaded and SHA256 verified as `0dfe44aa4d56eae2ac5832a611ce1167d44ff17181c85596de01e149c04af01c`. Only its metadata and notices were inspected. Its real `info/paths.json` owns `lib/libclang.13.dylib`; its actual notice is `info/licenses/clang/LICENSE.TXT`, SHA256 `ebcd9bbf783a73d05c53ba4d586b8d5813dcdf3bbec50265860ccc885e606f47`. No SDK image was loaded or executed.

`developer_native_runtime.py` now finds the unique installed package owning each resolved SDK image through `conda-meta`. It validates the corresponding cache's name/version/build and file ownership against `info/index.json` and `info/paths.json`, then copies the real nested `info/licenses` files into a package-specific notice directory. The runtime manifest records owner identity, metadata hashes, available package archive hash and every copied notice hash. Missing, mismatched, empty or conflicting notices fail. It does not substitute another package's prefix license or create a dummy notice. Conventional SDK top-level notice handling remains supported.

The installer retains the owning package cache for this provenance lookup. Native compile/link/relocation/signing function bodies are unchanged (AST comparison), apart from the notice selector they already invoke. Metadata reads are repeated per image; a validated per-stage owner index could reduce this cost later without accepting stale ownership.

Seven filesystem/package policy tests pass; the original source fails the new conda controls. Tests cover owner/version mismatch, missing licenses, conflicting destination bytes, conventional SDK compatibility and unrecognized sidecars. Verified AppleDouble companions are metadata, not JSON or licenses; unknown/orphan companions remain errors. The initial sidecar discovery failures and original baseline failure logs are retained in T7. Ruff check/format, shell syntax, workflow lint and two existing provider configuration tests pass. All four POSIX CI consumers run the notice tests before building the real helper.

A separate metadata replay copied the **actual inspected package license** using its genuine index/paths and a synthetic, explicitly non-executable installed-image ownership control. This verifies notice selection/copying, not native ABI or dyld behavior. Actual Intel conda installation, complete dependency notice closure, relocated consumers and stdlib CI replay remain required. No original corpus, browser or Focus pass is claimed.
