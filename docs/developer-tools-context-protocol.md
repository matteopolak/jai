# Shared generator context protocol

This is the NEW implementers' internal handoff contract. It introduces no public compatibility export. The canonical model owner implements it once; configured Bindings_Generator facades and the other helper files consume it. The current staged lifecycle draft is not that implementation.

The unparameterized owner must declare the canonical Generator, CType, Declaration, Function and other shared model types once, keeping their reviewed names, fields, defaults and ABI. Configured facades expose aliases to those same types. The same unparameterized owner declares `#add_context generator: *Generator` once. Parameterized facades must not repeat it. Duplicate fields correctly reject under [the reviewed context contract](language/context.md).

Private implementation accessors are `generator_context_get() -> *Generator`, `generator_options_get() -> *Generator_Options_View`, and generic `generator_context_activate(generator: *Generator, options: $Options)`. These names are internal coordination names, not promised public Jai APIs. The owner supplies the definitions before dependent batches are integrated; callers must not replace a missing accessor with a mock or a second context declaration.

Generator_Options_View is one private, unparameterized snapshot type. It groups the reviewed option values into target, parser inputs, libraries, naming, stripping, printing and callbacks. It is not a second public Generate_Bindings_Options declaration. The activation helper accepts each configured facade's actual options value and copies its scalar values and borrowed array/string/callback views into these groups. The snapshot records its owning Generator pointer. TARGET_OS-dependent public defaults stay in configured facades; the snapshot stores the actual supplied os/cpu values, not independently chosen defaults.

The private view's group paths are fixed for the helper handoff. Keep reviewed option field names within each group; the activation helper performs the translation, so clients do not cast opaque bytes between configured option types.

For example, movement policy reads generator_options_get().stripping.move_struct_functions_to_global_scope; spacing reads generator_options_get().printing.mimic_spacing_flags; callbacks read generator_options_get().callbacks.visitor. Array/string/callback types are the actual canonical reviewed types. Only scalar defaults are copied from supplied values; the owner must not choose new public defaults during normalization.

The context stores one private pointer to this snapshot alongside the canonical generator slot. Accessors assert that the active pointer is nonnull and that the snapshot owner equals context.generator. Options must come from a real activation with supplied options; no empty/default successful view is substituted. Native-token operations additionally require the active generator's real translation unit. run_generator activates its supplied pointer/options before context-dependent work. init_generator installs the pointer and initializes reviewed primitives; the owner should also snapshot its supplied options for helpers that run during initialization, documenting that independent policy.

The caller owns the Generator record. Activation allocates the private snapshot through the caller's active allocator; snapshot scalars are copied, while option arrays/strings/callback data retain their supplied ownership. That backing storage must remain valid while helpers use the activation. A Pool context is suitable for a whole generation operation. Returned accessor pointers are borrowed and must not be freed or retained beyond their backing allocator lifetime. Native token views remain borrowed from the generator's live translation unit.

Use ordinary push_context management for nested activation/restoration. No separate generator stack or lifecycle registry is introduced. deinit_generator disposes token sets, translation unit and clang index and leaves the active generator slot unchanged, as reviewed. The caller must restore a safe context before destroying its Generator/options backing storage. Private snapshots must not silently free caller-owned option arrays or canonical model records.

Construction helpers register and look up canonical cursor identities through the active Generator.declarations_by_cursor. They must return/reuse those actual declarations rather than construct detached lookalikes. Emission helpers use the same canonical graph. The tooling owner retains run orchestration and emission; the model owner owns canonical context/init/deinit and constructors; platform/naming/modifier helpers consume the accessors without declaring context fields or duplicating records.

Required integration evidence: configured facades coexist without duplicate fields; alias types retain canonical identity; actual supplied target/default values survive activation; nested push_context restores both pointer and options; token access fails without a live TU; deinit does not restore/clear the active pointer; interpreter/native O0/O2 graph and emission consumers execute. This document does not claim those integration checks have already passed.
