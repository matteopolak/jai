# Debug_Info public parser workflows

`parse_dwarf_debug_info` now reads complete little-endian DWARF32 version4 compilation units, abbreviation sets, standard version4 attribute forms and the verified version4 line decoder. `parse_compilation_unit_v4` is the same public unit workflow with its reviewed contextual argument. The result contains types, globals, subprograms, parameters, nested lexical blocks and line sequences; it is not populated by a private-decoder oracle. Names and producer strings borrow section storage. High PC address and constant forms are distinguished. Origin/specification descriptive attributes resolve iteratively; cycles, missing targets, invalid forms and overflow fail transactionally.

Independent policies: the unit offset is the initial-length position in the complete `.debug_info` section; stored DIE offsets and translated unit-relative type references are section absolute. Encoded one-based DWARF file/directory IDs are preserved. Directory zero supplies no prefix. `get_filename` and its file-ID wrapper borrow unchanged paths and allocate joined paths with the active allocator; callers free only joined results. Absolute paths remain unchanged. No path normalization or filesystem lookup occurs.

Supported inputs are DWARF32/version4, 4-byte or 8-byte addresses and line programs representable by the public address-only line model. DWARF64, version5 forms, discontiguous `.debug_ranges` (no input parameter), supplementary sections and nonzero VLIW operation indices fail explicitly. Unrepresented standard attributes are consumed with bounds checks. Type records retain precisely the fields available in the reviewed model; they do not invent member layouts or location-expression evaluations. Cross-unit origin/specification references are unsupported; normal unit-relative type references are translated independently per unit.

`parse_msf` now constructs the canonical public aggregate over the verified MSF7/4096-byte decoder. The header and content borrow the supplied bytes. Stream page arrays, directory page list and independent active/freed FPM arrays use the active allocator. Nil streams are represented by byte_count=-1; empty streams are real empty streams. `get_stream_data` returns an independent allocated copy. `verify_integrity` revalidates the wire graph, compares stream/directory descriptors and verifies current FPM bits against the retained input.

MSF independent read-snapshot policies: growth1, maximum page number u32 max,32768 FPM bits per bitmap page, bitmap count rounded up from file page count, primary/alternate FPM pages1/2, first nonreserved data page3 and user streams starting at5. The freed map has zero bits, representing no deferred frees. `init`, `ensure_room` and `set_all` use represented active-word counts, rover0 and explicit fill bits. Mutations of individual page bits still require caller-initialized bounds; they do not grow silently. Other page sizes and small MSF layouts remain unsupported.

Public arrays have no aggregate deinitializer in the reviewed API. Release nested arrays and bucket storage with their recorded allocator, or retain them in an allocator whose lifetime covers the results. Failed parses release all partial owned arrays and return empty results. Input buffers must remain alive for borrowed strings/header views.

Run `python3 tools/check_debug_info_public.py` after building this checkout's jaic/jailint under the assigned CARGO_TARGET_DIR and `target/jaifmt`. The runner creates original ELF/PDB objects using the official SDK, applies ELF relocations, compares all projected type fields with llvm-dwarfdump and all PDB stream bytes with llvm-pdbutil, and runs public tests on Mac interpreter/native O0/O2. The DWARF tests also exercise multi-unit translation and failed-parse allocation balance. [Evidence](native/debug-info-public-evidence.json) records section hashes and SDK metadata.

CodeView type parsing now projects the reviewed common-base records: structures/classes/unions, enums, arrays, ordinary pointers, modifiers, procedures/member functions, argument/item lists, string/function IDs, source lines, aliases, type servers, method lists and represented field-list entries. It validates record lengths, integer numeric leaves and descending pad bytes. Unsupported leaf kinds and member-pointer tails fail explicitly. Each root allocation owns a payload copy; string fields point into that tail and survive input release. Nested argument and field-list arrays are separate owned allocations. Free those arrays before freeing the root. Type-index lookups return borrowed table pointers; primitive lookups allocate a Codeview_Builtin for the caller. Item IDs use a high-bit namespace selector in get_id_type; describe_id_type explicitly selects IPI for ordinary item indices. All descriptions are independently formatted owned strings, with bounded recursion and failure for cyclic/invalid descriptions. Dumps validate all descriptions before emitting text.

`parse_tpi_stream` validates V80 headers with type-index origin0x1000 and the declared record byte/count bounds, then uses that type parser. `parse_pdb` reads VC70 info headers/GUIDs, named-stream maps, feature flags and TPI/IPI. Name-map keys are bounded terminated strings; duplicate names, out-of-range streams, invalid bitmaps and unknown features fail. Private name-map storage uses dense key/value arrays plus the serialized presence/deletion sets. Modern feature flags follow the [official PDB info-stream documentation](https://llvm.org/docs/PDB/PdbStream.html). FASTLINK metadata returns its actual flag/name-map state without inventing unavailable external object types. Other PDB versions, supplementary type servers, hash validation and unsupported type leaves are explicit limits.

`copy_and_truncate_blocks` deep copies a clipped view of CodeView line blocks. The caller supplies the new text_offset/length and the old contribution offset. Half-open row intervals use successors across every file block; repeated addresses within a block use the final row. Equal addresses in different file blocks are diagnosed as ambiguous. New parser/inline output stores one start column per line; the helper also preserves explicitly supplied paired column arrays as an independent addition. The source retains its allocations; the detached result has independent mutable arrays. Invalid inputs leave the caller's view unchanged and log a diagnostic. These ownership guarantees describe this implementation; the reviewed source contract permits views and does not promise deep-copy independence or unchanged source rows.

`parse_codeview_symbols` now parses C13 symbol/source subsections. Compiler, procedure and inline-site roots use the explicitly reviewed leading common base, with subsequent layout determined by the Jai target ABI. `is_procedure` recognizes exactly the four reviewed variants. Heap-allocated roots own copied payload tails for strings; all inline sites also appear in the symbols array. Procedure.inlinesites and site.children contain nonowning pointers to those roots; release their pointer arrays and annotation arrays, then free each root once. Checksums, string tables, lines, start columns and inlinee extra-file arrays are owned independently. The parser stages work and appends only after complete validation, preserving caller types/ids and pre-existing parsed state on failure. Duplicate string tables/checksum IDs/inlinee IDs are rejected instead of ambiguously merging namespaces.

Recognized auxiliary symbol payloads (object names, frame/local/data/UDT/register records, defranges, function lists and integer constants) are wire-validated but are not projected into guessed common-base records. Lexical block records maintain scope nesting. Unknown non-ignored subsections, unknown symbol records and unsupported numeric payloads fail explicitly. Scope ends and nonzero parent/next references are checked against enclosing scopes/procedure boundaries; zero references in original relocatable COFF objects are retained. Serialized offsets are preserved as stored, without inventing COFF relocation processing or symbol addresses. These are representation/format limits of the incomplete public parser, not missing entry points.

`decode_inline_site_line_info` requires a unique matching inlinee entry and emits procedure-segment ranges with file/line/statement/start-column state. Contiguous ranges coalesce while preserving line rows. Missing matches, overflows, unknown opcodes, unfinished final rows and zero-line/zero-length streams fail with diagnostics. Column-end values have no public output representation. Independent offset policy: ChangeCodeOffsetBase supplies a literal procedure-relative byte base; CodeOffset selects an offset from it. Offset movement bounds an earlier emitted row, while explicit code lengths close the current row without advancing the accumulated offset. This policy does not claim equivalence for undocumented funclet/base-index encodings.

`overlay_inlinesite` requires each decoded range to fit exactly one existing sequence in the same segment. It splits before/after that range, inserts the inline sequence and applies children within the parent's decoded regions. `overlay_inlinesites` processes sites in supplied order. Children take precedence over parent rows; a later site must still fit a single current region. Invalid placement or nesting beyond64 levels fails and releases all intermediate output. The implementation returns independent owned sequences; the reviewed source contract does not require this stronger ownership behavior.

The combined runner now covers eight public workflow fixtures plus twelve existing helper/decoder regressions, all in Mac interpreter/native O0/O2. Four original inline COFF objects cover Windows x64/arm64 at O0/O2 in addition to the prior type objects. SDK dumps verify compiler/procedure fields, parent/child identity, decoded annotation operands and inlinee/source tables. Generated synthetic streams exercise all four procedure tags, multibyte compressed operands, invalid encodings and scope-reference corruptions. Allocator-denial tests exercise symbol payload/checksum/inline-row failures as well as prior parser allocations. Target-derived ABI checks run for Windows/Linux/Mac on x64/arm64. These regressions supplement public endpoint tests and are not counted as substitutes for them.

All formerly pending Debug_Info function names now have implementations and invocation evidence. The final symbol/inline ABI question is resolved in [questions](specs/questions/debug-info-impl.md). The module does not claim full format coverage.
