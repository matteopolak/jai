# Developer tools deviations and unfinished paths

- **Incomplete owned scope:** Bindings_Generator, Check, Codex, Debug, Debug_Info and Iprof remain unfinished. Public inventory records distinguish pending declarations from supported APIs.
- **Rewrite subset/contract choices:** edit ranges use the NEW producer's one-based UTF-8 byte coordinates and exclusive endpoints. Public spec endpoint rules remain an explicit question. Only `<<` prefix dereferences are converted; other deprecated syntax remains unclassified. The current NEW producer exports prefix and postfix dereferences with the same operator tag, so the implementation checks the actual source prefix rather than treating every tagged node as deprecated. Nested overlapping edits are diagnosed and refused, not combined automatically. String-built compiler inputs are skipped because they have no writable source snapshot. No unreviewed get_plugin export was added; callers use the reviewed lifecycle functions and My_Plugin base explicitly.
- **Rewrite options/ownership:** `write` is an independently chosen explicit option pending spelling refinement, not a claim about historical option spelling. Unknown options fail. The default remains read-only; tests only write local target copies. Plugin-created table snapshots, line views, replacements and arrays are released by the private shutdown hook. External callers own records/replacement strings they pass directly to edit helpers. The table has no public allocator field for all these snapshots; callers must keep a consistent allocator across init/gather/shutdown. Error diagnostics are logged because the public finish/rewrite signatures return void; compilation status is not silently fabricated.
- **Rewrite performance/failure boundary:** snapshots may be read for nondeprecated dereference nodes because producer metadata does not preserve syntax style. Sorting is stable quadratic insertion sort and line/column conversion scans source bytes for each edit. Stale comparison detects preexisting changes before writing, but there is a TOCTOU window and writes are not yet atomic. I/O or invalid-location errors are reported. Complete multi-file transactions and automatic nested-edit normalization remain unfinished.
- **Print_Vars implementation choices:** Program_Print renders canonical source expressions, which can normalize original whitespace/parentheses. Widths count UTF-8 bytes rather than terminal grapheme/display-cell widths. Expressions are captured eagerly once into temporary formatted strings, then aligned in two passes; this satisfies the documented allowance for eager evaluation but requires temporary storage proportional to rendered output. Compile-time recursion is one level per argument. The exact fixed-array public helper receives a compile-time copy of the baked variadic Code view with an explicit baked count; dependent view.count alone was not accepted as an array extent by the producer. No public signature changed and no compiler special case was added. Returned get_code_name strings use the current allocator; runtime value strings use the standard temporary arena.
- **Performance_Report:** uses private independent text rendering rather than Program_Print because procedure names and counters suffice for its reviewed summary contract. Run records use stable insertion sorting (quadratic worst case); polymorph groups retain producer order. No exact historical textual formatting was specified or inferred. Plugin allocation belongs to its creation allocator; builders retain their own allocator. Actual measured tests use native compiler hosts; unsupported timing on actual wasm compiler hosts remains the producer's explicit diagnostic boundary.
- **Generate_C_Header current subset:** incorporates the reviewed refinement: default normal C enums, optional C23 fixed-underlying enums, uppercase-derived member prefixes, numeric type collision suffixes, C/C++ linkage/preamble, void-pointer procedure values, omission of non-C-call procedures/polymorphic structs/imported/constant/void fields, and runtime descriptor projection for string/Any/Type/views/resizable arrays. It still rejects multiple returns, fixed arrays in adjusted C argument/return positions, explicit overlays, packed/tagged unions, zero-sized records/arrays and invalid C identifiers. Reserved-name mapping and primitive-alias prefix scope require refinement. C11, C23 and C++17 consumers have actual host evidence; no claim covers every compiler/language standard.
- **Header refinement/test classification:** the initial exact-width typedef/macro enum representation and function-pointer procedure-value representation were independently chosen before refinement and have been replaced with the reviewed forms. The earlier implicit-context rejection fixture was inconsistent with the clarified non-C-call omission rule; it is explicitly reclassified and now tests genuine unsupported multiple returns, while a separate positive fixture verifies omission. Runtime support tests supply test-only reviewed-layout records; no duplicate bootstrap definitions or production canonical-identity claim is introduced.
- **Layout validation boundary:** generated C11 static assertions verify every emitted struct's size/alignment/field offsets when C is compiled. Generation does not yet prevalidate all explicit alignment/padding relationships; a mismatched descriptor can produce a header that deliberately fails C compilation. This must become a generation-time failure before full compatibility is claimed.
- **Diagnostics and output:** validation completes before opening output, preserving existing files on unsupported declarations. Native write failures propagate as false plus a diagnostic, but an I/O failure after opening may leave partial output; transactional replacement remains unfinished. `handle_message` logs unsupported type exports but its void signature has no accumulated error state; callers must check diagnostics. No errors are swallowed.
- **Memory/performance:** declaration strings use the caller's standard temporary arena (`tprint` and temporary builder materialization); builders and resizable traversal arrays are freed. Temporary strings live until caller temporary-storage reclamation. Graph membership/dependency traversal currently uses linear searches; worst-case time is quadratic in the number of reflected types. No large-header throughput claim is made.
- **Dependencies:** native execution and formatter building require the existing NEW portable crash C helper; `tools/build_portable_runtime.py` created the dylib within this worktree. No peer dependencies have been copied or edited. Shared native configuration was not changed.
- **Verification correction:** the first WASM check used invalid CLI CPU spelling `wasm32`; the source-built CLI accepts `x64` or `arm64`. Corrected to reviewed `-os wasm -cpu x64`. This is metadata/typechecking evidence, not WASM execution.
- **Regressions found and fixed:** a callback field initially became an invalid C function member; the first correction used function pointers, then reviewed refinement established opaque void pointers. A second enum-prefix test caught builder reset after the first enumerator; non-resetting temporary materialization now preserves the prefix on every member. Both were exercised through actual C compilation rather than weakened assertions.
- **Workspace baseline:** ownership/spec changes and a coordinator-owned denied corpus path were already dirty at startup. They are not staged or edited. No history was inspected. Shell here-document creation was denied by the sandbox; file edits use apply_patch or direct Python file writes instead.
- **Notification channel:** no callable `agent_message` tool exists; durable progress/deviations and concise commentary are used.
- **Bindings_Generator staging:** public models/defaults/constants, literal conversion, include discovery, normalize_options and both generation overloads now call the independently authored private C parser. Public visitors/model parsing, C++ bridge, run_generator, most creation/printing/mutation helpers, ensure_local_libclang_exists and full native libclang reexports remain pending. The installed official LLVM/libclang is version 23 while the reviewed public constant remains 21; this is staged evidence, not verified native version-21 compatibility. The public driver currently locates its source-built helper under this worktree's target directory. Coordinator packaging/native dependency integration remains required; no shared config changed.
- **Parser limits:** C11 subset rejects C++/Objective-C, variadics, inline/static bodies, macros (including include guards), bitfields, anonymous/nested aggregates, attributes, globals, unsupported widths and reserved identifiers. Reviewed typedef names/prefixes are unwrapped to target-width canonical types; other system type dependencies fail explicitly rather than generating missing names. SDK include paths are probed from official Clang; framework directories and recursive system-type inclusion remain pending. Repeated declarations/collisions are not fully normalized. Const/volatile annotations are not preserved. Function declaration parameter names and attached documentation are retained where exposed by libclang; callback typedef argument naming remains limited by available cursor metadata.
- **Supported public options and pending normalization:** currently requires one source header and one explicit regular/system Library. It honors target OS/CPU, include paths, extra Clang arguments, additional typedef prefixes, common enum prefix stripping/original aliases, header/footer, library identifier/path prefix/declaration toggle, struct checks, comment toggle, generator command and will_print_bindings. Custom declaration/argument callbacks, legacy/zero/multiple library mappings, search paths, system-type overrides, C++ transformations/bridge and other declaration transformations are diagnosed or remain outside the successful subset. Defaults are structurally exact, but complete option behavior is not claimed. Native export-symbol membership is not verified; supplied single-library ownership is assumed and actual missing symbols remain native compiler/loader failures.
- **Public generation ownership/performance:** returned builders belong to the caller's current allocator; temporary command/source strings use standard temporary storage. Captured process streams, discovered include strings/arrays, command arrays and builders are released. Include discovery invokes official Clang and parsing invokes the source-built helper for each call; process startup and capture polling are a deliberate staging performance tradeoff, with no large-header throughput claim. There is no helper auto-install/download fallback. C warnings are treated as generation failure. Parser/callback/unsupported-option failures preserve existing output; write failures propagate but are not transactional after opening.
- **Literal/data refinement and identity classification:** reviewed macro-result members/default, target parameter, exact compatibility arrays and suffix/conversion rules are implemented; successful converter strings may borrow input or temporary storage. A new fixture initially assumed repeated compile-time array .data addresses must match. The contract does not establish that guarantee; the observation is preserved under compiler-requests and not counted as passing identity evidence. Value/canonical-type identity remains tested. TARGET_OS is a compile-time module parameter in the NEW producer and has no addressable scalar storage. No mutable backing workaround or public type/signature substitution was introduced.
- **Check subset:** honors reviewed Windows-only availability and exact settings. Checks fixed-array/pointer assignment/call misuse and additions whose operands remain narrower than C int; an explicit widened operand avoids that finding. Findings use compiler continuable errors and module skipping follows Message_Import.module_type. The original typed-message fixture exposed a missing result descriptor; the rule correctly inspects operand types instead of assuming a fabricated result type. General metadata materialization is separately requested. Elsewhere/native symbol checks, memory-stat bookkeeping, print-format auditing and finish_error_checking remain absent. Expected compile-rejection tests are formatted and verified separately, without lint suppressions or assertion changes.
- **Private parser lifetime/output:** libclang diagnostics and handles, CXStrings, argument arrays and output memory are disposed. Parsing/generation errors preserve existing output. Allocation/output failures fail nonzero; writes are not yet transactional after opening. Exact-size buffer growth can cause quadratic copying for large headers; recursive type depth is bounded at 64 with an explicit diagnostic. Native incomplete records are explicitly opaque pointer-only types, never successful by-value definitions.
- **Private runner portability:** native library build currently uses macOS dylibs and defaults to the local official LLVM SDK prefix, overridable with DEVELOPER_TOOLS_LLVM_PREFIX. Linux/Windows target tests parse independently authored headers with explicit Clang triples and check generated Jai metadata; they are not native execution on those targets. SDK evidence is regenerated under docs/native, with no source or raw compiler log dumps.
- **Debug_Info frame subset:** only the canonical CFA instruction records/enum, Frame_Common_Information_Entry, decode_cfa_instructions and parse_common_information_entry are implemented. The rest of this large module remains pending. Parsing is little-endian DWARF32; 64-bit length encodings, legacy eh augmentation, segmented addresses, unknown versions, SET_LOC (address size unspecified by its standalone API), expression blocks and vendor CFA extensions fail explicitly. No partial instruction array or advanced offset is returned on failure. CIE augmentation text/data borrow the input buffer; instruction arrays use the caller allocator and must be freed before/independently of input destruction. Decode work is linear in input bytes, with one result per instruction.
- **Debug_Info compatibility input:** operand formats use the official DWARF5 debug-information specification, alongside reviewed public records/opcodes. Native verification uses an original C function compiled to an x64 Linux object by the installed official Clang SDK and extracts its .eh_frame with official llvm-objcopy. Neither the object nor its debug bytes are reference Jai input. This is host execution parsing native-produced target bytes, not execution of a Linux program.
- **Debug supported subset:** native capture/symbolization/debugger detection/pointer query/output/abort/breakpoint paths exist only for macOS/Linux. macOS has actual native/interpreter evidence; Linux C branches are source-only. Android/WASM debugger-presence false is implemented and target checked; Windows and other public common exports remain unfinished. Signal handlers, crash callback/storage, assertion handling, interactive dialogs, debugger attachment, minidump writing/state and break_once remain absent rather than falsely successful. Exit_Code, Minidump_State and the reviewed separate-thread constant retain exact declared values.
- **Debug ownership/limits:** symbol arrays and embedded text share one native malloc allocation; free_backtrace frees that allocation, independent of Jai context allocator. Only complete returned arrays may be freed, not sliced views or edited data pointers. Address capture is capped at 4096 physical frames (high-level convenience capture uses 256); skip removes physical frames after the C helper and does not attempt optimizer-dependent filtering of Jai wrapper frames. Symbolization uses platform backtrace_symbols with the platform's formatting; richer debug-type/source-line integration remains unfinished. No claim is made about exact historical stack frame spelling/skip boundaries.
- **Debug failure/probe semantics:** native allocation/sysctl/proc read/output failures report diagnostics. Expected inaccessible-pointer reads return false via kernel-mediated mach_vm_read_overwrite/process_vm_readv without direct dereferencing. A successful one-byte probe is a point-in-time readability check, not a guarantee that a whole object stays mapped/readable. Native abort uses _Exit and deliberately does not run language cleanup or flush buffered streams. A breakpoint traps only if a debugger is detected. Tests run without an attached debugger; attached-debugger interaction remains unexecuted.
- **Debug verification workflow:** initial native helper implementation and fixture were authored together rather than running an initial missing-module red step. Subsequent tests execute real interpreter/native effects, protection transitions and exit codes; no test result is represented as test-first evidence. The helper is built solely from this worktree's source with warnings denied. Build artifacts stay in its owned private directory; shared native configuration was not edited.
- **Iprof reporting subset:** only complete report/row/zone/history shapes, Report_Mode, relevant constants and text/CSV writers are implemented. Runtime zone instrumentation/timing, smoothing/history algorithms, plugin source injection, graphics/config/drawing and report generation remain pending. The module parameter defaults/conditional history fields are retained; setting modes does not invent a runtime profiler. Writers omit zero-call rows and, in manual mode, rows without initialized zones. Text output uses caller headers where present and both requested time thresholds jointly; exact historical formatting and threshold combination are unspecified. CSV has independent explicit columns name,self_time,hier_time,calls,heat and proper CSV quoting. Void writer failures log diagnostics. Reports/rows remain caller-owned; builders and final log strings are freed. Work is linear in rendered bytes/rows, excluding the caller-provided profiler collection.
- **Codex inspection subset:** only get_file_and_module, is_global_ident and the public Math module import are implemented. Classification follows the producer's IS_GLOBAL flag, including globals also marked IS_CONSTANT; whether historical metrics exclude constants remains a precise question. The helpers neither invent serialization nor emit empty metrics. Header/wire/short-string/plugin/magic/version/help contracts remain pending; record-only declarations are not represented as a working interchange format.
- **Codex import workaround:** standalone jailint reported the required direct public Math import unused. The facade now uses an ordinary private module import plus a public Math alias, retaining the same canonical module/type identity while making the dependency explicit to the linter. This adds no public compatibility name and uses no lint suppression or compiler change; original Math.Vector3 identity tests pass.
- **Denied process metadata probe:** a local ps command was denied while checking a long-running verification command; no alternate process metadata access was attempted. The verification command subsequently completed normally. No denied source or credentials were sought.
