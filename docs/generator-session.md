# Private canonical generator access and ownership

The shared internal module is `stdlib/internal/developer-tools/generator-session/module.jai`. All Bindings_Generator TARGET_OS instantiations import this single module. There is no second parser model, cursor registry, generator stack or canonical-type cache.

The reviewed active slot is `context.generator`. Its shared storage is a generic pointer; model internals cast to their module's canonical Generator. The reviewed prose establishes the slot name and supplied-pointer behavior, not an exact transitive Context field type across multiple TARGET_OS instantiations; that remaining type question is recorded for review. init_generator/run_generator owners must install the supplied pointer as reviewed. deinit_generator must leave it installed. Borrowing helpers use that slot directly.

The same unparameterized owner declares `_bindings_generator_options: *void`. Its activate(generator, options, owner) installs borrowed Generator/options pointers and an optional ownership ledger. active_generator()/active_options() read those slots; gm_active_generator()/gm_active_options() provide typed access inside the shared Bindings_Generator module scope. A null options pointer means no active caller options. Keep a stack options value alive through every callback, and restore its pointer through caller push_context before that value expires. The reviewed public run/init/deinit functions remain the tooling owner's implementation scope.

An optional private `_bindings_generator_session` Context field points to a transaction allocation ledger. The Session stores a borrowed Generator pointer, target discriminator, captured allocator, allocation sizes, child-array headers and failure/liveness state. It has no model maps. A small construction-phase list points only to canonical declarations and distinguishes shell, building, types-only and full C/C++/Objective-C scopes; it does not contain another cursor index or copied model. This prevents recursive construction and allows later full expansion without overwriting consumer edits to completed scopes. Its pointer must agree with context.generator; a mismatched target/ledger is diagnosed. Constructors use this ledger so that output records, strings and copied token arrays have one owner. Helpers that only inspect canonical state need no ledger.

Tooling owner integration sequence:

1. Keep the caller-owned Generator valid. Initialize its native handles/canonical primitives and install context.generator according to the reviewed public lifecycle.
2. Open a local ownership ledger for the complete model transaction. Within ordinary push_context, set context.generator to that Generator and `_bindings_generator_session` to the ledger. Do not copy a ledger after allocations are added.
3. Capture #Context before entering libclang. Each native callback restores the captured context in its own push_context block. Reentrant callbacks reuse the same ledger. A nested transaction for another Generator uses another ordinary push_context; return/break/error exits restore the caller's two slots automatically. There is no module-managed generator stack.
4. Finish all callbacks and consumers before leaving the activation block. Dispose canonical token arrays before their TU, and TU before index; these belong to the public lifecycle owner. Reset canonical tables before releasing model records they reference. The ledger closes after the activation scope, detaching still-owned array headers before releasing its tracked buffers/records/strings using the captured allocator. Array allocator interception tracks callback-driven resizes/frees; replacing a public array header with a caller-owned buffer does not transfer that buffer's ownership. It never disposes libclang handles, caller input, or canonical table buffers itself.

The public explicit init/run/deinit allocation lifetime is still a reviewed-contract question; this transaction protocol does not add new behavior to another worker's lifecycle functions. It enables real standalone model-helper use without duplicating public storage. Tooling may wrap its model transaction using this ledger, but must establish the promised lifetime before releasing it.

The original fixtures cover nested scopes and early returns, captured native callback context, wrong-target/missing-activation diagnostics, and a forwarding allocator proving all transaction allocations and child-array buffers are released through their original allocator. Context slot addition exposed a general jailint module-finalization bug, independently reduced and fixed in its driver; no source/path exception is used.
