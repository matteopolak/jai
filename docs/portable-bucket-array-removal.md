The reviewed custom iterator now supplies a removal replacement in every forward/reverse and value/pointer insertion branch. It invokes the existing canonical `bucket_array_remove` with the currently yielded physical bucket and slot. It never treats the dense traversal index as a locator and never synthesizes dense-array removal.

Before the production change, the independent six-mode fixture failed with `remove is only valid inside a for loop over an array`. Exact source/compiler hashes and the genuine exit-1 diagnostic are preserved in `artifacts/local-verification-stdlib/cargo-target/bucket-remove-red-8k2k32z_/results.json`.

`bucket-array-remove.jai` covers forward/reverse value iteration, explicit pointer iteration and both directions with `always_iterate_by_pointer`. It removes entries from multiple partly occupied buckets, checks dense traversal indices against physical order, occupancy and live counts, free-slot hints and exactly-once unfull-bucket membership. Survivor pointers/locators remain unchanged. Refilling every empty slot must reuse the existing buckets. The fixture also checks canonical record names, initialized/default slot reservation and caller-written uninitialized reservation before reset.
