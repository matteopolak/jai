# Sequence values

## What it is

Strings, fixed arrays, array views, and resizable arrays retain their source element types in the shared registry. Sequence lowering uses whole array snapshots or explicit count/data descriptors rather than encoding LLVM instructions as strings.

## How it works

Typed literal constants use opaque semantic constant IDs, so copying lexical bindings does not clone arrays or byte buffers. The declaration scheduler binds source-aware file constants and aliases before procedure checking; defaults can read these typed values. String-valued module parameters keep their defining module scope and are lowered to byte-preserving string expressions.

`jai-sema/src/sequences.rs` resolves ordered array literal elements in their contextual element type, checks the fixed length, and constructs the common `ValueExpr::Array`. Type inference resolves the first element once and reuses that expression. Copying a fixed array copies its entire value, including nested records. Index projections belong to the common place system so reads and writes use the same element identity.

String literals preserve arbitrary bytes, including embedded zeros and non-UTF-8 bytes. The LLVM backend creates private immutable byte-array globals and descriptors containing the exact byte count and their data address; empty strings have a zero count and null data address. String comparison is not fabricated as a compiler builtin: source library overloads must define any comparison behavior.

Sequence indexing accepts signed and unsigned integers. Narrow indices extend losslessly to `s64` or `u64`, retaining their signedness; a `u64` source index never silently narrows to signed storage. Descriptor counts remain signed, and checked access rejects negative counts and indices outside the logical count before computing an address. Native lowering additionally proves that the index times the selected target's actual element stride fits the pointer displacement domain before normalizing its width. Zero-sized elements keep logical bounds checks and use zero byte displacement. Raw pointer offset expressions retain their separate signed-offset contract.

A `string` descriptor can also refer to mutable byte storage, as required by the source String module's `to_lower_in_place` and `to_lower_copy` procedures. Indexed writes to an addressable descriptor use the same checked `u8` place projection as byte-array writes. Passing or copying the descriptor preserves its backing alias, and compound index expressions execute once. For example, `text: string = .{count=bytes.count, data=bytes.data}; text[0]=65;` updates a mutable `u8` array named `bytes`. Constant names and direct literals do not denote assignable descriptor storage. Assigning a literal descriptor to a runtime variable does not make its backing writable: the VM rejects writes to its frozen bytes, and native literals remain in immutable global storage. This matches the source module's requirement to copy literal data before modifying it.

Views and strings use `count:s64` followed by a pointer. Resizable arrays also contain `allocated:s64` and an embedded allocator with two pointers, matching the public storage contracts in the [authored compiler prelude](compiler-prelude.md). Fixed arrays converted to views preserve the address of the original storage. Constant contextual array literals use immutable static backing storage and can be returned safely. Empty literals have null data. Nonconstant contextual array literals use temporary stack storage; returning their views or data pointers directly is rejected, including through casts, conditionals, and nested aggregates. Static classification deliberately excludes potentially trapping operations and control-flow expressions until they have a proven constant lowering. Ordinary addressable views retain the source language's explicit lifetime responsibility. Descriptor field selection uses `SequenceField`, separate from nominal record fields. LLVM storage layouts remain checked against the selected target's `TargetData`.

Array iteration captures its sequence once before binding the value and optional index. It lowers to the existing inclusive signed range `0..count-1`, so empty sequences perform no iterations. Fixed array variables become views of their original storage; value iterators copy each selected element, while pointer iterators address that element. Strings allow byte value iteration, and reverse iteration shares the existing range control flow. The implicit index name is `it_index`. By-value fixed-array iterator elements are read-only: their fixed-array subfields cannot produce mutable slice or data aliases. Pointer iteration provides mutable storage; existing slice and pointer backing keeps its shallow access behavior.

Contextual descriptor literals preserve the written order of `count`, `data`, and `allocated` initializers. Missing fields use zero storage. Descriptor field places permit source code to update real dynamic array storage. Native allocation fixtures call host libc `malloc`, `realloc`, and `free` through declared foreign procedures; allocation behavior remains in source procedures, without fabricated `array_add` compiler builtins.

Mixed Jai variadic calls such as `collect(20, ..existing, extra=2)` build a checked `SequenceConcat` at the pack parameter. Scalar arguments are evaluated once, and each spread is copied immediately before later argument expressions run. Already boxed `Any` spread elements retain their descriptors. A lone spread forwards its existing descriptor without allocating.

Concatenation backing belongs to the caller frame. A callee may return a view borrowed from that frame, and the caller may consume it until it returns. Native allocation metadata and VM allocation identities reject typed returned pointers or descriptors into the departing frame, including nested records, arrays, and local aliases. Proven direct forwarding escapes produce a source diagnostic; other escapes trap. Native untagged unions conservatively check each pointer-capable member representation. Explicit integer encodings of addresses and stores into longer-lived source storage retain ordinary Jai pointer lifetime responsibility.

Each nonempty spread snapshot and final backing region charges its size, alignment padding, and bookkeeping against one cumulative frame budget. Repeated calls in a loop therefore remain bounded; empty storage has null data and no charge. Storage is reclaimed when its owning frame returns, with no hidden permanent heap allocation. Negative counts, null nonempty data, count overflow, byte overflow, and exhausted scratch budgets fail before copying or allocating.

Dynamic array regression programs implement reserve, add, resize, ordered removal, and reset as source procedures over real descriptor fields and host `realloc`/`free`. They test empty and invalid removals, rejected negative and overflowing capacities, unchanged storage for satisfied reserves, zero initialization on growth, shrinking, and repeated reset. These procedures illustrate supported language behavior without adding invented compiler builtins.

## How to change it

Source index normalization lives in `jai-sema/src/pointers/index_values.rs`; target displacement checks live in `jai-codegen/src/pointers/index_values.rs`. `sequence_index_width_ir.rs` verifies VM/native unsigned behavior and emits a real 32-bit object, checking its stride guard and lossless target normalization. Preserve signed descriptor count validation when adding new sequence types.

`TypeLowerer` rejects fixed-array byte sizes outside the selected target's pointer domain before constructing their LLVM array type. Its dynamic descriptors use the adopted allocator's exact nominal storage type when an authentic Preload role is available; bootstrap-disabled descriptors retain their existing zero allocator storage. See [canonical allocator schema](allocator-schema.md) for source identity binding. Typed `.allocator` projection requires the coordinated VM representation integration.

Mixed pack construction lives in `jai-sema/src/procedure_values/sequence_packs.rs` and its source-ordered argument binder. Native allocation and lifetime checks live in `jai-codegen/src/sequence_packs.rs` and `sequence_pack_lifetimes.rs`; the VM mirrors them in its `execute/sequence_concat.rs` helper. Preserve the shared `jai_ir::sequence_temp_allocation_charge` policy when changing allocation strategies. Extend semantic construction in `crates/jai-sema/src/sequences.rs`, the enum-based common IR and its verifier, `crates/jai-codegen/src/sequences.rs`, and the VM together. Preserve initializer evaluation order and avoid evaluating the first inferred array element twice. New descriptor fields need both their semantic type and their physical ordinal checked; they must not be treated as nominal record fields. Keep `jai_ir::is_static_value` consistent with actual LLVM constant construction, including custom record layouts. The backend rejects a static-classified array snapshot that lowers to a runtime value, since falling back to stack storage could invalidate a returned view.

Native regression fixtures live in `crates/jai-codegen/tests/sequences.rs`. Independent checked-IR VM/native fixtures live in `crates/jai-codegen/tests/sequence_packs_ir.rs` and verify borrowed-callee returns, escaping local aliases, mutable string backing, and immutable literal writes without relying on source binding. They compile trusted Jai source through the Rust implementation, compare VM results for operations available in virtual memory, emit a target-specific object with LLVM and link it with independently installed Clang, and execute only that newly generated program. The libc allocation fixture is native-only because the VM does not execute host foreign calls. These tests do not execute the supplied reference compiler or its native libraries.

## Configuration

Mixed packs use `MAX_SEQUENCE_TEMP_BYTES = 1_048_576` per caller frame. The shared charge helper requires a power-of-two alignment and charges `max(bytes,1) + max(alignment,16)-1 + 64` for each nonempty region. The 64-byte allowance covers metadata and stack padding. This fixed compiler resource policy is independent of VM fuel and allocation limits. Sequence behavior has no environment switches. Array counts are compile-time nonnegative integers. Declaration defaults use a budget of 1,048,576 materialized constant cells and a depth limit of 128, defined in `crates/jai-sema/src/constant_limits.rs`; failures produce located diagnostics. All-zero array defaults retain compact zero storage, so large zero arrays do not expand into compiler-owned element vectors. Target size and alignment policy come from LLVM target data rather than Rust host layouts. Native tests require Clang and the same configured LLVM installation as the rest of `jai-codegen`.

## Dependencies

Semantic resolution uses `jai-syntax`, `jai-types`, and `jai-ir`. LLVM instruction and constant construction uses Inkwell; native tests use Clang. The VM uses typed virtual memory rather than host pointers. Reference sources are read statically for language evidence.
