# Module scope syntax foundation

## What it is

`jai-source` provides opaque compilation identities and immutable source records. `jai-syntax::parse_file` parses one file independently, and `jai-modules::ModuleGraph` resolves its source dependencies, module namespaces, exports, and file privacy. Executable lowering is a separate semantic/backend responsibility.

## How it works

Create a `SourceMap`, insert decoded UTF-8 source with its display path, and pass its `SourceRecord` plus a session `Symbols` table to `parse_file`. `ParsedFile::source()` identifies the file and `items()` preserves its top-level order. Each top-level item carries a `SourceSpan`. Nested expressions and statements retain file-relative `Span` values, converted through `ParsedFile::location(span)`; they never refer to concatenated source. Parse errors are `LocatedDiagnostic` values with source identity and original offsets.

`SourceId` is allocated by `SourceMap`. `Identities` allocates `UnitId`, `ModuleId`, `ScopeId`, and `DeclarationId`; constructors are private and each ID has `index()`. These IDs are registry-local: use one registry of each kind per compilation session. A `Symbol` identifies an interned spelling, not a declaration. All independently parsed files share one `Symbols` table, which is restored even after parser errors.

The parser starts each file in `Visibility::Export`. `#scope_export`, `#scope_module`, and `#scope_file` update subsequent declaration/import visibility, with optional semicolons. `FileItem::Load` preserves a dependency rather than expanding it; it does not inherit a caller's visibility into the loaded file.

`FileItem::Import` records an optional namespace, `using`, active visibility, `ImportMode::{Search, File, Directory, String}`, a literal target, and separate instance/program argument lists. Absent lists differ from explicit empty lists. Argument names use `Symbol`; values use `ModuleArgumentValue::{Expression, String}`. `#module_parameters` records inferred, scalar, string, structured type, and interface-constrained annotations and optional defaults, with a separate optional program-parameter list. Duplicate parameter directives in one file fail parsing; argument duplication, binding, evaluation, module-entrypoint placement, and program-parameter ordering belong to semantic graph construction.

Qualified references have `ExpressionKind::QualifiedName(NamePath)` or `QualifiedCall(NamePath, arguments)`, where `NamePath` contains a root `Symbol` and ordered member symbols. This is module qualification syntax; arbitrary struct/member access and indirect calls remain unsupported.

The existing `parse(&str)` API is an explicit compatibility entrypoint for the executable subset. It rejects scope/import/load/module-parameter directives and qualified references. The driver uses `parse_file` through the module graph; the scalar `parse` API remains useful for isolated frontend tests. Module syntax acceptance through `parse_file` is not evidence of resolved imports or executable support.

### Scoped module graph

`ModuleGraph::load(entrypoint, GraphOptions { import_dirs })` creates an application module and recursively loads its dependencies. File and directory imports resolve relative to the importing file. Named search checks each configured directory in order, preferring `Name.jai` over `Name/module.jai` within a directory. Filesystem paths are canonicalized; the canonical entrypoint and the ordered supplied instance arguments identify an imported instance. The identity includes argument names, typed evaluated values, and absent versus explicitly empty lists. Reordered names and explicitly supplying a default deliberately create separate instances, following the supplied `380_module_parameters` source tutorial.

A `FileInstanceId` identifies a file's participation in one module. Canonical `#load` paths deduplicate within that module, and every loaded file gets its own file scope starting in export mode. The same source can also appear in another module: immutable source text and parsed syntax are shared, but its file scope and declaration identities are distinct.

`Binding` separates name resolution from spelling: declarations, immutable overload sets, modules, and parameters carry their own typed identities. Namespace-member aliases retain their owner declaration plus member symbol; storage-member aliases retain a source storage-member identity. Every declaration stores its defining file, syntax, and original location. A file-private binding shadows the containing module binding. Module-private declarations are visible to all files of that module, while namespace lookup consults only exports. Imported procedures retain their defining file for later semantic resolution and cannot acquire application globals through an import.

Anonymous imports link exported bindings into the active file/module/export scope. Namespace imports bind a module reference. `using Alias :: #import` binds that namespace and also links its exports. Reexports preserve declaration and module identity; they do not duplicate storage. Repeated imports are idempotent. Procedures and procedure aliases with the same destination name form an immutable overload group of original declarations, including declarations from different modules; value and type collisions still produce located errors. Export linking order is deterministic.

Graph accessors expose immutable modules, files, declarations, source records, spellings, and typed import/load edges. `lookup(file, NamePath)` returns a typed binding or `LookupError`; `locate(file, span)` attaches the original source identity to nested syntax offsets. Same-instance `#import` backedges reuse their reserved module and declaration identities instead of recursively expanding source. File-level anonymous/`using` import publications are retained and replayed to an export fixed point as late loads and selected declarations appear. Repeated linking remains idempotent, including immutable overload membership. Namespace links always reference the original module. Canonical `#load` cycles and recursive imports that would create a new specialization of an active source remain located errors; admitting a graph edge does not resolve genuine constant, type-layout or compile-time execution dependency cycles. Source parse failures and binding conflicts render their original file and line.

A binding collision reports the import or declaration that attempted publication, followed by the original locations of the existing and incoming declarations. These notes follow declaration identities through imports and reexports. Overload groups show up to four original declarations per side; source-member aliases identify their original namespace owner. Module namespace links have no declaration location to invent.

Bootstrap fallback names are consulted after ordinary file/module bindings; they are not injected into those bindings or module exports. Consequently, changing Preload cannot resolve a collision between two anonymous imports. The pinned OpenJai `build.jai` imports both its Basic and Compiler modules, which independently export `Type_Info`: Basic defines an enum-tagged record at `modules/Basic/module.jai:82`, while Compiler defines a string-tagged record at `modules/Compiler/module.jai:123`. Their declaration identities and field layouts differ. That root currently remains blocked by this source incompatibility; the graph neither unifies those records by spelling nor substitutes the reference Compiler module. Qualified imports can preserve both identities, but the compiler does not rewrite the supplied root.

The independently selected modern Compiler and legacy Preload/Basic source profiles also disagree about `Source_Code_Location`: [pinned OpenJai Compiler](https://github.com/withlang-dev/open-jai/blob/264ba53218bf0e55bbc328197b312fe704496224/modules/Compiler/module.jai#L13) exports a two-field nominal record, while the selected Preload has a third signed character coordinate and Basic aliases that canonical Preload identity. Anonymous imports of both distinct records correctly collide. This is a source-profile incompatibility, not evidence that equal spelling or similar structure makes nominal types equivalent. Preserve each public contract and choose an explicit genuine-declaration profile adapter where the compiler service permits it; the loader does not rewrite an imported public type to pass a root.

Module instance parameters bind scalar, floating-point, UTF-8 string, source-nominal enum, and type values into private module scope. Float instance-key identity includes precision and raw IEEE bits, preserving signed zero and NaN payloads. Inferred float parameters retain their default precision; explicit `float32` and `float64` annotations bind floating-point values, allowing float32-to-float64 widening and rejecting implicit narrowing. Float conditions use numeric nonzero truthiness, so both signed zeros are false. Explicit scalar parameter types require range-preserving coercion; inferred parameters use their default's type. Required values, unknown names, duplicates, positional arguments following named arguments, and declaration collisions produce located diagnostics. Parameter values live in `BoundParameter` records exposed through `parameters()` and `parameter(id)`; they are never rewritten into synthetic declarations or mangled symbols. Each instance allocates its own file scopes and declaration identities, which allows semantic lowering to preserve separate storage.

The second import argument list configures program parameters once per canonical module entrypoint, before every other import of that module. Only the application module may set it. Fully bound program values, including defaults, are shared by later instances; program parameters do not enter the instance identity. `#module_parameters` must be in the module entry file. Its declaration block produces real private declarations, which are available while evaluating defaults. Defaults use a fixed-point parameter binder, so a scalar parameter may depend on another parameter declared later.

File-level `#if` preserves both branches in syntax and expands only the selected branch. Selected declarations become real bindings; selected loads preserve independent file scopes, and selected imports retain normal isolation. A per-module dependency worklist retries unresolved pure constants after subsequent loads or imports add bindings, including constants from a later unconditional `#load`. Neither branch text nor loaded source is concatenated with the caller.

Pure scalar arguments, defaults, and conditions use `jai-eval::evaluate_paths`, resolving names in the defining file and module. Unknown or semantically unresolved dependencies return `GraphError::Pending`; unsupported argument/default evaluation returns `GraphError::Unsupported`. Conditions that need semantic evaluation become typed requests in [incremental source discovery](source-discovery.md), retaining the same graph and original source context until the caller supplies a selection. The convenience `load*` APIs return `Pending` for those conditions. Pure integer/boolean operators, casts, conditionals, and scalar constant chains work. Builtin, source-nominal, and structural type-valued parameter defaults bind with graph source identities and materialize in the shared semantic registry. Generic record applications and semantic type queries require a later semantic scheduler; target-platform constants use explicitly supplied `BuildTarget` facts and source tag enums; they are not fabricated. String imports remain unsupported. The graph itself does not validate procedure bodies or require `main`; that belongs to semantic resolution, with `main` restricted to the application by the executable entrypoint policy.

## How to change it

Edit `jai-source/src/locations.rs` for source records and compilation identities, `jai-syntax/src/modules.rs` for module AST/parser behavior, and `jai-modules/src/loader.rs` for source loading and export linking. Public graph types and lookup live in `jai-modules/src/lib.rs`. Add AST variants for new dependency forms before teaching the graph resolver their semantics. Keep syntax and visibility resolution separate: import aliases must eventually refer to declaration identities, and module instances must own distinct globals. Do not concatenate module text or ignore scope directives to produce successful builds.

[Nested procedure and block imports](scoped-imports.md) retain lexical aliases while loading canonical module dependencies. Computed dependency targets and semantic conditions require additional phases. Non-scalar module parameter annotations retain their structured `TypeSyntax`; builtin, source-nominal, and structural type parameters bind source identities without allocating foreign runtime type IDs. Named interface-constrained records check explicitly typed member signatures and expose the declared type variable. Parameter declaration blocks retain all declarations. Generic record applications, modified interface types, inherited members, and inferred/generic signatures remain explicitly pending semantic resolution. Enum defaults bind through declaration identity; see [Module parameters and target selection](module-parameters.md). The graph has no dependency on sema, avoiding a compiler-phase cycle.

Reference rules come from `reference/how_to/040_import_and_load`, `151_file_and_global_scopes`, and `380_module_parameters`. Recent corpus examples in jaison, Linux_Display, Simp, and Vk-Engine confirm file/module scope switches and both parameter lists. The historical tutorial documents order-sensitive explicit-argument deduplication; both parser and graph preserve that ordered request identity. This is a source-backed compatibility rule, not a claim about all newer compiler versions.

Same-instance admission and export replay live in `loader.rs` and `loader/import_cycles.rs`. Keep argument evaluation and program-parameter ownership checks before admitting a backedge. The replay records binding scope and original import location, not synthesized declarations; update it when adding an import publication mode. The fixed point follows finite original names/declarations and canonical overload sets. Acyclic graphs skip replay. `import-cycles` graph tests cover late reexports, overload identity, privacy, exact typed instance requests and genuine collision rejection; semantic tests cover original defining environments and mutually recursive nominal pointer fields. Retained source discovery also tests selected lexical backedges without rereading source.

Collision-origin rendering lives in `jai-modules/src/loader/collisions.rs`; extend its typed binding match when adding a binding kind. Keep identity and linking policy in the graph rather than inferring equivalence from diagnostic spellings. `nominal-import-origins` tests cover qualified distinct records, fallback shadowing, and the same genuine import conflict with Preload enabled and disabled. A policy that retains ambiguous imports until use would require separate language evidence and lookup semantics; richer diagnostics do not implement that policy.

## Configuration

The CLI selects module search directories with platform-separated `JAI_RS_MODULE_PATH`, defaulting to `modules`. Graph callers supply `GraphOptions::import_dirs`; its default is the process-relative `modules` directory. Per-file parser callers supply decoded sources and one interner. `SourceMap` performs no filesystem reads, path canonicalization, or source decoding; those remain driver responsibilities.

`JAI_RS_PRELOAD=search` selects the first Preload source under the configured search roots; `off` disables the fallback. Collision notes use the internal `MAX_COLLISION_ORIGINS = 4` bound and have no runtime configuration.

## Dependencies

This foundation uses standard Rust, `jai-source`, `jai-lexer`, and the existing `jai-types` scalar types. It adds no external dependencies. `jai-modules` depends on source, syntax, lexer, shared `jai-types`, and the pure `jai-eval` evaluator, allowing sema to consume it without depending on the driver. The driver reexports it as `jai_driver::modules` and resolves checked programs through the graph-aware semantic APIs.
