# Parameterized records

Parameterized record declarations retain their source parameters and specialize into nominal runtime types when applied. A type application such as `Buffer(u8, 16)` binds baked type and value arguments; the unapplied declaration has no runtime layout.

## How it works

The syntax layer keeps ordered `RecordParameter` declarations, source `CallArgument` expressions, and the complete ordered record member body. The semantic layer resolves parameters in declaration order. Typed parameters constrain their argument, inferred defaults establish a parameter's type, and a default may refer to an earlier parameter. Named arguments are matched to declaration slots before binding; duplicate, unknown, missing, and out-of-order arguments produce diagnostics.

`RecordSpecializations` belongs to the mutable semantic context. Its key combines a typed template declaration identity with normalized baked argument values in declaration order. The compiler reserves a nominal `TypeId` before resolving fields, so a pointer to `Node(T)` refers back to the same type while its shape is being built. An unsuccessful materialization can retry using the same reserved identity. Structural types continue to be interned by the sole mutable `TypeRegistry`.

Field annotations, fixed array counts, layout constraints, and immutable field defaults read a typed substitution overlay. Nested record declarations reserve their own nominal identities within the owning instance. Record body constants and transparent aliases resolve forward dependencies before field materialization. Nested enums retain nominal identities under their owning source record, including static records used by Preload. Their representation, flags, members, and typed defaults come from that declaration. The original syntax remains unchanged. Two equivalent applications of one template have one nominal identity; distinct originating declarations remain distinct even if they have the same spelling and field layout.

Namespace constants may contain typed aggregates and exact checked procedure identities. Their evaluator shares the immutable source declaration facts seeded before record definition; a signature's type alone never creates a callable value. Explicit casts determine the canonical target of an inferred field or member constant before its value is evaluated. Nested shapes and constants resolve through one dependency worklist, so a forward aggregate literal waits for its reserved nominal shape. Field inference uses the same typed lookup as baked parameter defaults.

Once a nested shape is complete, later ancestor bindings extend its default and method scope without rebuilding its descendants. Existing local bindings keep their lexical precedence. This keeps deeply nested forward defaults bounded by the actual declaration tree.

```jai
Buffer :: struct(T := int, N: int = 3, Fill: T = 7) {
    values: [N] T;
    tag: T = Fill;
}

first: Buffer();
second: Buffer(N = 2, Fill = 11);
```

Procedure signatures such as `read :: (box: Box($T)) -> T` retain the originating record template and argument patterns. Overload selection reads immutable specialization metadata to infer `T` or a baked count, and only the selected signature materializes a result such as `Box(T)`. Omitted defaults remain typed constraints. Each instance retains canonical defaults evaluated against its actual preceding arguments, so a null callback default whose signature depends on `T` can match after type inference. An instance with a customized baked argument does not match a header that omitted that default. Selected result specialization fills omitted parameters from the original definition scope.

Restrictions such as `value: $R/Table` match the actual generic record origin without constructing an instance from missing arguments. `value: $R/interface Readable` checks the declared members against canonical field types. Existing module or definition bindings remain concrete inside the restricted pattern; a restriction does not replace them with a new inferred variable. The header builder preserves restrictions inside pointers, arrays, callbacks, and application arguments for the common matcher.

Explicit arguments in procedure bodies also read an owned lexical snapshot. Local type names, typed nested namespaces, and raw weak scalar constants reach the binder without changing their source syntax. Captured code, inline record type expressions, and already checked query results use expression spans in the snapshot. Formal annotations, omitted defaults, nested bodies, and field defaults use the definition scope and preceding formal bindings; caller shadows cannot change them. Bound specializations validate each typed value against its resolved formal type before entering the cache.

Concrete record methods retain the owning `TypeId`, source member ordinal, and defining file. Member reservation stores their source environments without defining a placeholder shape. A type-only header sweep publishes exact procedure identities without evaluating parameter defaults. A separate complete-header phase fills actual defaults using the same IDs; body checking follows provider readiness. Publishing a header does not mark a body ready. The body sweep reserves every signature before checking real bodies, which permits mutually recursive methods. Baked record parameters and nested members are available through the definition overlay. Methods use explicit parameters; the binder does not add an implicit receiver. The compilation worklist checks methods of every materialized record, including unused methods. Independent polymorphic method parameters and overload groups still require the lexical callable template worklist.

The source worklist runs header completion with its actual compile-time provider, including the completed Context schema and ready source bodies. A pending `#run` default does not prevent other record owners or default-free sibling methods from becoming ready. After each sweep, callable aliases refresh their named parameters and defaults from the latest canonical signature while retaining the same procedure identity. This also applies to chains such as `forwarded :: alias; alias :: Methods.read;`.

Callback annotations resolve every source parameter type, including `#discard` parameters. Their runtime procedure type contains only evaluated parameters, with variadic positions counted after that filtering. Original source annotations retain the discarded argument contract for call checking, so an erased ABI slot does not permit an unresolved annotation or execute the supplied argument.

Namespace short lambdas retain their original constant declaration in the record's source environment. A contextual lambda has no invented callback signature during member reservation. Its value or call producer supplies the expected callback or argument types, then reserves and checks the actual procedure through the shared allocator. The namespace source lookup can prepare the type-only environment without executing defaults or unrelated bodies.

Record namespace enumeration follows the selected source declarations. Captured outer names, the record's own name, and baked parameters remain available for definition-scope evaluation but are excluded from `using` exports. The specialization table retains the ordered source member names separately from that evaluation overlay.

Direct insertion such as `#insert #code { values: [N] T; }` expands original declaration syntax before both member reservation and field materialization. The two passes use identical member order so inserted nested types retain stable identities. Quoted fields, constants, aliases, records, enums, procedures, and prototypes retain their original spans and attributes. Runtime statements and nonliteral insertion operands produce diagnostics. Code-value insertion with captured external scopes, generated source strings, and writable `#modify` descriptors require additional scheduling and remain explicit diagnostics.

Record `#assert` conditions must succeed before the shape is defined. Optional assertion messages are checked compile-time strings in the definition scope, including when the assertion succeeds. Record `#if` selects one ordered member sequence from baked formals and the definition scope; inactive members are never registered. Case tables use the common canonical selector for type, bool, integer, enum, and string values. Labels retain expected types and enum identity, `#through` retains the original following bodies, and `#complete` checks the actual bool or enum domain. Both reservation and materialization consume the same checked sequence. Numeric predicates use the pure typed evaluator, and nullable baked callbacks test their actual checked identity or zero value. A condition that needs a not-yet-bound body declaration remains a dependency diagnostic rather than assuming either branch.

Plain assignments inside a checked record body override construction defaults. Each target resolves to real physical `FieldId` projections, including promoted `using` fields and anonymous aggregate members. The default evaluator applies active assignments in source order to an owned root-field constant. It checks each assigned value against the final field type and leaves the nested type's canonical defaults unchanged. Quoted insertion preserves assignments before selection and default evaluation. Index, pointer, and union default paths require additional semantics and receive diagnostics; see [record default overrides](record-default-overrides.md).

The source and VM suite covers argument diagnostics, recursion, default constraints, member namespaces, nested enum identities, and inferred type/count/value parameters. `jai-codegen/tests/parameterized_records.rs` additionally lowers self-written fixtures, compares their VM results, links fresh objects, and executes them at O0 and O2. It never executes the reference corpus.

## How to change it

The implementation is in `modules/aggregates/parameterized/`: `binder.rs` owns argument association, `state.rs` owns canonical reservations and ready metadata, `type_resolution.rs` resolves type syntax, and `materialize.rs` builds schemas. Extend baked values in `polymorphism` rather than adding printed signatures to specialization keys. Preserve reservation-before-recursion and ensure failures release the active depth and containing-record slots without replacing a reserved ID.

`lexical.rs` defines the caller snapshot; `member_values.rs` preserves typed namespace values during constant evaluation. `methods.rs` stores member procedure source identities, and `namespace.rs` calls the checked binder in `local_declarations/methods.rs`. Methods share the checked procedure allocator and retain definition scope when bound. `modules/compile_time/methods.rs` coordinates complete headers and actual bodies through the worklist provider; `modules/record_method_headers.rs` refreshes source aliases. Keep pending dependencies available to both phases so defaults can wait for genuine provider bodies. Extend quoted declaration categories in `metaprogram/record_members.rs`; keep `expansion.rs` shared by reservation and materialization.

Instance namespace access uses the original selected member names and the actual template's own formal parameters. It excludes the enclosing record's injected bindings and other definition-only names. Pure argument descriptions use the same guard and read published facts without allocating constant handles or binding method bodies. An incomplete published method header records its actual procedure dependency rather than advertising complete defaults.

`conditions.rs` evaluates record predicates and typed case tables, and `expansion.rs` selects checked members. It shares `compile_time_cases::select` with other source scopes. Lexical imported applications retain the actual template declaration identity in the caller snapshot, so namespace aliases do not require path rewriting. `member_constants.rs` binds typed namespace constants, while `members.rs` schedules dependencies and complete member namespaces. `default_overrides.rs` resolves original assignment targets; `record_default_overrides.rs` validates physical promotion paths and replaces owned constant projections.

`Defaults` shares the existing typed constant evaluator across static records and late specializations. Explicit named and positional literals resolve their type through the bound record namespace before module declarations, preserving nested nominal identities and lexical shadows. New default expression forms belong there, where constant depth and cell limits remain enforced. `Resolver::lexical_annotation`, file-scope annotation adapters, and record metadata queries connect applications to procedure bodies and module declarations.

The staged `application_proofs.rs` helper supports future immutable literal and callback-preview consumers. Its key retains the original application site, actual file instance, exact supplied substitution, lexical scope identities, and enclosing annotation owner. A proof records normalized initial arguments separately from the final nominal key and requires ready canonical record metadata. Register its producer only after retained preparation can retry missing proofs; a read-only consumer must never substitute its expected type, reserve a specialization, or rerun a modifier. The helper is currently unregistered and supplies no production readiness fallback.

`pending_types.rs` preserves separate modifier and authored-placeholder dependencies for retained initial type preparation. A placeholder dependency keeps its actual graph identity and original demand location; only a diagnostic boundary formats the reservation note. Recursive resolution must intercept the typed lookup result before converting it into a diagnostic, and scalar expressions must retain the evaluator's actual binding and arithmetic behavior when discovering dependencies. The paired scalar adapter carries dependencies separately from diagnostics, clears only unfinished constant visits on a wait or error, and retains ready constants. `jai-eval::DomainInference` reads actual primitive annotation facts, ready scalar bindings, or recursive initializer domains before evaluating selected values. An inactive typed operand still widens a conditional result, but its initializer is not read. A genuinely unavailable domain retains its real prerequisite. The structured domain binder distinguishes actual typed execution producers from pure dependent aliases. Only the producer carries `PendingType::Constant` with its original declaration ID; only a genuine completed scalar is admitted through `Constants::register_ready_value`. The adapter never invents a domain or parses a diagnostic message as a dependency.

Source dependency discovery currently has specialization jobs for procedures. Generic record bodies still need a separate dormant declaration scan and record job; their dependency selection is not yet specialized against the accepted record formals. The unregistered `source_records.rs` carrier retains the actual reserved owner, original declaration extent, record span, and named final baked arguments in formal order. Its future producer must run after modifier acceptance and canonical reservation, before resolving body fields that may themselves need imports. Ready layout metadata remains a separate fact. The source codec must encode these final bindings directly, reject nonportable values precisely, and avoid reapplying a modifier to its own output.

Unsupported record body declarations or modifier execution must produce a diagnostic before field-only iteration. Keep complete member syntax available for checked namespaces and insertion.

## Configuration

There are no environment variables. The compiler's constant depth and cell budgets in `constant_limits.rs` constrain recursive expansion and default materialization. Literal insertion limits nesting to 128 and declarations to 65,536; method materialization also limits the number of checked record owners to 65,536. Layout annotations use the same target-independent record layout checks as ordinary records.

## Dependencies

This path uses `jai-syntax` for source syntax, `jai-modules` for definition-site identities and lookup, `jai-types` for nominal and structural types, `jai-ir` for immutable constants, and the polymorphism module for typed substitutions and baked values. The integration tests compile only self-written Jai fixtures and execute the resulting checked IR in `jai-vm`.
