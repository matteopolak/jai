# Typed process source adapter

## What it is

`jai_vm::process_source_machine` adapts a selected set of bound source POSIX declarations to typed VM memory and the shared virtual descriptor ledger. Its control outcomes preserve source suspension and fork boundaries; they do not manufacture native process results or replace ordinary `Process` bodies.

## How it works

`ProcessAbiProcedure::invoke_process` receives the actual checked arguments, private branch `Memory` and `ProcessBranchState`, the exact source target, a scheduler-owned shared `VirtualProcesses`, and a work-charge callback. It revalidates the sealed [ABI proof](process-abi-bindings.md), target and complete argument types/count before accessing process state. The memory byte target must match. Integer file descriptors and counts must be portable integers; address-derived integer provenance is rejected.

The implemented scalar operations are `pipe`, `close`, `read`, `write`, `dup2`, `getpid`, `getppid`, positive-child `waitpid` and the target errno accessor. The [descriptor flags adapter](process-descriptor-flags.md) implements the exact `fcntl` getter/setter C-int protocol. Its central dispatch now validates the declared two-argument prefix under the configured VM limits, then validates the complete closed getter/setter protocol through the sealed adapter. This permits a setter's real third promoted `s32` operand without admitting arbitrary C-vararg calls. The three central dispatch regressions passed in the coordinated 557-test VM gate; the earlier frozen CLI remains unchanged. `pipe` writes two actual `s32` descriptors into the supplied `[2] s32` source allocation. Read and write use bounded target byte ranges. Sending pointer/procedure relocation tags as bytes rejects. An incoming partial read initializes only the bytes actually received, preserving uninitialized trailing storage. Zero-count reads and writes never dereference their source buffer; a valid empty pipe read returns zero immediately instead of blocking. Invalid descriptors remain invalid even for zero-count calls.

Work accounts for shared-world backing/metadata, candidate cloning/cleanup, memory byte-image operations and errno state before any source allocation, byte copying or mutation. The adapter operates on a candidate world and publishes it only after the corresponding memory write succeeds. `ProcessCallOutcome::Pending(ProcessEvent)` consumes no transport data and changes no source memory. The VM must retain the exact operands and resume that call when its real virtual event becomes ready.

Recoverable descriptor errors `EBADF`, `EAGAIN` and `EPIPE` return the proper `s32`/`s64` negative result and update a stable, mutable cell of the actual source `OS_Error_Code` IsA nominal. The inspected macOS/Linux errno values are selected by the sealed target. Successful calls preserve errno. Memory lifetime, readonly storage, provenance, type, policy and budget violations remain VM/boundary errors; they are never converted into fabricated C errno. Virtual pipe writes report `EPIPE` without inventing a native signal.

Each `ProcessBranchState` retains its typed current process and private errno pointers. `for_child(child, world)` verifies a real ledger parent/child relation and clones the metadata. Its caller must also create the corresponding private forked memory space with inherited pointer roots preserved. The child returns its actual virtual parent's ID; a root `getppid` rejects because the model has no external parent.

An exact bound `fork` emits an opaque `ProcessForkControl` containing the proof and actual parent. It creates no ledger child and returns no scalar PID. The central VM must split genuine source continuations, fork memory/descriptor state, and inject child/parent results. Exact bound `_exit` emits an opaque `ProcessExitControl` with the actual checked `s32` status; the scheduler applies its low exit byte and discards that branch continuation without running source cleanups. `waitpid` accepts a selected positive child and either zero options or the inspected `WNOHANG = 1`; it suspends on the actual child event, preserves status for a still-running child, and stores `(exit_code << 8)` before publishing a single reap. A null status pointer skips storage. Missing/already-reaped children return `ECHILD = 10`. Signal/timeout status encoding remains unsupported because the host receipt carries no actual signal number. The [socket ABI adapter](process-socket-abi.md) additionally implements exact nominal `socketpair`, SCM_RIGHTS `sendmsg`/`recvmsg` and `shutdown(WR)` with inspected target layouts. The central `fcntl` route is active and tested. Eight genuine continuation-scheduler regressions also passed in the coordinated VM gate; the authored source fork fixture and reviewed exec bridge remain queued.

The separate `invoke_exec` route decodes the inspected `execvp(*u8, **u8)` arguments through actual typed memory. It reads each null-terminated pointer entry and bounded C string, preserves byte sequences and argv[0], and resolves the exact executable spelling, complete argument boundaries and canonical working directory against sealed `ReviewedPrograms`. It performs no PATH lookup, shell expansion or native call. `ProcessExecScope` is trusted embedding authority with a fixed canonical cwd; source `chdir` is not implemented.

The existing outer `CompilerEffects` transaction submits one exact `RunProgram` request. An opaque `ProcessExecControl::HostPending(key)` retains the actual request key; `complete_process_exec` applies only its observation and never submits again. `Replaced` means the scheduler must discard the child continuation. The host receipt captures the entire registered child completion, so successful exec never returns a scalar zero to source. Actual output work is charged before ledger replacement. A matching-platform `ProcessLaunchFailed` observation returns source `s32 -1`, writes its actual errno and preserves child/CLOEXEC descriptors; capability denial, budget rejection and mismatched-platform errno remain fatal boundary errors.

## How to change it

Keep branch memory separate from the shared world. A world clone per source branch breaks inherited communication; a candidate clone inside one atomic call is only temporary validation state. Extend the operation dispatch only with exact bound proofs and complete typed argument checks. Retain pending host keys and complete exec observations once rather than reissuing an already-submitted virtual exec. Successful exec must replace the child continuation.

The self-authored Rust tests exercise actual typed `Memory` buffers, pipe output arrays, partial reads, suspension/EOF, dup/close, nominal errno writes, zero counts, uninitialized output, fuel rejection, wrong argument types, pointer-tag rejection and sealed fork control. Exec tests additionally exercise byte-preserving argv, exact review rejection, actual launch errno, retained pending completion, duplicate completion rejection, raw-integer argv authority rejection and output fuel failure. The full `jai-vm` gate passed 518/518 tests, including all 34 process adapter tests: ten socket tests and six descriptor-flag tests are included in that total. No separate focused 34-test run was performed.

The mandatory authored driver fixture (`cargo test -p jai-driver --test process_abi`) passed 1/1 tests. It compiles checked Jai source, consumes its actual `#run`, exercises pipe/write/partial read/EOF/close and `EBADF` through the nominal errno cell, and verifies the resulting `main` value is 131. The former missing foreign-route failure is resolved for this fixture. This source test and the Rust adapter gate do not establish unchanged ordinary `Process` wrapper execution. The additional `process_fcntl` driver fixture is authored and queued: its exact receipt-bound stdio declaration uses `..Any`, nested getter/setter calls preserve C-int operands, and its `#run` must complete with 42. Three passing `central_fcntl` VM tests cover actual pipe descriptors on both inspected targets, malformed tails before ledger initialization, and fuel rejection before flag mutation. Exec activation remains held; complete source acceptance must additionally cover the genuine continuation scheduler and remaining ordinary foreign/source operations.

## Configuration

The bound proof supplies the exact inspected source target. `ProcessLimits` bounds transport and descriptor work; VM `Limits` bounds memory and fuel. The explicit charge callback must reject work before mutations when the root budget is exhausted. `ProcessExecLimits` defaults to 4096 arguments and 1 MiB aggregate executable/argument bytes including terminators. `ReviewedPrograms` separately bounds registry entries, payload and arguments; its cached work includes empty argument metadata. The embedding must supply the exact registered-program grants and canonical cwd in `ProcessExecScope` (typically shared by `Arc`). No host executable, root directory, shell, native library or source capability is enabled by constructing branch state.

## Dependencies

[Process ABI proofs](process-abi-bindings.md), [the virtual process ledger](virtual-process-protocol.md), checked target memory/byte images, actual source nominal types and the central resumable VM scheduler. Complete ordinary source Process compatibility also depends on authenticated source binding, actual allocator/context bodies and the central source availability/control hooks, the trusted reviewed-program host provider and the remaining socket/ancillary adapters. No supplied native artifact is executed or loaded.
