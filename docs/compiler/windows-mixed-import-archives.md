# Windows mixed-machine import archives

`interp/native/windows_imports.rs::object` validates COFF import metadata and returns each provider with its exact machine tag. `providers` scans the complete archive, selects only exact-machine records, and deduplicates their provider basenames case-insensitively. Incompatible records cannot select a DLL or contribute to compatible-provider ambiguity. When no compatible provider exists but an incompatible import does, the existing CPU-mismatch diagnostic remains an error.

Validation precedes filtering: malformed incompatible members, truncated headers/payloads and invalid archive padding still reject, including after a compatible provider has already been found. ARM64EC (0xa641) and ARM64 (0xaa64) are distinct ABIs. Recognizing either tag does not translate one ABI into the other or enable a new interpreter CPU. Candidate search precedence, DLL loading and rejection of multiple compatible providers are unchanged.

The admitted public Microsoft.Windows.SDK.CPP.arm64 10.0.26100.6584 archive `c/um/arm64/d3dcompiler.lib`, SHA256 `afdbfe3ffbaf9d9044d75393f5f4c1e623c236880238f9c4c706c323ffc6320c`, contains 28 ARM64EC and 28 ARM64 short imports. Before this correction its metadata reader returned a CPU-mismatch error at the first ARM64EC import. Afterwards selecting ARM64 returns exactly `D3DCOMPILER_47.dll`. The SDK artifact was read only as metadata and is not committed.
