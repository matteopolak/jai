The failure is in match_pattern_value's polymorphic-struct call branch. StructInfo.poly_args is a value-only instance key, not the written parameter declaration or its types. type_of_value(Int(20)) returns s64 even when the actual constant was bound as u64. The same positional key can include hidden inferred type bindings and parameters already fixed by a baked alias, so indexing it by written argument position can also infer the wrong value.

The fix selects the constructor's written parameter declarations, then retrieves each instance constant and its actual TypeId by parameter identity through existing poly_struct_bindings. Named AST identifiers compare symbols, not source spans. Qualified constructors resolve through normal constant lookup; canonical instance matching, private-member checks and final argument conversions remain in place.
