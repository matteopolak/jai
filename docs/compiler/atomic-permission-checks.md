# Nonmutating Linux atomic permission checks

The interpreter's atomic operations already use actual Rust host atomics. Their Linux permission validation nevertheless copied a byte out of the target and wrote that old byte back. That non-atomic write can overwrite a concurrent CAS or exchange update, despite the actual operation being atomic. The reported Linux contention failures therefore expose a real validation-side race, not a reason to replace atomics with cooperative scheduling or a private lock.

Linux `Probe::sys::region` now reads only its own `/proc/self/maps` permission metadata and returns the matching readable/writable range. The [Linux kernel contract](https://www.kernel.org/doc/html/latest/filesystems/proc.html) describes mapped ranges and their access permissions; `self` denotes the reading process. The new parser treats ranges as half-open, checks the requested permission, rejects malformed/overflowing metadata and ignores pathname bytes, including non-UTF8 names. No user allocation is read or written during that query. Unavailable metadata fails closed; Linux therefore requires its own procfs mapping metadata to be readable.

Natural alignment, scalar widths, memory orders, per-access read/write permission checks and actual atomic operations are unchanged. Existing fault-safe kernel-buffer transfers remain in place. Cached permissions still use the existing invalidation epoch and separate read/write caches. Native callers must retain shared storage and use compatible atomic accesses, as before. Mac/Windows permission queries and other Unix fallback code are unchanged; this checkpoint does not qualify the latter's contention behavior. The suspended invalid-pointer investigation is outside this work; no invalid-pointer or fault controls were run.

Three independent pure-metadata tests cover exact boundaries, readable versus writable/shared mappings, malformed/missing metadata, overflow and opaque path bytes. The existing four-worker CAS regression retains its 80000-update assertion. Exchange retains its original sum assertion and now additionally checks that all 80001 values (prior results plus final storage) occur exactly once, preventing duplicate/lost observations from cancelling in the sum.

The two original contention tests pass on owned, allocated AtomicU64 storage on Mac ARM64; all threads return and join. This is preservation evidence for the host's existing nonmutating query, not execution of the new Linux path. Strict Linux x64 source/Clippy checks and parser execution pass; actual Linux x64/ARM64 contention replay remains required in coordinator CI. No native Linux execution or full-matrix pass is fabricated from source checks. Native execution was serialized in the shared inbox and reaped/released in `finally`.

Exact source guards, commands and results are in the compiler T7 `mac-repairs-audit/atomic-x86-833` directory. The sealed SDK import-selection packets are unchanged. No module exceptions, unchecked access fallback, assertion weakening, external-process memory access or SDK binary execution was introduced.
