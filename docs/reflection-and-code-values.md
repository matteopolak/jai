# Reflection and code values

## What it is

The semantic compiler binds `type_of`, `size_of`, `initializer_of`, `type_info`, and captured `#code` syntax. Reflection describes the compiler's nominal `TypeId` identities and uses the explicitly selected target layout.

## How it works

`type_of` checks an expression's type without emitting its evaluation. `size_of` uses the same `LayoutEngine` as record offsets and array strides. `initializer_of` obtains declaration-site defaults, including nested record fields; it does not execute a constructor.

Annotations also retain `type_of` as typed syntax. A formal such as `code: type_of(Error.code)` reads the ready record's canonical field ID and retains the inline enum's nominal identity. Queries follow specialized record fields, lexical shadows, pointer chains, and `using` promotion without constructing a record instance or loading a field. Module annotation queries currently require declared name/member facts; operands that need semantic body inference report the missing readiness rather than execute a procedure. The ordinary expression query uses pure argument descriptions, including the declared result of `#run`, without invoking the VM.

A selected global's explicit annotation can supply its type before storage exists. That annotation resolves in the global's original defining file, with the query caller's lexical overlay disabled; it never evaluates the global initializer. Builtin type-value fallback uses a FileScope-owned absence query: only a bare, genuinely unknown name qualifies. Lexical declarations, generic type/value substitutions, and captured source values retain precedence; reserved or otherwise failed graph lookups cannot silently become builtin types.

Pure lambda preview parameters expose their checked `TypeId` directly to these queries. Forward declarations use the ready annotation preview, so a type query cannot execute a `#run` array count merely to learn another declaration's type. Ordinary declaration binding still evaluates annotations through its normal readiness path.

A query can prepare a referenced source record's real field metadata before the normal declaration pass reaches it. Both paths reuse the same source owner, nominal type, and field IDs; the later pass hydrates that metadata instead of defining the nominal again. Recursive readiness and traversal budgets still apply.

Immutable scalar expressions can combine ready reflection and source facts, such as `extra :: size_of(s32) - 2`. Their checked arithmetic uses the VM's pure constant bridge, which rejects runtime loads and implicit procedure calls before execution. Explicit constant annotations resolve in their retained lexical environment and preserve the ordinary conversion rules; narrowing a typed `int` expression to `s32` requires an explicit cast. These evaluations use the existing compile-time limits and supply no compiler effects.

`ReflectionGraph` closes a type's pointer, record, array, enum, variant, and procedure dependencies. Missing nominal definitions and missing target layouts remain explicit readiness dependencies. Descriptors retain field identities and declaration order, enum aliases, procedure context and ABI, names, and source note bytes. A note such as `@JsonIgnore` is exposed as the string `JsonIgnore`; argument spelling and spacing remain intact after the initial `@`.

`type_info` materializes checked immutable `Type_Info` records, strings, and array views. One append-only `StaticDataBuilder` publishes snapshots throughout a semantic session. Previously published objects cannot change, and every reflected `TypeId` keeps one descriptor object across queries. The VM allocates these objects in virtual memory; LLVM emits private constant globals with typed relocations. Neither representation contains a host address.

Snapshots share immutable objects through `Arc`; they do not duplicate earlier descriptor trees. Admission checks public trees iteratively before retaining them, and rejection disposes malformed deep trees iteratively. A cumulative publication-reference budget bounds snapshot overhead as well as each graph's object and node counts.

Graphs loaded without a source Preload use one lazy compiler-owned descriptor catalog. Procedure annotations and queries share its nominal IDs, and source declarations shadow its fallback names. Graphs with a source Preload require the checked source schema; they do not generate a second catalog. A concrete descriptor pointer can implicitly convert to its first `using info: Type_Info` header while preserving object identity. Universal `Any` reflects as tag 10 with a header descriptor, while its two pointer fields remain ordinary checked runtime storage.

Captured `Code` retains the original AST, source location, defining file and procedure, lexical declarations, runtime bindings, and specialization bindings. `#insert` binds that AST structurally in its captured environment. `#insert,scope()` binds in the current environment. Expression and assignment-place insertion require one quoted expression; a quoted statement or block inserts a scoped block. Source locations remain those of the quotation in both modes. Code has no runtime storage. Ordinary [Type values](type-values.md) occupy checked descriptor pointer cells, including when boxed into `Any`. Expansion depth and cycle checks bound recursive insertion.

A capture keeps its original source file instance separately from its lexical lookup file. Current-scope insertion may change lookup while retaining the original quote instance, source span, safety checks and debug policy. Replay facts encode both genuine file environments and the ordered invocation captures; transient Code handles and storage projection indices never become persistent source identity.

File-level quotations and their immutable aliases bind through the typed declaration readiness queue. The queue captures them with the same semantic Code binder used by local declarations and publishes `Binding::Code` in their defining file's environment. Quoted names remain unresolved until insertion; for example, Preload's `FIRST_ADD_CONTEXT` can name the runtime's later `Context_Base`. These bindings stay in `CodeRegistry`, outside runtime constants and the VM value codec. Ordinary deferred `#run` constants retain their checked VM evaluation path.

`#code,null` has one compiler-owned identity per semantic context and no captured body or lexical scope. It can describe a root compiler source scope in a checked compiler-call adapter. It cannot be inserted or stored as a runtime pointer. The ordinary quotation `#code null` still quotes an expression that needs a pointer type when evaluated.

A concrete module or local procedure marked `#expand` can execute in statement position. Runtime arguments acquire their formal types and are stored once in caller source order, including named arguments. `Code` arguments quote ordinary argument syntax without executing it; existing local or file-level Code bindings retain their original captures. `Type` parameters bind semantic type values, and baked scalar parameters require a checked constant after acquiring their formal type. The body emits an ordinary checked IR block in its definition environment. Local macros retain lexical declarations, nominal types, imports, and preceding runtime bindings. Their identities belong to the semantic macro registry, rather than the runtime procedure table. Generated argument stores retain caller source locations, while body and formal declarations retain definition locations, including macros defined inside inserted quotations.

Expanded `#discard` formals use pure argument checks and have no runtime operand or generated argument store. Both runtime calls and `#run` arguments are checked without execution. Discarded defaults are checked in the retained definition environment, including explicitly annotated defaults; discarded variadic inputs are checked individually or through a typed spread. A discarded formal is unreadable in the body or an inserted quotation. A new declaration may shadow that name normally.

Expanded bodies select compile-time branches before checking emitted return statements. An active return in the macro body reports a diagnostic because statement expansion has no result contract; an inserted caller quotation can return from the caller. Nested expansions and failures restore lexical frames, source origins, checks, and export overlays.

Backtick declarations in an expanded body export checked bindings to caller quotations inserted during that invocation. These bindings overlay the captured caller environment and refer to the macro's actual storage or immutable constant. On successful ordinary statement expansion, the complete export set is also published into the receiving caller block; subsequent statements can use it. Publication checks every same-block collision before adding any name. A nested caller block may shadow an outer binding normally. Custom iteration remaps protocol exports `it` and `it_index` to loop-header names and retains their invocation scope.

The registered caller-reference binder retains the invocation's caller frames before definition lookup begins. Its root lookup leaves member, index and call operands in definition scope. Production expression/place syntax is still gated on the shared compatibility checkpoint; see [caller reference syntax](caller-reference-syntax.md). Overloaded ordinary expanded calls, generic pattern formals on ordinary expanded calls, evaluated variadic packs, evaluated omitted defaults, and macro return results remain explicit unsupported boundaries.

A top-level backtick `defer` instead schedules a checked cleanup in the caller's surrounding block. It retains macro storage identities and the caller's active context; nested expansions preserve the caller lifetime, and loop and return exits use the existing cleanup machinery. See [caller defer exports](caller-defer-exports.md) for the scope restriction and regression fixtures.

Record insertion has a pure adapter for direct quoted declaration syntax. It preserves member order, source spans, initializer AST, alignment attributes, and compile-time conditional branches before field IDs are allocated. The record binder selects and checks the actual member sequence before producing layout or reflection metadata. Nested literal insertion is bounded. A quoted `using` declaration currently reports a diagnostic at its complete source wrapper because record members cannot represent its member selection; the adapter does not discard that selection or admit only its child. Runtime statements and dynamically obtained record `Code` values require further typed binding support. Record `#modify` requires mutable draft type transactions and is not implemented by changing published reflection objects.

File declaration insertion has a separate structural factory and portable capture codec. It retains original declaration subtrees and rejects runtime storage or unavailable graph capture transports before publication. Its graph transaction and source scheduling boundary are documented in [declaration insertion](declaration-insertion.md); this factory alone does not complete top-level source insertion.

The current readable descriptor subset includes headers, signedness, pointer targets, procedure argument/result types and context/ABI flags, array element/count/kind, record names and member names/types/offsets/using flags/notes, record layout/status flags and notes, enums and ordered alias values, and variants. Source Preload supplies named descriptor enum members; the compiler-owned fallback catalog supplies their exact integer ABI tags without publishing synthetic source enum members. Access to `specified_parameters`, `polymorph_source_struct`, `initializer`, or `constant_storage` reports a diagnostic because those advanced record fields are not materialized. Record descriptors with unsupported declaration members also report a diagnostic. `code_of`, generated string insertion, compiler AST mutation APIs, and runtime execution of `Code` remain explicit unsupported boundaries.

## How to change it

Builtin expression fallback lives in `type_values.rs` and uses the narrow `FileScope::type_value_name_absent` query instead of exposing scope internals. Selected-global annotation queries live in `modules/aggregates/parameterized/type_queries.rs`; preserve their definition-file resolution and pure metadata boundary. `type-value-source-scopes` tests cover builtin-spelled shadows, imported global nominal identity, and declaration-site query errors.

Extend the pure descriptor model in `jai-types/src/reflection.rs` before adding schema fields in `jai-sema/src/reflection/schema.rs` and values in `storage.rs`. Populate source facts in `jai-sema/src/modules/reflection.rs` and the local-declaration metadata adapter. Do not turn unavailable metadata into an empty value: implement it or keep an explicit diagnostic.

Annotation fact lookup lives in `modules/aggregates/types/type_queries.rs` and the parameterized record resolver, with the lexical adapter in `reflection.rs`. Add type-only facts there before broadening operands. Keep the source query's expression and span, and never fall back to executing an initializer to infer its type. The `type_of_annotations` source tests cover the File_Async-style inline enum formal, containers, promotion, shadows, and explicit unavailable facts.

Semantic constant materialization also lives in `reflection.rs`, reusing `local_typed_constant` for annotations and `evaluate_pure_constant` for checked scalar trees. Keep type checking separate from execution permission. Evaluation uses the original source override retained by inserted quotations independently of their lexical lookup scope. `semantic_constants` tests arithmetic over sizes/default fields, explicit conversion, rejection of implicit runtime calls, and exact quotation origins for arithmetic failures in both insertion modes.

Extend captured syntax handling in `jai-sema/src/metaprogram`. Preserve source AST and lexical identities when adding transformations. New static value kinds must be validated in `jai-ir`, interpreted in `jai-vm`, and emitted in `jai-codegen` before they can enter checked IR. Keep publications append-only so nested descriptor references and direct queries have identical addresses.

## Configuration

`ResolveOptions.layout` selects the target `LayoutPolicy`; its default is `None`, which cannot answer layout-dependent queries. Static data has bounded object, value-node, value-depth, and projection-depth limits. Captured insertion currently permits at most 128 active expansions and rejects cycles. The compiler driver supplies its selected target layout rather than using Rust's host `usize` layout.

Static-data admission uses the default maximums (65,536 objects, 1,048,576 nodes, depth 256). The node ceiling applies to the total of all defined objects, including unpublished work. Publications may choose stricter limits. The node limit also bounds the cumulative number of object references retained by all successful snapshots in one builder.

Annotation member paths, pointer chains, and promoted-field depth are limited to 256. Readiness preparation allows 65,536 field visits per annotation, and each selected member's promoted lookup has the same ceiling. These checks precede unbounded traversal or cloning.

Run the pure contracts with `cargo test -p jai-types -p jai-ir`. Source reflection regressions are in `jai-sema/tests/reflection.rs`; quotation and expanded-call regressions are in `tests/code_values.rs` and `tests/macros.rs`. They execute the independent VM. Native descriptor and macro coverage belongs in `jai-codegen/tests/reflection.rs` and uses only this compiler's generated LLVM.

## Dependencies

The feature depends on `jai-source` identities and spans, `jai-syntax` preserved syntax, `jai-modules` declaration scopes, `jai-types` ready type views and layout policy, and the shared `jai-ir` static object graph. `jai-vm` provides virtual storage and `jai-codegen` uses the audited `jai-llvm` constant GEP bridge for native relocations.
