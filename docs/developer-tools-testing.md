# Developer tooling contract tests

These fixtures were independently authored in this clean worktree from reviewed module specifications, NEW public producer APIs and official C/OS SDK contracts. They are not inherited replaced-stdlib tests and do not use corpus/vendor source, reference binaries, transcripts or another Jai implementation. Their presence is not evidence of full module coverage. Separate coordinator/spec-reviewer review remains pending; this document supplies the provenance and remaining gaps for that review.

## Run and dependencies

Use this checkout's source-built `target/debug/jaic`, `target/debug/jailint` and `target/jaifmt`. Build the NEW portable runtime with `python3 tools/build_portable_runtime.py`. Run `python3 tools/check_developer_tools.py` for the focused suite. It builds the owned binding/debug C helpers from source, then runs interpreter/native O0/O2 effects, generated C/C++ consumers, expected failures, actual compiler-plugin messages, formatter checks and warnings-denied lint. It leaves generated test sources and executables under this worktree's target directory.

The native runner currently executes on macOS arm64. It needs an official LLVM SDK with clang, clang++, libclang, public clang-c headers and llvm-objcopy. `DEVELOPER_TOOLS_LLVM_PREFIX` selects that SDK; the current evidence uses LLVM23.1.2. Public LIBCLANG_VERSION remains the reviewed21 constant; this does not certify execution against SDK21. The dedicated `tools/build_developer_bindings.py --llvm-prefix <sdk>` builds the private helper beside stdlib sources and creates a local symlink to the installed libclang. No SDK binary is copied or vendored. Rebuild for a different installation. Integration into shared builds is coordinator-owned.

Windows Debug checks additionally use the installed public MinGW-w64 SDK/toolchain. `DEVELOPER_TOOLS_MINGW_PREFIX` overrides the default `/opt/homebrew/opt/mingw-w64/toolchain-x86_64`. The cross-build links x64 test executables at O0/O2 and compiles an arm64 object, but executes neither. On an actual Windows machine, build the helper with `tools/build_developer_debug.py`; the original C execution fixture exercises readable/protected/freed pages, stack ownership, pipe bytes, presence, abort and unattached breakpoint behavior. Native execution and interactive console/debugger testing remain pending coordinator CI.

Linux/Windows generated binding/layout checks and WASM debugger-presence checks are compiler source checks on this host. They are not execution on those targets. The Linux-target DWARF fixture is produced by official Clang and parsed on macOS; it is not a Linux executable test.

Private MSF fixture production additionally requires official `lld-link` and `llvm-pdbutil`. `DEVELOPER_TOOLS_LLD_LINK` selects the linker; otherwise PATH supplies it. `python3 tools/check_developer_msf.py` builds original Windows x64/arm64 PDBs and exports each stream as an independent byte oracle; the focused suite then decodes them on the host. No Windows executable is run. The synthetic fixture and staged private-unit source are recreated from durable owned sources on every run.

## Changes and remaining coverage

Production regressions and test-oracle corrections are recorded separately in [deviations](status/developer-tools-deviations.md). In particular, a callback declaration-count mistake and a fix-it byte-offset mistake were corrected using the independently authored source, without changing production behavior or removing valid assertions. The reviewed CXIndexOptions refinement corrected the spec, then drove the exact implementation and replacement native tests.

The per-API [inventory](developer-tools-api.json) distinguishes pending exports, source-only native declarations and grouped actual execution evidence. Full C++/macro/bridge generation, profiler instrumentation, debugging/crash/minidump/assertion paths, debug-type parsers, Codex metadata/metrics and remaining Check routines are incomplete. [Progress](status/developer-tools-progress.md), [questions](specs/stdlib/developer-tools-questions.md) and deviations track those gaps. This worker does not migrate or delete integration-owned inherited tests; it never uses obsolete private expectations as gates for these modules.
