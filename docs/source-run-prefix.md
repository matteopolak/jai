# Retained source-run prefix

## What it is

`PreparedLibrarySession::drive_source_prefix` exposes a source-generation checkpoint before unrelated procedure bodies are checked. The workspace owner uses it to publish actual compiler input or configuration changes and rebuild the source graph without treating a semantic failure as successful source generation.

## How it works

The prefix uses the existing source-run queue, original `FileRun` references, shared auxiliary procedure allocator, checked prerequisite bodies, and VM cache. It requests procedure, constant, field-default, and alignment dependencies through the same typed channels as ordinary preparation. A reserved procedure or type ID is not an execution capability.

`SourcePrefixReadiness::Ready` means one original run completed. The owner immediately compares its actual private source and configuration journals with the baseline that produced the immutable graph. If those journals changed, it cancels and retires the semantic arena before rebuilding with the retained source/effect replay receipts. If nothing changed, it calls the prefix again on the same session. This boundary is necessary for an original second run that uses a declaration generated by the first run.

`Complete` means the original source-run queue and its alignment prerequisites completed. A workspace with no source/configuration delta proceeds to ordinary `drive` with the same semantic arenas and cache. `Pending` retains actual VM dependencies and an optional separate source preparation cause. `Failed` is a terminal error and drops the private workspace frame; source changes made before a failing producer cannot escape through that failure.

Ordinary root runs begin after actual global initializers and source parameter defaults complete. Header and initializer sweeps do not bypass that readiness merely because a Context schema exists. When an unrelated placeholder blocks initial types, the prefix may use an independently complete original Context. The early producer currently admits the genuinely empty schema only when the original graph has no context additions and no designated bootstrap additions. It calls the ordinary source Context builder and preserves that same canonical definition during later preparation. A graph containing unfinished context additions retains its original source wait.

For example, `#run add_build_string("answer :: 42;", -1); child :: () -> int { return answer; }` reaches a source checkpoint before `child` is bound. Likewise, a run generating `message :: "generated";` can be followed by an original `#run write_string(message)` against the rebuilt graph. Neither an unknown-name diagnostic nor an empty VM dependency list is used to infer source generation.

## How to change it

Keep the prefix API in `modules/prepared_session.rs` and the per-run checkpoint in `modules/compile_time.rs` synchronized with `jai-driver`'s workspace source frame. Extend typed prerequisite channels when another source job can suspend; retain its original source identity and existing execution owner.

The prefix is explicitly requested by the driver. Direct `drive` callers retain ordinary source effect ordering. Do not begin ordinary driving and then request a prefix, publish a second run before inspecting the first run's actual journal changes, or move semantic TypeIds into a replacement graph arena.

Tests must keep omitted source arguments so real default readiness is checked, and exercise generated declarations, a dependent later original run, missing type placeholders, failing and repeating producers, and cancellation before graph mutation. Pure source tests can establish checkpoint ordering but cannot establish compiler input publication or replay counts.

## Configuration

The retained phase uses the same `ResolveOptions`, target, compile-time limits, selected source receipts, and effect owner as ordinary preparation. The graph owner supplies the actual compiler input/configuration baseline; there is no source-name or diagnostic-text fallback.

## Dependencies

`jai-modules` owns immutable source graphs and source declaration identities. The semantic source worklist and `jai-vm` own checked bodies and continuations. The driver compiler session, workspace frame, and effect replay journal own source publication, rebuilds, and rollback.
