# Procedure overloads and polymorphic specialization

## What it is

Procedure names can identify immutable groups of declaration identities. `jai-sema::overloads` matches a call against each group member without evaluating source expressions; `jai-sema::polymorphism` retains structural type patterns and reserves concrete specializations by typed arguments.

Calls such as `min :: (a: $T, b: T) -> T` select a concrete signature and compile its body through the same work queue as ordinary procedures. Unused templates have no compiled procedure identity. The executable tests exercise recursion, baked values, nominal records, fixed arrays, aliases, forwarded packs, bodyless intrinsic prototypes, and ordered argument effects in the independent checked-IR VM. The independent CLI fixtures `polymorphic-call` and `overload-choice` also pass native execution with exit codes `18` and `26`.

## How it works

`jai-modules` preserves each procedure's `DeclarationId`. Local declarations and imported callable links with the same name create or reuse an immutable `OverloadSetId`. Module bindings and exported bindings merge separately, so internal calls can see module-private overloads while imports receive only exported members. Repeated imports and reexports deduplicate the original declaration identities. Values and types do not join callable groups.

The modern OpenJai `Basic/module.jai` anonymously imports `Math` and declares a logging `log`; `Math` exports its numerical `log`. This requires callable groups at the importing scope. It preserves the isolation described in tutorial `151_file_and_global_scopes`: each candidate's body and defaults resolve in its original defining file. Adding an application candidate cannot change a library body's internal overload lookup.

`jai-sema/tests/imported-callable-overloads.rs` verifies this policy through the checked VM: definition-site defaults and bodies, hermetic generic calls, private candidate filtering, reexport deduplication, and ambiguous equal candidates. `jai-codegen/tests/imported_callable_overloads.rs` checks the same definition environments through freshly generated native executables. The graph tests also cover the modern Basic/Math prototype shape and retain errors for scalar and type collisions. These independent fixtures do not claim full Basic or Math acceptance.

The template builder resolves concrete names through callbacks for the defining file. `$T` becomes an introducing `TypePattern::Infer`; later `T` occurrences become `TypePattern::Variable`. Pointers, slices, dynamic arrays, and fixed arrays retain their structure. `[$N]T` introduces an array count, while `[N]T` uses a count already supplied by a baked parameter or introducing array. A type variable has one introducing occurrence. A variable in a return type cannot acquire its type from the expected result of a call; a modifier may explicitly introduce and assign it.

`Parameter.baking` retains `ParameterBaking::None`, `Required` (`$`), or `Optional` (`$$`). `jai-syntax/src/parameter_baking.rs` preserves the source formal's name boundary and rejects extra dollar markers. An optional bake specializes a constant argument while allowing a nonconstant argument to remain a runtime formal; required baking demands a constant. The parser preserves this distinction rather than mapping both markers to a boolean. Matching, specialization keys, and runtime-slot publication must retain the selected policy. The source contract is documented in `115_auto_bakes.jai` and `550_is_constant.jai`.

`TypeSyntax::Restricted` retains the introducing variable, a nominal or interface restriction, and the exact `$T/...` source span. `jai-syntax/src/type_restrictions.rs` keeps the restriction type unresolved, stops before the next formal, and rejects executing `#run` or `#insert` markers. Tutorial `160_type_restrictions.jai` distinguishes nominal ancestry, record-template origins, and structural interfaces. Syntax regressions check these source shapes; matching and execution are validated separately by the semantic specialization tests.

The restriction matcher binds the full supplied type before proving its restriction. A nominal constraint accepts that exact type or its unique `using` ancestor; an ordinary field or `#as` conversion alone provides no ancestry proof. A bare generic record constraint compares the actual record-template declaration, so `*$T/Table` accepts an actual `*Table(int)` and retains all of its specialization metadata. Interface restrictions require each named field to have the exact canonical type, including visible promoted fields; extra fields and declaration order do not affect matching. Missing members, different types, and ambiguous promotion paths reject the candidate before argument evaluation.

`is_constant` reads checked source facts and does not execute ordinary calls or runtime operands. Optional parameters with available constants enter the baked substitution and lose their runtime slot; storage values retain that slot and one shared runtime body. Invalid constant conversions fail rather than selecting a runtime fallback. A discarded parameter stays unreadable even when its value is part of a baked key. Optional baking of an explicit `#run` or force cast constant currently reports that selected constant materialization is required; that deferred transaction phase must complete before the result can become a specialization key.

The lexer reserves `is_constant` as a keyword. Its expression adapter interns that exact source spelling and enters the existing call AST, retaining the call and argument spans. The semantic constant-query binder owns arity, source-fact evaluation, and nonexecution; the parser does not fold the query or treat arbitrary reserved words as callable names.

Explicit numeric casts preserve their canonical target and normalize the checked child facts, including float, enum, and distinct constants and bound type queries. Weak floats round directly in the declared float width. A checked cast that cannot produce a constant remains applicable as a runtime cast; requesting an optional bake of that expression requires materialization rather than selecting a runtime fallback. Nonzero native address constants retain their source recipe for ordinary arguments and cannot supply baked VM pointer provenance.

Pure cast annotations read ready canonical nominal declarations after checking lexical and source bindings. A scalar shadow of a type remains an error. This lookup does not resolve a new declaration or evaluate a type annotation's source expressions.

Nonnumeric distinct casts use ordinary coercion of the actual unwrapped representation. Exact record, fixed-array, and string constants keep their owned values when wrapped or unwrapped; runtime casts require the exact canonical storage representation. A different array extent or unrelated record does not become a valid storage cast. Exact procedure identities and empty slice constants remain checked values. Null pointer erasure preserves null while validating both pointer types. A nonempty baked slice needs a proven typed backing recipe, because its descriptor cannot be replaced by an array constant or a zero value.

Descriptions of checked concrete procedure values retain their actual reserved `ProcedureId` and canonical type as a validated `ConstantValue`. Baking a callback removes its runtime parameter slot but retains its checked source contract in a sidecar keyed by the actual specialization and original formal symbol. Both call preview and runtime invocation use that source contract for names, defaults, discarded parameters, and result obligations; the target procedure's ABI alone does not supply it. A discarded formal or nearer lexical declaration still shadows the baked binding. Extend this path through `contracts/baked_bindings.rs`, generic contract registration, and both call-description and indirect-call routing together. An inferred omitted callback default requires its original checked definition-site contract before it can be accepted.

Defaults that read a global or implicit context carry a checked definition-site `RuntimeDefaultRead` path. Generic signatures retain that recipe and validate its final type after substitution. Reading the default occurs only for an omitted argument at the eventual call, so a mutable allocator is never sampled into a baked key during candidate selection. Extend this path through `runtime_defaults.rs`, `modules/runtime_defaults.rs`, and the generic default carrier together.

Quoted string argument descriptions preserve literal origin. A literal can provide the existing NUL-terminated `*u8` backing at a literal conversion rank; a `string` parameter is still an exact match, and a stored string cannot acquire this pointer conversion. Baked string-pointer keys require a published static-data identity rather than a byte-string value disguised as a pointer.

Callback patterns such as `f: (T, T) -> $R` infer their introducing variables from an actual checked procedure signature. Parameter and result types remain invariant inside a callback: widening an ordinary scalar argument does not widen a callback parameter. Calling convention, implicit context, variadic shape, and result count must agree. Matching traverses canonical signature metadata, and selected materialization interns the complete callback type. `type_of` annotations use ready declaration and field facts, preserving definition scope and substitution rather than evaluating the queried operand.

A short lambda in a dependent callback context first receives parameter types inferred from the other arguments. Its body is described using scoped parameter type facts, then an introducing result variable is inferred from that description. A zero-result body supplies canonical `void`; a weak literal uses the language's default only when it introduces the result type. The final callback signature is checked before argument lowering, including when the callback parameter precedes the argument introducing `T`. This preview can intern a genuine signature but allocates no procedure identity and queues no lambda body. Multiple distinct result substitutions remain ambiguous.

Named short lambdas follow the same dependent matching pass. Their body preview uses the original definition file and captured static scope, so a caller's shadow of a type alias does not change inferred result types. An explicit callback annotation must agree with the inferred parameter context and final result signature.

Record application patterns such as `Box($T)` retain the original record template declaration and its ordered type/value arguments. Matching consults immutable specialization metadata rather than comparing field shapes. An omitted record argument compares against its normalized definition-scope default at the instance's preceding arguments; it never becomes an unconstrained wildcard. After selection, materialization calls the same record registry that resolves `Box(int)` elsewhere. Result applications such as `Box(T)` consequently reuse the canonical nominal instance.

Matching first binds positional and named arguments to parameters. It then visits introducing parameters in declaration order, resolves baked constants, and checks every dependent parameter and omitted default. Only the introducing occurrence chooses a type. Named arguments can therefore arrive in any permitted order without changing inference. Weak integer descriptions preserve their bounds; contextual conversion must fit the destination width. `$T` applied directly to a weak integer uses its default `s64` type. Known integers convert only when the destination contains the source type's entire range. Nested array elements and pointees keep exact identities; scalar widening is not applied through pointers or arrays.

Each viable candidate records an exact, literal-adaptation, widening, array-view, or universal-boxing rank for every explicitly supplied argument. A candidate wins only when its conversions are no worse for any argument and better for at least one. When conversions tie, a fixed signature precedes a variadic signature; this allows Basic's binary `min` and `max` to coexist with their pack forms. Other equal and incomparable matches remain ambiguous. Generic inference carries no ranking penalty: an unrestricted generic and an exact concrete overload can both match. Defaults do not decide ranking, and declaration order never breaks a tie.

Jai variadic arguments match the pack's element pattern and become a slice parameter after substitution. An explicitly named pack or `..values` forward matches a slice context. Positional scalar elements can precede one final spread; the checked binder constructs a single concatenated slice in source order. A spread closes that pack, allowing following positional arguments to bind the trailing fixed parameters. A second spread or combination with a named full-slice pack is rejected. Trailing parameters retain their names and defaults, and positional pack elements remain in source order. C variadic candidates preserve their fixed parameter count and validate extra scalar or pointer arguments before the shared ABI binder applies C promotions.

Weak float expressions retain their default width and the widths permitted by their decimal leaves. Pure baked expressions are rounded separately in each possible destination width; a default-width evaluation never makes the expression strong. A typed float operand determines the expression width. `Any` boxing ranks after typed conversions. It keeps the default width of a weak numeric argument, requires complete runtime payload storage, and rejects `Code`, `void`, and untyped null or enum metadata. First-class `Type` values have descriptor pointer storage; selected lowering proves the canonical reflection schema and represented identity before boxing them. The selected binder validates the actual target layout and creates the represented type's descriptor.

Null can match a pointer or concrete procedure context but cannot introduce a generic type or pointee; another introducing parameter must supply that type.

Contextual `xx` casts retain their operand and checked or unchecked mode until a candidate supplies the destination. They cannot introduce a type variable. Explicit cast destinations receive equal contextual ranks; a checked runtime overflow does not select a different overload. A baked cast must finish successfully before its normalized typed value enters the specialization key. Known cast domains share the actual runtime cast helper. A typed pointer may widen to `*void`; nested pointee inference stays exact.

Force casts use `StorageBitcast::prove` with the selected `LayoutPolicy` during pure candidate matching. Equal-size and prefix strengths compare actual completed storage extents before advertising a result type; a missing target policy or contextual source type is a diagnostic. This layout proof does not materialize bytes or authorize a portable pointer constant. Baked force casts require the shared target-layout VM materialization boundary and never become numeric wrapping conversions.

Leading-dot enum members retain the member symbol until a candidate supplies an enum identity. Record and array literals retain each field or element's weak type description. Pure matching validates duplicate or unknown fields, declaration defaults, fixed lengths, and every element conversion before lowering. Explicit record types preserve nominal identity; a field-compatible unrelated record does not become interchangeable. Empty arrays can introduce a fixed count when the element context is already concrete. A literal used as a baked record is normalized in declaration field order, so omitted defaults and equivalent explicit defaults reuse one specialization.

An untyped record literal in an `Any` context builds its two-pointer descriptor, using `type` and `value_pointer` field identities and zero omitted fields. Explicit ordinary record or array literals retain their represented payload type when boxed. Source `#as` conversions are queried through immutable record metadata and rank with widening conversions; field promotion through `using` does not make an implicit conversion.

`#caller_location` remains a deferred runtime default, carrying the validated source `Source_Code_Location` identity through pure matching and generic signatures. The selected call materializes the original call site's location. It cannot become a baked constant or specialization key.

Explicit `#location()`, `#file`, and `#line` arguments and generic defaults instead retain their definition's source record. The pure descriptor stores the checked location record, exact filename bytes, or typed line integer. It validates the same source identity and nominal location schema as ordinary lowering, without evaluating a source expression.

Compiler-only `#code, null` defaults carry their actual `Code` type and deferred marker. Compiler candidates use source parameter metadata, including the quoted-code parameter removed from the runtime ABI. Type-query descriptions preserve canonical reflection pointer types, and a ready `size_of` produces a typed integer constant. They do not execute their operands.

Scalar operators fold already resolved child facts through `jai-eval::binary_values`. This allows expressions such as `size_of(*int) * 2` to remain constant in overload and baked-count matching without sending type queries back through the scalar source interpreter. The shared operator binder preserves integer widths, weak literal identity, float widths, overflow policy, and the original diagnostic span.

The chosen binding plan keeps explicit arguments in source order and records each runtime parameter destination separately. Baked and `#discard` arguments have no runtime slot. Discarded arguments still participate in pure type checking, inference, and ranking. The semantic signature retains their source names and defaults, while its canonical procedure type contains only evaluated parameters. Source variadic metadata consequently remains separate from compact runtime variadic indices. Reading a discarded formal from a body is an error. Lowering evaluates each explicit runtime expression once in source order, then arranges values for the procedure ABI.

The core matcher contains no expression evaluation callback and cannot execute compile-time effects. A viable `#modify` candidate requests a checked auxiliary body before overload ranking. Its initial typed substitution keys that request; the common scheduler compiles the modifier in the defining file and executes it with `NoEffects`. Accepted type or baked-value changes are validated against the original call arguments before conversion ranks are compared. Rejected modifiers remove that candidate, and pending dependencies defer selection. The accepted final substitution determines the runtime specialization key, so different inputs modified into the same bindings share a body. Auxiliary modifier procedures are excluded from runtime publication and its debug/inline sidecars. See [specialization modifiers](specialization-modifiers.md).

Describing a nested generic call previews its substituted result types without reserving a procedure or queuing a body. An outer call that fails selection consequently cannot trigger compile-time work from speculative nested procedures. Definition-site aggregate defaults use the existing `aggregates::Defaults` evaluator and then retain its checked constant, including nominal enums and recursively typed fields.

Instance namespace members use the same source-member and own-formal allowlist as runtime lookup. Preview reads published namespace bindings or baked facts and never completes a method body or default. A method whose header is incomplete keeps its real readiness dependency. A simple local/global receiver can expose a namespace constant; a receiver such as `make().Size` remains nonconstant so optional baking preserves its evaluation. Baked record field projections validate each physical field owner before keeping their checked constant value.

`Substitution` stores type, constant, and executable callable-policy bindings in declaration order. `SpecializationKey` combines the originating `DeclarationId` and substitution. Runtime-representable constants reuse `jai-ir::ConstantValue`; integer width, enum and record nominal identity, and recursively typed fields stay in the key. Zero scalars and zero structs normalize to the same representation as their explicit constant values. Compile-time type values, IEEE float bits, and byte strings have separate immutable key representations; mutable VM pointers cannot become baked arguments.

Callable policies retain the full checked source parameters, names, defaults, evaluation policy, and source pack position, including parameters erased from the runtime ABI by `#discard`. Opposite discarded source slots require separate specialized bodies even when their canonical callback type is equal. Equal source policies share a body regardless of the target procedure's identity. Result usage obligations remain outside this key and trigger the existing same-ID body recheck. Policy collection reads checked source facts before modifier requests and after their accepted bindings, outside mutable specialization-queue borrows. Replay encodes the same policy using source symbols, structural type origins, and actual field ordinals; it never serializes opaque arena IDs or debug output for policy identity.

Callback readiness exposes a retained terminal body diagnostic by the actual procedure identity. Cached compile-time results must check that failure before treating an unchanged readiness revision as permission to reuse a result. Pending body work remains a dependency; it does not become a failure or a completed proof.

`Specializations` reserves a `ProcedureId` once and schedules signature work before body work. A recursive body call can reuse that identity once its signature is ready. Readiness distinguishes pending signatures, pending bodies, completed bodies, and failed work; repeated requests never enqueue a second body. Each entry retains the original defining file so specialization resolves names in the declaration's scope. `GenericContext` owns templates and generated signatures, while the shared body compiler drains owned requests and installs a `FileScope` substitution overlay. Compile-time readiness snapshots include newly materialized signatures after argument binding. Source `#run` cache entries include the specialized procedure identity.

Bodyless polymorphic prototypes use the same pure header matcher and procedure allocator. A selected header publishes its checked `ProcedurePrototype` directly as ready metadata, without entering the source body queue. Marked runtime intrinsics bind the explicit source tag against the concrete signature and selected target layout; foreign prototypes retain their defining library and symbol. Generated prototypes enter both the final library and compile-time readiness snapshots. Generic compiler prototypes currently require a specialization-aware compiler binding implementation.

## How to change it

Extend `overloads::TypePattern`, its introducing-variable pass, compatibility checks, and `polymorphism::materialize` together. Add syntax-to-pattern conversion in `polymorphism/template.rs`; do not rewrite source text or use generated names as semantic identity. Preserve weak literals until a candidate supplies a concrete type. If a new contextual argument form is supported, validate its complete shape during candidate matching before committing expression lowering.

The graph's merge helper accepts real procedure declarations from any linked module. Callable alias collisions remain deferred until their targets prove callable; a scalar alias never gains callable semantics from its name. Keep overload sets immutable: mutating an exported set when a private declaration joins would expose private members. Callable aliases refer to their original declarations or overload sets rather than manufacture wrapper procedures.

Use the specialization readiness query before inspecting a signature or body. Publish a signature once, process its body in the defining file with type and baked bindings installed, and mark work ready only after checked IR exists. The allocator is shared with local procedures, anonymous compile-time owners, and auxiliary modifiers. Extend structural callback patterns through `overloads/procedures.rs` and the shared materializer; keep every ABI field in both paths. Restrictions and dependent count arithmetic require their own checked implementations before participating in selection.

Collection macro formals use the same pure patterns with genuine module or local macro origins. The formal adapter retains captured definition bindings, matches the actual nominal specialization, and returns a typed substitution for expansion. Address or dereference adaptation ranks with widening, allowing an exact source protocol to precede an adapted one. Definition errors propagate; only applicability mismatches remove a protocol candidate. Keep nominal identity in this path, including a bare generic record formal that checks its template origin without constructing a new instance.

## Configuration

There are no feature flags or environment variables for overload matching. Runtime intrinsic prototypes and runtime `Type` storage in modifiers require an explicitly selected target layout through `ResolveOptions.target` or `ResolveOptions.layout`; CLI native builds supply their selected target. Modifier execution uses the configured VM limits and materialization depth. The specialization scheduler's first procedure index must follow the concrete procedures already reserved by the compilation. All type patterns and constants belong to the compilation's `TypeRegistry`; foreign type identities are rejected.

Run focused checks with `RUSTC_WRAPPER= CARGO_TARGET_DIR=target cargo test -p jai-modules --locked -j1` and the `overloads` or `polymorphism` filters on `jai-sema`. Source fixtures are independently authored; the reference tutorials and standard library are read-only semantic evidence, never executable compiler tooling.

Run the import-policy regressions with `cargo test -p jai-sema --test imported-callable-overloads --locked` and `cargo test -p jai-codegen --test imported_callable_overloads --locked`, using the repository's configured LLVM environment for native tests.

## Dependencies

The implementation uses `jai-source` for symbols and declaration identity, `jai-modules` for independent file scopes and overload groups, `jai-syntax` for unresolved signatures, `jai-types` for canonical type descriptors and integer conversion rules, `jai-eval` for pure scalar defaults, and the shared `jai-ir` for typed runtime constants and procedure identity. It adds no external dependency.

The static reference explains introducing versus dependent types in `reference/how_to/100_polymorphic_procedures.jai`, weak literals in `085_default_types_for_literals.jai`, module isolation in `151_file_and_global_scopes/151_file_and_global_scopes.jai`, and unconstrained generic ambiguity in `160_type_restrictions.jai`.
