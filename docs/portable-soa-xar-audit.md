# Soa and Xar public collection audit

Soa's five and Xar's thirteen reviewed declarations have real supported bodies and focused shared-library evidence. Their public facades omitted canonical index operators. Filtered imports now expose only Soa `[]`/`[]=` and Xar `*[]` from the existing implementations. No wrapper, type replacement or helper export was added.

Genuine lexical-import index failures are preserved in `collection-operators-red-p7_iqaph/results.json`. The Soa fixture checks generated component arrays for scalar and nested members, constant omission, canonical type name and repeated-import procedure identity, reads/writes, ordered value iteration, pointer update writeback across continue/break, zero extent and the public example. Overlay layouts are implemented by stored-member selection but are not independently exercised by this fixture.

The Xar fixture checks its canonical type and private helper exclusion, every live index/address across all four chunks, growth-stable element pointers, forward and backward iterators, ordinary/pointer iteration, unordered removal's moved value, all three sorting entry points against separately reset permutations, chunk reuse, actual captured allocator ownership, reset release and retained-allocator reuse. It uses a forwarding allocator with real allocation/free calls. Over-aligned types remain outside the reviewed alignment guarantee.

Run `tools/check_portable_soa_xar_shared.py` with worker source-built tools and `CARGO_TARGET_DIR`. Receipt `artifacts/local-verification-stdlib/cargo-target/soa-xar-shared-n2hp4by4/results.json` has 40 passing checks: six actual interpreter/native Mac ARM64 O0/O2 executions, four builds, twelve source checks, twelve complete strict production/fixture lint contexts and six format gates.

Test corrections and compiler questions are separate. A reverse-iterator draft used a descending range instead of the reviewed `<` iteration form; it now requires all 32 visits. Soa's explicit typed record assignment works, while shorthand contextual inference is preserved as a failing independent reduction. Taking `X.operator *[]` as a typed procedure value is a separate parser/spelling question; ordinary indexed storage addresses work and remain tested. Both questions are recorded in [the owned question document](specs/stdlib/portable-collection-compiler-questions.md), without a fabricated compatibility claim or library workaround.

Native other platforms, Soa overlay ABI examples, unsupported reverse loops, invalid parameters/indexes, allocation exhaustion and over-aligned Xar elements are not verified by this scope. Xar sorting uses the pre-existing heap algorithm; this is real mutation/order behavior, without a distinct quick-partition performance claim. Neither pending expression is counted as passing functionality.
