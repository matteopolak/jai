# Virtual stdio state

## What it is

`VirtualFiles` models the buffered state needed by actual source `File` wrappers calling the C stdio ABI. A file handle identifies an owned byte buffer and cursor; it never contains a native `FILE` address or loads a native library.

The ledger, C signature proof, pointer ownership ledger, source receipt binder and VM dispatch are implemented. Buffer and adapter fixture results alone do not establish unchanged `File` source execution. The separate `jai-driver` integration suite must pass before making that claim.

The required self-authored source gate passes with the actual trusted `OriginalInputPolicy` installed: NUL-terminated byte arrays reach the exact checked stdio declarations, open an explicitly granted file, seek, measure its length, and close it. The unchanged reference `File` fixture now passes the earlier `print :: print_to_builder;` callable-alias graph boundary, then stops at `Basic/Int128.jai:157`: the constant-polymorphic `operator <<` declaration is rejected as having an invalid operand signature. This occurs before the ordinary File wrappers or allocator chain execute, so full wrapper acceptance remains unverified. The unchanged fixture retains its complete read/seek/write/close, `read_entire_file` content/count checks, and ordinary source buffer free.

## How it works

One ledger belongs to one evaluation transaction. VM dispatch charges C-string scans, source/destination allocation images, transfer bytes and retained ledger work before mutation. Open responses charge their actual payload before token creation. A read into uninitialized storage marks only the bytes actually copied as initialized. Virtual handle relocations cannot be serialized to host files.

Private branch admission rejects every live stream; copying a cursor would break shared open-file behavior. The closed-ledger accounting hook charges its outer table walks before inspecting nested ledgers and reports retained empty table capacities and headers. The scheduler must admit that backing and charge its clone before taking a branch snapshot, even after all handles have been closed.

General rollback checkpoints permit live streams and copy their cursor, mode, EOF, token ownership, path backing and byte buffers together with Memory. `HostFileMachine::snapshot_bounds` charges table walks before nested metadata inspection, counts actual retained capacities rather than configured maxima, and reports a clone bound for the checkpoint owner to admit before copying. Empty tables still retain headers and buckets; an almost-empty file can retain a larger byte buffer. These bounds remain separate from the closed-only fork rule.


The latest full VM test run passed 518 tests, including both FILE fork-bound fixtures: retained empty nested-ledger backing, and charging before inspection while rejecting live streams. These results verify the private stdio ledger accounting boundary; they do not establish unchanged File wrapper execution, which remains blocked by the source declaration failure reported above.

Opening a successfully observed read file retains its bytes with a scoped, nonrecycled `VirtualFileHandle`. Writable opens retain an empty truncated buffer or an observed append buffer. `ReadFileForOpen` observes expected OS open failures as typed data so the ordinary wrapper can return false; capability, symlink and budget rejections remain fatal rather than becoming successful fallback results. The caller must validate the host path and stage writable open effects before installing the handle; `opened` grants no root access.

Reads preserve C `fread` item semantics: return the number of complete items while copying the trailing partial item bytes, advance the cursor by bytes read, and set EOF only when a read requests more than remains. A seek clears EOF. Seeking past the end does not allocate memory; a later write fills the gap with zero bytes. Append writes always use the end of the buffer, regardless of a previous seek.

Closing a writable handle sends a typed `WriteEntireFile` request to the host provider. A successful staged acknowledgement releases its buffer; pending or rejected effects keep the handle live for rollback. A read-only close releases its buffer without any host request. The ledger never publishes a file. `require_closed` detects live handles at successful transaction exit; `reset` on rollback frees every buffer and makes all previous handles invalid.

`StdioAuthority` accepts only a Rust source binder catalog of actual procedure identities and a canonical file library declaration for system `libc`. Binding rechecks exact library metadata, symbol, procedure identity and the full fixed C ABI, including its nominal `FILE` struct pointer. A matching name on another procedure or another library does not grant a capability. The embedding binder must first verify its selected POSIX stdio source and keep the authority scoped to that graph and type registry; declaration indices are not globally unique. `FileAbiBindingContext` retains the selected configured POSIX entry and target stdio source path, immutable source allocation provenance and target. The source binder verifies these receipts against the current graph, resolves its actual library and nominal `FILE`, then binds exact checked prototype identities. `ReadyProcedures` publishes only these proof-bearing adapters. `FileTokens` mints readonly, uninitialized storage of the actual `FILE` struct and maps its provenance-carrying virtual pointer to a private file handle. Lookup rejects unrelated heap storage, different memories, shifted pointers and stale tokens; equivalent provenance-preserving casts remain valid. Removing a token mints a non-cloneable `RetiredFileToken` with a private constructor. The memory lifecycle helper accepts only that retired proof for trusted storage release; ordinary source `free` sees read-only storage. VM snapshots restore allocations and both ledgers together on rollback. Successful request exits require every stream closed, so persistent open streams across compile-time requests are currently rejected. Ordinary heap pointers, integers and matching procedure names must not mint handles. The source implementation of `read_entire_file` or `write_entire_file` must execute normally through those bound foreign declarations.

## How to change it

Edit `crates/jai-vm/src/virtual_files.rs` and the tests in `virtual_files/tests.rs`. The checked declaration/signature binding lives in `file_abi.rs`, with rejection tests in `file_abi/tests.rs`. Pointer ownership lives in `file_tokens.rs`; the opaque allocation lifecycle is in `memory/host_files.rs`. Keep checked byte counts, item counts, position bounds, append behavior and EOF rules separate. Invalid counts, seeks or writes must not partially modify a buffer.

New file modes need explicit parsing and state rules. Extending this ledger does not grant another host filesystem operation: add a typed host protocol request and provider checks for that operation. Native process `fork`/`exec` and file descriptors need a separate virtual control model; they are not stdio handles and must remain unsupported until implemented.

Run `cargo test --offline -j 1 -p jai-driver --test file_abi` for source acceptance. Its unchanged reference fixture reads a byte after a seek, measures length, reads the entire file with content/count assertions, frees that buffer through ordinary source `free`, writes one output file and closes every stream under an explicit temporary root. This covers the direct allocator path in `read_entire_file` as well as the temporary C-string path used by open. That fixture emits an explicit `SKIP` when the optional private reference checkout is absent; public CI must not upload those original modules. The smaller self-authored source fixture is required and isolates exact stdio prototype binding. Neither fixture executes reference native bytes or upstream build scripts; failures before source resolution are compiler build failures rather than file adapter acceptance results.

Both fixtures authenticate `OriginalInputPolicy` against the workspace's trusted inventory manifests and apply its deny rules before registering their temporary root. This exercises production policy population in the required self-authored test as well as the optional unchanged-source test. The policy uses reviewed native-file digests from compiled receipts; it does not read, load, or execute the supplied native originals to construct the inventory policy.

## Configuration

`FileLimits` defaults to 1,024 live handles, 16 MiB of aggregate file payload, and 1 MiB per read/write transfer. Modes currently include the actual wrapper spellings `rb`, `wb+`, `a+` and their equivalent supported forms. Unknown modes are explicit errors. Source authority is supplied through `ResolveOptions.file_abi` and `FileAbiBindingContext::from_graph`; ordinary resolution has no file authority. `FileCompilerSession::with_root` supplies a canonical registered host root and working-relative path, and `CompilationUnit::resolve_with_file_session` selects source receipts from its configured import roots. Paths outside this root are rejected. Position and transfer arithmetic reject overflow before allocation or cursor movement.

## Dependencies

Rust's standard library, the typed `HostPath`/`HostEffects` protocol, validated VM memory and source foreign declaration receipts. The ledger has no OS calls, native library dependency or reference executable dependency. The signature helper uses `jai-ir` foreign metadata and `jai-types`; tests use internal `jai-source` identities to create real declaration fixtures.
