# Virtual POSIX process execution protocol

## What it is

The `jai_vm::virtual_process` module implements bounded virtual POSIX descriptor and process state, following the inspected ordinary `Process` source wrappers. Source process compatibility remains incomplete: genuine fork continuation splitting and a checked process foreign declaration adapter must be verified separately from this ledger.

The existing [host provider](compile-time-host-io.md) supports a direct typed, deferred invocation of an individually reviewed installed read-only command. That boundary does not replace `run_command`, `create_process` or any other ordinary library body.

## How it works

The supplied POSIX `create_process` wrapper calls `socketpair` and `fork`, builds pipes in the child, passes descriptors to its parent through ancillary messages, remaps output with `dup2`, and calls `execvp`. The parent receives descriptors, reads launch status, captures output and waits. A foreign-call adapter cannot return a made-up successful PID and skip this source flow.

The implemented ledger uses opaque `ProcessId` values and generation-checked, process-local `FileDescriptor` tokens. `descriptor(process, source_s32)` checks the current slot before creating a token; no slot refers to an OS descriptor. Open descriptions are shared by inherited/duplicated descriptors and descriptors held in queued `SCM_RIGHTS` messages. Closing the final writer produces EOF after buffered bytes are consumed. Socket `shutdown_write` produces directional EOF even while inherited aliases remain open. `O_NONBLOCK` is shared on the open description; `FD_CLOEXEC` belongs to a descriptor and is cleared on `dup2` and descriptor transfer.

`read` and `recv_rights` return `ProcessIo::Pending(ProcessEvent)` when blocking would be required. A nonblocking empty read returns `WouldBlock`; EOF returns an empty ready buffer. `readiness` reports queued byte count and writer closure, and `event_ready` lets a future scheduler observe progress. Ancillary data remains attached to the first stream byte, transfers into new receiver-local slots exactly once, and retains its open descriptions while queued. Unsupported rights truncation rejects without consuming bytes. Plain `read` discards ancillary rights. Resource limits bound process records, live descriptors, queued messages/rights, buffered bytes and individual transfers.

`exec` accepts an already-authorized `ProgramInvocation`, preserving its exact argv and root. It requests `HostRequest::RunProgram` and records a pending host key. `complete_exec` accepts only that key, then atomically applies an actual `ProcessOutput`: close-on-exec descriptors close, stdout/stderr bytes enter the selected virtual streams, child descriptors close, and wait state retains the actual termination. `ExecOutcome::Replaced` requires the future scheduler to discard the child source continuation. Boundary rejection leaves the child running with its status writer unchanged. A future source adapter must propagate policy/budget rejection as a boundary failure, never disguise it as C `errno`; `ProcessLaunchFailed` carries an actual positive OS launch error code and host platform. `ExecOutcome::Failed` leaves descriptors and close-on-exec flags unchanged and restores the child to running, so a checked adapter can resume source `execvp` with -1. Its `matches_platform` proof must pass before the adapter writes errno; another target must not receive a guessed error code. Virtual per-process errno storage and the actual source error branch are still required. No native errno/TLS accessor is loaded. Source `exit` keeps the low eight bits of its exit code; wait reaps once. The current host termination type does not retain a signal number, so a complete C signal wait status is unsupported. Virtual `kill` and cancellation of a running host command also need explicit driver integration.

The host runner currently accepts null stdin. Buffered virtual stdin at exec and writes into its stdin while a host request is pending reject; neither silently drops input. Captured output requires valid virtual stdout/stderr writers. Conventional slots 0, 1 and 2 are reserved for explicit stdio mappings; new pipes/sockets begin at slot 3. The embedding must explicitly model inherited stdio before supporting operations on those slots or uncaptured process output.

The private process table uses a `BTreeMap`; open descriptions and channels retain their hash maps. Retained process metadata counts entries, so a candidate fork adds exactly the parent's copied descriptor-slot count plus one process entry to the world work bound. `fork_descriptor_cells(parent)` checks the actual running parent and process limit, then returns its descriptor count without allocation, mutation or PID creation. Parent lookup is logarithmic; the count reads are constant time. The scheduler must combine this pure metadata with its trusted cached world work before copying, then admit actual candidate retention afterward. The helper does not prove the global descriptor quota: that check remains in the charged mutator, whose temporary parent-slot copy must also be covered even on quota rejection.

The ledger derives `Clone` for whole-transaction snapshots. Both fork branches must share one instance; cloning a separate ledger per branch would break IPC. `fork(parent)` only copies descriptors and returns `ForkPair`; it does not copy VM memory, source stacks, or fabricate execution of either branch. The separately developed continuation engine must retain expression/call progress, block/loop position, cleanup and context state when splitting a genuine source fork. Branch memory identities must preserve inherited pointers while isolating later writes. Ledger tests alone do not verify that engine or source fork compatibility.

The required execution protocol is:

1. A trusted source binder selects actual POSIX foreign declarations by their owning source receipt, canonical library declaration, procedure identity and complete C signature. Binding is graph-scoped. A caller's procedure name or a `#library` spelling cannot grant host authority.
2. A virtual descriptor ledger creates paired socket endpoints and shared open descriptions. Source `s32` descriptor values are only an ABI representation of ledger membership. They never refer to an OS descriptor. Typed descriptor entries distinguish sockets, pipes, buffered stdio and process streams, with explicit read/write/close rights and lifetime checks.
3. A VM `fork` operation creates two continuations of the actual checked call stack and memory state. The child receives the source fork result `0`; the parent receives a virtual process identity. This is an internal VM fork, never a native `fork`. Child memory must preserve inherited pointer provenance while separating later memory writes; shared descriptor state must retain POSIX offset and communication semantics.
4. The scheduler cooperatively executes both source continuations. A blocked receive, read, poll or wait returns a typed dependency on a virtual event, without blocking the driver thread or pretending to succeed. Socket messages preserve ancillary descriptor transfers. Closing the last writer creates real virtual EOF. Unsupported ancillary data, flags or descriptor kinds reject explicitly.
5. The child continues executing its actual source preparation until a validated `exec` call is reached. The adapter reads the real, bounded, null-terminated source argv array from VM memory and preserves every argument boundary. An installed-program catalog must resolve it to one explicitly registered `ProgramId`, its exact arguments and working root. Unknown programs do not search PATH or run a shell. Supplied binaries, linkers, libraries and objects can never be selected.
6. Only the driver readiness step outside VM execution may service this typed process request. It uses the host provider's empty environment, bounded captured output, deadline and direct-child cleanup. Arbitrary subprocess trees are outside that provider's contract. Native libraries are never loaded into the compiler process.
7. Successful `exec` replaces the virtual child continuation: code following `exec` must not run. Captured bytes and the actual typed termination result populate the process-stream and wait ledgers. A launch failure returns the appropriate virtual C error and permits the actual source child's error-report and cleanup path to run. Nonzero exits remain nonzero; output or status cannot be invented.
8. Parent source read/poll/wait operations consume these streams and states normally. Reaping transitions the virtual process from running to terminated to reaped exactly once. Closed descriptors and reaped processes cannot select another object after a retry.

Each branch needs a stable source identity and deterministic request journal position. Transient allocation, process or descriptor numbers must not become replay keys. An owned continuation parks unchanged compiler and host staging journals; the host provider retains their cursor/overlay in sealed source-bound tokens. Terminal failure or cancellation discards staging. The earlier synchronous Pending path uses whole-request rollback/retry and must not be mistaken for a fork continuation. Completion polling and exact already serviced observations prevent a resumed or retried source from starting a second real program. Divergent requests reject the retry. Failed or cancelled work must close every virtual endpoint and release retained output once its source identity is retired.

The transaction cannot roll back arbitrary externally writing programs. The provider must therefore remain restricted to exact reviewed read-only installed invocations. Packaging commands, destructive commands and custom upstream linkers are not approved by this plan. Any broader execution requires a separately reviewed isolated runner and the user's applicable execution and source-transfer authorization.

## How to change it

The module's self-authored Rust tests exercise inherited writer lifetimes, descriptor transfer after sender close, the source-equivalent socket ACK/status pipe handshake, partial output/EOF, nonzero exit/reaping, host-observation replay after snapshot rollback, launch rejection, wrong completion keys, flags, stale tokens, stdin policy, pending-request commit rejection, limits and cancellation of queued socket-reference cycles. Closing deep ancillary-reference chains uses iterative cleanup rather than recursive compiler-stack growth. These are ledger tests, not executions of Jai source wrappers. Run them with `cargo test -p jai-vm virtual_process`.

Next add self-authored Jai programs exercising the actual foreign ABI control path: fork branches, descriptor transfer, partial reads, EOF, nonzero exit, launch failure, timeout, cancellation, reaping and replay. Validate real installed benign command results against those source outcomes. Test scheduler progress and deadlock detection; ordinary unit proofs or a fake ready PID are insufficient acceptance evidence.

Keep descriptor/process control separate from `VirtualFiles`. Stdio is buffered file state; process communication needs shared open descriptions and scheduler events. Add an explicit VM fork continuation operation and transactional branch state rather than treating `fork` as an ordinary scalar effect response.

Cancellation must inspect `pending_requests()` and cancel/retire their host-provider observations separately, then call `reset()` to collect virtual resources, including possible socket-rights reference cycles. `reset` never services or cancels host work itself. Before commit, `require_quiescent(root)` checks that child processes were reaped, descriptors closed and payload released.

Before enabling an unchanged upstream `#run`, inspect every command it can reach and register only the exact permitted invocations. Do not experimentally execute an upstream build script to discover its behavior. File-source integration, process-source integration and complete project builds must retain separate acceptance records.

## Configuration

No process source capabilities are enabled by this document. `ProcessLimits` defaults to 128 process records, 4096 descriptors, 4 MiB of buffered bytes, 4096 queued messages, 4096 in-flight transferred descriptors and 1 MiB per transfer. The future embedding driver must additionally supply a verified source declaration catalog, explicit program identities, exact argv/root policies, deadlines, scheduler fuel, event progress limits and retired-source cleanup policy. Empty capabilities continue to reject foreign process work.

## Dependencies

The checked VM continuation/memory machinery, typed foreign source receipts, descriptor/process event ledgers, the driver scheduler, and the direct typed host provider. Actual ordinary source wrappers additionally depend on their source `Basic`, allocator, string-builder and time implementations. None of these dependencies authorize native loading or execution of supplied artifacts.
