# Semantic source discovery

## What it is

Source dependencies guarded by typed constants or explicit `#run` continue through the checked compiler rather than requiring the caller to supply a guessed condition. The driver retains one `jai_modules::GraphDiscovery` while semantic readiness produces immutable boolean selections.

## How it works

Computed file-level `using` selections follow the same retained discovery protocol as parameters and source conditions. The driver first asks the semantic resolver for canonical selection and mapping decisions, publishes each decision through its original `UsingRequestId`, and adds any discovered source specializations before retrying the graph. A pending selection retains its defining source diagnostic; it cannot be bypassed by an otherwise complete graph or reported as an unrelated unknown name. Pure discovery uses `NoEffects` for these requests, while build discovery retains the caller's actual compiler session and replay cache.

`discover_graph_with_session` advances unconditional source work first. When discovery reports pending conditions, `jai_sema::resolve_discovery_conditions` prepares the available declarations and uses the normal procedure readiness worklist. Its condition jobs bind the original expression in the defining file or original lexical scopes, including source parameters, record declarations, scoped imports, and runtime name shadows. A runtime initializer is never treated as a constant merely because its current value is known.

Ready decisions return before unrelated incomplete procedure bodies must pass final verification. Pending results retain the request identity, original diagnostic, and actual procedure or constant dependencies. The driver records each decision in the retained graph and advances again; selected dependencies receive canonical source identities while inactive dependencies remain undiscovered. A stalled session reports its original located diagnostic. No temporary main procedure, copied source body, or numeric type identity represents a decision.

A suspended lexical guard does not prevent discovering a later independent import. The source scanner retains the first pending diagnostic, continues independent statements, and restores temporary loop or block name frames before continuing. It still stops on invalid selected dependencies. Conditional declarations remain semantic shadows until selection supplies their actual source definitions.

The graph retains selected conditions by defining file and original source span, with `SourceConditionOrigin` distinguishing scalar graph choices from canonical typed decisions. Final semantic lowering consumes only semantic decisions without rebinding or replaying their runs. Scalar choices still pass ordinary typed binding and the purity check: short-circuit evaluation cannot hide an unknown name, mutable storage, or an implicit call. Active file guards are checked from their original `FileItem::Conditional` syntax in the readiness worklist, and their typed result must agree with the dependency selection. The workspace scheduler supplies the same compiler session and effect replay cache during discovery and final binding. A successful VM transaction commits normally; failed or cancelled executions discard their staging. A retained stallable execution keeps its checkpoint and transaction until completion or cancellation. Previously committed source transactions replay without repeating compiler mutations when another source input requires preparation again.

Generic bodies with source dependencies stay dormant until the real procedure readiness worklist reserves an actual specialization. It publishes a `SourceSpecializationKey` containing the declaring source identity, original procedure location, and named arguments in formal order. Values and types use canonical `ModuleBoundArgument` representations, so no temporary `TypeId` crosses preparation boundaries. The graph scans the original body for that key and keeps its guard choices and scoped imports separate from other substitutions. The driver probes semantic readiness after structural completion when dependency templates exist; unused generic bodies do not run assertions or discover imports.

Typed guard reconstruction selects earlier original static branches before binding their imports. If a selected dependency is not yet available, the later guard stays pending instead of falling back to a same-named file constant or namespace. Completed `#run` results include the canonical source specialization key in their cache identity: two baked substitutions at one directive cannot share a boolean result even when the temporary readiness owner is the same.

### Suspended source guards

`PreparedDiscoverySession` owns one immutable graph snapshot's actual semantic phase, type registry, places, metadata, and readiness worklist. `PreparedDiscoveryRequests` retains original condition, case, using, or declaration insertion requests. A `#run,stallable` guard can return `DiscoveryReadiness::Pending` with real compiler or host dependencies; a later `drive` resumes the same VM checkpoint without repeating earlier source instructions or beginning another transaction.

The driver exposes `PreparedGraphDiscoverySession` with the compilation's real target, import directories, workspace, limits, and effect policy. Its graph borrow prevents advancing discovery while the old checkpoint is alive. Callers keep the same effects owner between drives, explicitly cancel before abandoning pending work, and release the session before publishing completed canonical source choices or advancing the graph. Completion cancels unrelated parked tokens before releasing the old semantic arena. For example, an independent string guard can finish while another guard awaits an external workspace receipt: only the finished guard publishes a choice, and the parked transaction rolls back before its graph is advanced. A fresh graph preparation does not inherit old VM pointers or temporary type identities.

`PreparedGraphJob` owns the provider and `GraphDiscovery` inside a pinned async future, with private compiler and replay journals. A borrowed guard and its cancellation handler remain in that future across genuine pending observations. The root workspace scheduler keeps a private build frame containing its compiler session, replay cache, source rounds, and discovery or body-binding job. Successful discovery transfers its actual graph and private journals directly into `PreparedWorkspaceJob`. Pending observations and generated-input rebuilds keep the same frame; the caller receives its journal only at `SchedulerReadiness::Complete`. A caller revision change or active caller transaction cancels the frame instead of merging unrelated state. Hard failure discards every round's private inputs, outputs, and replay, then records only the actual workspace failure in the committed caller.

`PreparedWorkspaceJob` drives `SourcePrefixReadiness` before unrelated full body checks. Each `Ready` result proves one original source run completed; `Complete` proves the prefix is finished. A real source or configuration delta returns `WorkspaceJobProgress::SourceRebuild` immediately, cancels unfinished work against its actual effects owner, and starts a new graph with those private completed journals. A no-delta checkpoint continues the same prefix and arena; output alone cannot skip full checking or cause a rebuild. Source-owned replay requests retain their original source origins across this rebuild; temporary procedure and type identities do not cross arenas.

Production driver tests suspend an actual compiler message wait in a source guard, service real child source readiness, and then load only the selected file. The final resolver reuses the committed guard without repeating its messages or workspace requests and executes the selected program with result 42. An empty child keeps the same guard pending across two scheduler drives; cancellation drops its exact checkpoint and leaves the original compiler session untouched.

The synchronous `discover_graph_with_session` entry point still reports an externally stalled guard rather than retaining it across calls; it must not be treated as an asynchronous resume API. It and the discovered program/library binding adapters merge their compiler session and replay fork only after the source operation completes without a compiler error, so failed or cancelled source work cannot publish private compiler output or inputs. The semantic fixtures also exercise host observations, a live local file buffer, and rollback on cancellation. Parameter discovery currently uses its existing typed preparation path; the owned guard boundary covers conditions, cases, using requests, and declaration insertions.

`DiscoveryEffectPolicy::Disabled` executes pure checked guards with `NoEffects`, including legitimate explicit runs that need no host capability. Check commands use this policy. `CompilerSession` enables the actual session and transactional replay for native builds; the policy is explicit in `SemanticDiscoveryOptions` and final resolution helpers.


### Source preparation and declaration publication

`LibraryPending.source` carries the actual `SourcePreparationPending` cause, defining source span, and optional graph-scoped `PlaceholderId`. Its VM dependency list contains only dependencies of a genuinely retained VM checkpoint. A source marker does not fabricate a procedure, type identity, VM fuel wait, or compiler effect. When a source cause accompanies real VM dependencies, the driver retains and services that exact continuation.

`DiscoveryWorklists` records the actual available insertion, using, case, condition, and parameter producers for one immutable graph frontier. A source wait with no VM dependencies returns an owned source ticket, releases its old semantic graph borrow, and keeps the compiler and replay journal owners. Every other available producer gets a chance to publish. Publication begins another graph round and fresh semantic preparation; a round with no runnable producer or publication reports the original source diagnostic. The body-binding stage returns a typed `WorkspaceJobProgress::SourceWait` ticket when its completed graph cannot satisfy a source cause. `GraphJobProgress::SourceWait` similarly retains the exact preparation, parameter, insertion, using, case, condition, or module request identity and its rendered original diagnostic. The scheduler retains a source ticket's journals inside its private build frame only when they contain a real workspace input or configuration change for another graph round. Without that change it discards the source job's journals and reports the unresolved source diagnostic after all available producers reach a fixed point. A later failure also discards effects from earlier generated-input rounds. Hard `Failed` results discard their private journals. Neither stage exposes an indefinite wait with an empty VM dependency list.

Declaration producers return genuine captured `Code` with original source scope and source capture provenance. Before a producer's VM transaction commits, the driver's immutable graph admission callback validates the exact code by appending it into a session-preserving graph fork. The resulting `InsertionAdmission` seals the admitted code and binds its request generation and graph frontier. The semantic outcome returns one accepted insertion for that frontier. After releasing its semantic arena, the driver stages the sealed proof with `prepare_insertion_admitted`, consumes the receipt with `commit_insertion`, and advances the graph. Stale proofs, conflicting names, invalid quote provenance, and failed append cancel their receipt; failed insertion journals do not merge into the committed compiler session. A later insertion receives a fresh admission against the newly published graph.

Subscribed child work uses the same retained graph and body-binding controllers. Its private build frame is keyed by the parent's actual `CompilerJobId` and checks the exact preview revision, original source origin, and subscribed workspace identities before resuming. An empty child remains pending; a child with real VM prerequisites keeps its actual continuation across drives. A failed child discards its whole source-round frame before publishing its genuine `Failed` status and `CompilationFailed` receipt under the parent's private transaction. It emits no `Typechecked` event. Failed sibling work also prevents publishing successful events from that discarded attempt. The parent must explicitly reset or destroy a failed workspace under the existing compiler policy; otherwise the aggregate compiler error remains a failure. Successful semantic jobs emit actual source and typecheck events, while completion requires `NO_OUTPUT`, shutdown, or a real backend result.

## How to change it

`jai-driver/src/source_discovery.rs` owns synchronous continuation and diagnostic reporting. `discovery_worklists.rs` shares the typed producer round, source fixed-point diagnostics, and admitted graph publication with `graph_job/discovery.rs`. Extend that shared boundary when adding another producer so synchronous checks and retained scheduler jobs make the same decisions. `workspace_scheduler.rs` supplies the actual workspace, source overlay, bootstrap parameters, selected target, limits, and shared replay cache. Its `build_frame` module owns the private source-round transaction and cancellation; `child_jobs` drives subscribed jobs under the exact waiting parent's preview. Preserve its physical-source checks, source identities, and private frame when retrying generated inputs. Do not merge partial frame journals into the caller at a pending observation or between source rounds.

`workspace_job/source_prefix.rs` compares actual source inputs and settings only at the semantic prefix's real checkpoints. Extend this checkpoint with the semantic source-run owner when introducing a source producer; a failed diagnostic or console output is not a producer proof. `effect_replay/completed_forks.rs` adopts only an actual direct completed fork, verifies earlier source traces, and preserves the receiving frame's cache identity and parent seal. Do not replace a child frame's replay cache with an unrelated inner fork before attaching it to its waiting parent's preview.

`jai-driver/src/graph_discovery_session.rs` adapts the driver options to `jai-sema/src/modules/discovery_session.rs`. The latter retains the common prepared semantic phase and its worklist, rather than introducing another binding pipeline. Extend `PreparedDiscoveryRequests`, its outcome, `DiscoveryQuery`, and the shared producer queue together when adding another request kind. Keep the admission callback borrowed from the actual `GraphDiscovery`; replacing it with a rebuilt graph changes source identities and weakens the transaction proof. Pending checkpoints belong to their existing effects owner: cancelling or completing them must happen before a graph mutation or replacement arena.

`graph_job.rs` owns the production future and graph-advance loop. Its guard must be dropped before applying source decisions or advancing discovery, and before releasing its journals on cancellation. Keep `workspace_scheduler.rs` physical-source verification and virtual-path collision checks connected to the completed graph; the provider overlay stays owned throughout suspension. Parent cancellation must retire retained child frames by their actual job identities before releasing its own effect tickets. A prepared job attaches a weak cancellation capability to the scheduler's actual child-frame registry when servicing children; cancelling or dropping that job retires its children and descendants synchronously. The weak capability does not keep an abandoned scheduler alive.

`jai-sema/src/modules/discovery_conditions.rs` reconstructs defining environments from original syntax and evaluates guards through `Resolver::compile_time_condition`. `modules/compile_time.rs` shares readiness with ordinary compilation; its `file_conditions` helper validates only active original file guards. Discovery mode returns decisions or pending facts before freezing a library; ordinary library mode still checks every reachable body. Extend lexical context in `jai-modules/src/discovery.rs` when a new source construct needs additional defining inputs. Keep condition selections and substitution keys as immutable source identities, so no `TypeId` from one preparation crosses into another. `source_specializations.rs` encodes and decodes actual substitutions using the canonical module type materializer; preserve formal order and original procedure location when extending its supported value forms.

## Configuration

The graph target and semantic target must agree. `ResolveOptions.compile_time_limits` bounds genuine guard execution. The workspace scheduler uses its existing pass, source, workspace, and replay limits. The caller of `discover_graph_with_session` must retain the supplied compiler session and replay cache for subsequent semantic resolution.

## Dependencies

`jai-modules` retained discovery, `jai-sema` declaration preparation and typed guards, `jai-vm` transactional execution, and the driver's `CompilerSession`, `SourceOverlay`, and `ReplayEffects`. Independent source tests cover file loads, lexical imports, string comparisons, explicit runs, and original failure diagnostics. No original reference native binary, object, or library is executed or loaded.
