# Debug public runtime implementation

The final reviewed [Debug contract](specs/stdlib/modules/debug.md) is implemented. All31 assigned names are accounted for:30 have applicable public implementations, while init_crash_handler_thread is correctly absent under the supplied false constant. No function contract blocker remains. Prior Debug_Info commits are preserved. No compiler or peer Generator/model production change is involved.

`USE_GRAPHICS := true` is the sole façade parameter. Graphics-disabled instances omit interactive_assert and os_show_assert_dialog. A filtered module re-export consumes one unparameterized internal/debug-state owner: types, crash_handler, ignored_asserts and report mode have canonical identity. Public mixed-configuration tests compare storage addresses and updates; constant value aliases that would copy mutable storage are not used. No production Context additions are introduced.

`init` preserves custom callbacks and installs interactive_assert or break_assert only over the runtime default. Windows also preserves custom loggers and initializes the shared DbgHelp session. interactive_assert prints the diagnostic first, returns true when reporting is noninteractive, returns false for an ignored location, remembers Ignore, attempts attachment on Debug and exits Assert3 on Abort. Mac dialogs return Abort without displaying a native dialog, exactly as reviewed. Linux graphics instances use an actual modal X11 window with Retry/Ignore/Abort buttons and keyboard choices r/i/a; closing or an unavailable display selects Abort. The full diagnostic goes to output; the X11 choice window shows at most three100-byte legacy text rows. Windows uses a real native retry/ignore/abort MessageBox. Report mode initially remains false as an independent default; enable_signal_handler does not change it.

ignored_asserts is canonical Hash_Table storage keyed by filename contents/line/character. Internally remembered Ignore keys and backing use the constant runtime heap allocator and live for the process. If public table backing was allocated through a caller arena, internal retention migrates it to persistent backing, preserving entries; growth/migration may invalidate entry pointers like ordinary table rehashing. Copied internal filenames remain rooted in the state owner even if a caller resets the public table. Explicitly inserted external keys retain normal Hash_Table stable-key/lifetime obligations. Public table mutation and graphics assertions require caller serialization; no additional table concurrency guarantee is claimed. Internal retention allocation failures use the default fatal assertion policy so a nonfatal user callback cannot permit an invalid allocation to continue.

Unix os_attach_to_debugger returns false without launch; attach_to_debugger first detects an existing debugger. break_assert prints and returns actual attachment success. On Windows, the native implementation reads the64-bit AeDebug registry, accepts bounded terminated REG_SZ/REG_EXPAND_SZ commands, expands environment strings, and substitutes the documented first/second %ld with PID/inherited event handle. It parses placeholders as data; unknown, incomplete, third or absent placeholders make a registered command unusable and select the system vsjitdebugger fallback. Literal %% is supported. Commands are bounded to the Windows32767-character command limit. Graphics-enabled launch requests confirmation unless a valid Auto string is1; decline returns false. It uses actual CreateProcess/wait/exit status, then polls IsDebuggerPresent for up to60 seconds after a zero process status. These are real effects, with no synthetic attachment success. Registry/placeholder rules follow the official [postmortem configuration documentation](https://learn.microsoft.com/en-us/windows/win32/debug/configuring-automatic-debugging).

Windows automatic dump state defaults Mini. None suppresses automatic dumping, Mini writes MiniDumpNormal, Full adds MiniDumpWithFullMemory. Explicit write_minidump chooses from its Boolean independently and returns allocator-owned filename bytes on success, empty with diagnostics on creation/write/close/conversion failures. Names are `<executable basename>-YYYYMMDDTHHMMSSmmmZ-<pid>-<sequence>.dmp` in the working directory. CREATE_NEW prevents overwriting an existing file; a collision fails rather than inventing success. Failed partial files are removed, with removal failures diagnosed. The automatic handler publishes its latest result, including empty for a disabled/failed attempt; explicit calls leave it unchanged. The getter returns borrowed immutable module-owned filename bytes, initially empty. Earlier automatic bytes remain alive until process exit, a stronger independent lifetime policy than the reviewed replaceable-storage permission, not a deep-copy ownership claim. Non-Windows dump calls/getters return empty and create no core/minidump, as explicitly reviewed; the setter has no Unix dump facility to configure.

All Windows DbgHelp operations share the existing SRW lock and one initialized symbol session, cleaned up at normal exit. Automatic crash-time dumping uses TryAcquireSRWLockExclusive: if DbgHelp is busy, the write fails diagnostically and latest becomes empty rather than deadlocking on a lock held by the faulting thread. With the reviewed false constant, no separate crash thread is promised or exported. The alternate conditional declaration has the explicitly reviewed no-effect body. Calling MiniDumpWriteDump inside an unstable process remains best effort, consistent with the official [MiniDumpWriteDump requirements](https://learn.microsoft.com/en-us/windows/win32/api/minidumpapiset/nf-minidumpapiset-minidumpwritedump); no universal successful crash recovery is claimed.

Native handler transitions remain serialized. Immutable owned context-byte snapshots are atomically published, with verified lock-free reader counting protecting retired snapshots. Fatal delivery takes no lifecycle lock and does not allocate on Unix. Jai copies bytes into target-aligned local #Context storage before push_context. Snapshot pointer fields (allocator_data, logger_data, temporary_storage, stack_trace) still borrow pointees; those services must remain valid while handling/callbacks use them. Configure crash_handler before enabling and use operations suitable for the fault context. The default fatal trace contains the actual fault PC, not a fabricated full unwind, and returns terminate Exception4. Windows exceptions may allocate for the explicitly required best-effort dump.

break_once retains its independent documented policy: one actual attempt per exact filename/line/character, including consuming an unattached attempt; return actual breakpoint success. The native synchronized set owns filename bytes until process exit and diagnoses retention failures. Original Mac ptrace tests count actual traps and now verify attachment success in a traced child. No reference-equivalence claim is made for unspecified retry policy.

[The combined runner](../tools/check_developer_debug_public.py) executes actual Mac interpreter/native O0/O2 public contracts, original SDK tracing/lifecycle/ownership/concurrency/fatal tests, format/strict lint, Windows SDK x64 DLL/executable O0/O2 and arm64 object checks, and the preserved20-fixture Debug_Info SDK/public parser suite. Mac arena tests first failed against the unsafe retention path, then overwrite/reset the temporary arena and verify retained public suppression. Foreign-thread/fatal callbacks run native only. Bounded AeDebug command tests run Mac C O0/O2; they do not count as Windows launch execution.

Windows native-ready C fixtures check real dump headers/flags, explicit-versus-automatic latest state, and real native dialog choices via SDK window messages. Public Jai fixtures check canonical configurations and both dump overloads. These fixtures are cross-built, not executed on Mac. Linux X11 is type/lint checked without Linux execution. WASM detection type-checking is supported; Android is not a compiler CLI target and has source-only reviewed detection behavior. Exact verification boundaries are in [the scope inventory](status/implementation-remaining.json). No original source, reference binary, other checkout or external build cache is used.
