# Debug public runtime implementation

Debug ownership moved to the isolated Debug_Info worker after the parser scope completed. The reviewed shared clean candidate `7467b49d` supplies the current assertion/lifecycle contract. Debug_Info commits remain intact. No compiler, Generator/context architecture or peer production file is modified for this batch.

`break_once` now makes one actual breakpoint attempt per filename bytes, line and character. The first attempt consumes that location even with no attached debugger; subsequent calls return false. The returned Boolean describes actual breakpoint success. This is an independent policy where the reviewed signature supplies no detailed behavior, not a reference-equivalence claim. The native helper copies filename bytes and owns its mutex-protected location set until process exit. A failed allocation/lock reports a diagnostic through the Jai façade; allocation failure does not consume a location. No borrowed mutable caller filename is retained.

`tools/check_developer_debug_once.py` runs an original macOS SDK `ptrace(PT_TRACE_ME)` child driver. It counts actual SIGTRAP stops: one exec trap and exactly three first-location breakpoint traps, including a mutable filename ownership regression. Each public fixture runs both traced and untraced in the interpreter and native O0/O2. Strict C warnings, Jai formatting and warnings-as-errors lint are included. These results establish Mac behavior only. The shared Windows implementation is SDK cross-compiled separately and still requires native Windows execution; Linux requires its native host evidence too.

The existing backtrace/output/probe and signal/assertion lifecycle workflows retain their real native implementations. Exact platform/contract gaps are in [the question ledger](specs/questions/debug-impl.md) and [the assigned inventory](status/implementation-remaining.json). No unsupported-target empty success API is introduced.

The next batch loads the lifecycle façade on Windows as well as Unix. Windows `init` preserves custom assertion/logger callbacks, initializes one process-owned DbgHelp session shared with symbol capture, and installs `os_logger` only over the default runtime logger. The session and all symbol calls share one SRW lock and clean up at normal process exit. This follows the official [SymInitializeW lifecycle and threading requirements](https://learn.microsoft.com/en-us/windows/win32/api/dbghelp/nf-dbghelp-syminitializew). Native handler enable/disable save and restore the prior exception filter; a null prior filter is valid, as documented for [SetUnhandledExceptionFilter](https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-setunhandledexceptionfilter). An unhandled exception supplies the real fault address to the crash callback and terminates with Exception4, matching the independent existing Unix fault policy. This is a one-frame fault trace, not a claim to safely unwind a damaged stack.

The Windows logger preserves message bytes on the native diagnostic sink; metadata and user data do not decorate the text. Sink failure reports through the default runtime logger directly, avoiding recursion through the installed logger. This is an independent formatting policy. Original SDK C fixtures cover filter restoration/idempotence, concurrent enable/disable, original callback delivery, symbols, readable memory and output. A public Jai fixture checks custom/default callback ownership. SDK x64 DLL/executable O0/O2 builds, arm64 object compilation, both Jai target checks, format and strict lint pass; execution of these Windows fixtures is explicitly pending.

Lifecycle review also removed the former mutable Jai `handlers_installed` and `saved_context` globals. Both native platforms serialize the whole transition and copy context bytes into an immutable, atomically published native snapshot. Lock-free reader counting protects retired snapshots from concurrent reclamation. Crash delivery does not allocate or take the lifecycle lock. Jai restores the bytes into a target-aligned local `#Context`, preserving target-derived layout without assuming native malloc alignment is sufficient for arbitrary context fields. **The bytes are owned; pointer fields such as allocator_data, logger_data, temporary_storage and stack_trace still borrow their pointees.** Callers must keep those services alive while handling is enabled and while a callback may be in flight; configure the public crash_handler before enabling, and ensure the callback's operations are appropriate in a fault context. No whole-context deep-copy claim is made.

Original Mac SDK pthread tests run eight threads with distinct contexts through200 enable/disable cycles each, then deliver an actual trap and validate the retained context after its source bytes change. A separate native snapshot oracle first failed against the old handoff, then validates copied bytes after overwriting its input. These fatal callbacks execute native O0/O2; interpreter callbacks are not run asynchronously across foreign threads. Existing nonfatal public lifecycle tests continue to run interpreter/native O0/O2.

The public `ignored_asserts` is real canonical Hash_Table storage. Its key identity uses filename contents, line and character, with file-private independent hash/equality helpers; it does not replace the canonical table with another representation. Like ordinary Hash_Table keys, explicitly inserted filenames must remain stable while stored. Public table insertion/replacement/lookup behavior runs in Mac interpreter/native O0/O2. Graphics procedures still await the exact reviewed module parameter shape; no parameter default or extra Context field is guessed.

Additional Linux x64/arm64 public lifecycle and Windows x64/arm64 public table checks pass; WASM debugger-detection type-checking passes. Android's reviewed false-result branch remains source-defined, but this compiler's CLI rejects Android as a target, so no Android compilation or execution evidence is claimed. This is a compiler target-availability dependency, not a reason to relax its checks.
