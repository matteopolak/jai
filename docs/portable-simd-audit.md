# SIMD public value API audit

All 35 reviewed declarations have real scalar fallback bodies. The two scalar overloads of `-` and `/` retain a precise contract question for reversed scalar-left expressions; no missing lane implementation is substituted for that question.

The independent `simd-contracts.jai` lexically imports the public operator set and exercises ten primitive lane types. It covers vector/vector and vector/scalar arithmetic, symmetric commutative forms, all six comparison operations with 1/0 lane values, both min/max forms, horizontal scalar and interleaved sums, canonical layouts, 128-bit union overlay, contiguous unaligned byte copying with guards, signed byte-offset gathers, repeated gather/scatter locations, looping indices and the 64-lane signed mask boundary. No hardware instruction or acceleration claim is made.

The reviewed page identifies unusable scatter values and incomplete full-width horizontal output in its reference behavioral evidence. Current independent code implements the explicitly documented intended mapping and ordering. These are intentional defined behaviors; no exact output parity with uninitialized/unwritten reference results is claimed. That distinction remains visible rather than relabeling undefined data as verified compatibility.

Run `tools/check_portable_simd_shared.py` with worker source-built tools and explicit assigned T7 `CARGO_TARGET_DIR`. Receipt `simd-shared-v4ofm5jz/results.json` is under the worker's migrated T7 target and contains 21 passing checks: three actual interpreter/native Mac ARM64 O0/O2 executions, two builds, six source checks, six complete strict production/fixture lint contexts and four format gates.

The older `simd.jai` fixture lacked a lexical SIMD import and failed operator lookup under the tightened compiler. Integration added only `using V;`, preserving all original arithmetic/memory assertions. The actual original fixture now passes interpreter/native O0/O2, format and strict lint; see shared-portable-premises.json. No source/module exception was added. A new fixture draft used an unsupported statement-level `#no_aoc`; the scalar wrapping control now uses the ordinary procedure attribute required by the public arithmetic contract. This is a test syntax correction, not a production repair.

Native other platforms, unknown scalar-left noncommutative semantics, floating NaN/Inf edges, invalid pointers/counts/offsets and oversized masks are outside this evidence. The [question document](specs/stdlib/portable-simd-questions.md) preserves the unresolved public expressions. Existing SIMD production sources were not modified.
