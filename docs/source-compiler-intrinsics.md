# Source Compiler intrinsics

## What it is

Source `#compiler` declarations bind to typed Rust VM intrinsics. The binding checks the declaration annotation, selected module identity, calling convention, context, and complete supported signature before registering its `ProcedureId`; an ordinary procedure with the same name keeps its ordinary body.

## How it works

`CompilerBindingContext` carries the driver's current workspace and the application, Compiler, Preload, and Runtime_Support module identities for one `ModuleGraph`. `CompilerModuleOrigins::from_graph` matches the loader's selected canonical source entries against configured import directories. Automatic Preload and Runtime_Support identities come from the graph loader’s explicit bootstrap markers, including virtual sources. A module merely named `Compiler` outside configured directories gains no authority. Explicit `#compiler` declarations in the application are language bindings and still require the catalog's checked signature.

The declaration's optional `#compiler "name"` tag selects its catalog entry. Otherwise its declared name selects it. This text is parsed once at the binding boundary; VM calls use `CompilerIntrinsic` variants and never resolve names. The source adapter preserves `add_build_string(data, workspace)` and `add_build_file(filename, workspace)` argument order, converts source `s64` workspace values to opaque VM workspace identities, and maps `-1` to the driver's current workspace. It rejects zero and other negative identities. Creating a workspace returns source `s64`, while internal compiler requests retain nonzero `WorkspaceId` values.

Ordinary checked parameter defaults still apply. For example, the inferred `name := ""` constructor header resolves to the source string type before catalog signature validation.

The current supported declaration subset is:

| Source declaration | Behavior |
| --- | --- |
| `compiler_set_workspace_status :: (status: Workspace_Status, w: s64 = -1) #compiler;` | Applies OK or FAILED to the selected workspace, including recovery from a continuable report. |
| `compiler_create_workspace :: (name: string) -> s64 #compiler;` | Stages a new workspace and returns its identity. |
| `compiler_destroy_workspace :: (w: s64) #compiler;` | Atomically retires a root or child workspace and invalidates its handle. |
| `get_current_workspace :: () -> s64 #compiler;` | Returns the workspace injected by the driver. |
| `compiler_get_version_info :: (version_info_return: *Version_Info) -> string #compiler;` | Returns this Rust implementation’s version and writes checked s32 major/minor/micro fields for a non-null pointer. |
| `get_runtime_info :: (w: s64 = -1) -> Runtime_Info #compiler;` | Reads a certified current-workspace descriptor snapshot through metered immutable VM storage. The source catalog verifies the adopted `Type_Info` and global-data schemas; semantic snapshot provision and native external-data publication remain separate boundaries. |
| `get_name :: (w: s64 = -1) -> string #compiler;` | Reads the selected workspace’s real name, including a name staged by the current recipe. |
| `add_build_string :: (data: string, w: s64) #compiler;` | Stages generated source for graph scheduling. |
| `add_build_file :: (filename: string, w: s64) #compiler;` | Stages a source file for graph scheduling. |
| `compiler_report :: (message: string) #compiler;` | Reports an error and aborts the compile-time transaction. |
| `add_build_string :: (data: string, w: s64, code := #code,null, loc := #caller_location) #compiler;` | Validates null Code as root scope and preserves the source location with generated source. |
| `add_build_file :: (filename: string, w: s64, loc: Source_Code_Location) #compiler;` | Preserves the source location with the staged file request. |
| `compiler_report :: (message: string, loc: Source_Code_Location, mode: Report) #compiler;` | Preserves the source location and applies ERROR, ERROR_CONTINUABLE, WARNING, or INFO semantics. |
| `set_build_options :: (options: Build_Options, w: s64 = -1, loc := #caller_location) #compiler;` | Projects supported fields into typed options and retains the actual call location; the reduced two-argument form also works. |
| `get_build_options :: (w: s64 = -1) -> Build_Options #compiler;` | Reads transaction-visible settings into the same selected nominal record schema. |
| `write_string :: (s: string, to_standard_error := false) #no_context #compiler;` | Stages the exact bytes for standard output or standard error. |
| `write_strings :: (strings: ..string, to_standard_error := false) #no_context #compiler;` | Reads the checked VM string slice and stages its concatenated bytes. |
| `compile_time_debug_break :: () #no_context #compiler;` | Traps compile-time execution explicitly; it does not claim to attach a debugger. |
| `compiler_begin_intercept :: (w: s64, flags: Intercept_Flags = 0) #compiler;` | Sends a typed subscription request with exact source flags; the supported host subset requires SKIP_ALL. |
| `compiler_end_intercept :: (w: s64) #compiler;` | Ends the selected workspace subscription. |
| `compiler_wait_for_message :: () -> *Message #compiler;` | Reconstructs an actual owned event as a fresh checked source record; an empty queue is Pending. |

The supported Build_Options schema contains `output_path: string`, `output_type`, `runtime_support_definitions`, `backtrace_on_crash`, and/or `llvm_options: Llvm_Options`. These fields may also occur under `Commonly_Propagated`, with LLVM fields one level deeper. Named source enums and inline enums are validated against their exact `u8` values. Output kinds retain NO_OUTPUT, EXECUTABLE, DYNAMIC_LIBRARY, STATIC_LIBRARY, and OBJECT_FILE; runtime modes retain AUTO, ENTRY_POINT_AND_INIT, ONLY_INIT, and OMIT. Backtrace policy retains OFF and ON. The driver computes each workspace’s bootstrap parameters from its committed settings; native artifact support remains the backend’s responsibility. Supported LLVM fields are `target_system_triple: string`, `bitcode_optimization_setting: Llvm_Bitcode_Optimization_Setting`, and `machine_code_optimization_setting: Llvm_Machine_Code_Optimization_Setting`. The binder validates both enum names and their source `u8` member values. Every optimization level remains distinct in the driver. Empty output-path and target strings preserve the existing defaults. Additional fields are rejected instead of being ignored. Each committed located setting retains its latest `SourceLocation`, accessible through `BuildWorkspace::option_origin(BuildSetting)`. Rollback discards these origins; a later unlocated setting clears its prior origin. Location retention does not imply unsupported relative import-path options are applied. Reading settings returns the exact declared record and enum identities; a host path that cannot be represented as UTF-8 source text produces an explicit diagnostic.

`Source_Code_Location` must have the `fully_pathed_filename`, `line_number`, and `character_number` field order and types. Its structural validation shares the [caller location](caller-locations.md) implementation, while compiler binding additionally verifies its selected source origin. Omitted `#caller_location` defaults materialize the real call site and require an explicit target layout. `Report` must use the source values ERROR=0, ERROR_CONTINUABLE=1, WARNING=2, INFO=3. ERROR aborts the VM transaction, and the host also rejects a fatal report’s commit before publishing earlier staged changes. ERROR_CONTINUABLE returns control while recording a compiler error for the driver. WARNING and INFO commit only when the whole transaction succeeds.

The full `add_build_string` source signature retains four source parameters in semantic metadata. Its compile-only Code slot never becomes a runtime value: the call binder checks the actual Code identity in source argument order, accepts only a null scope, and lowers the other three arguments to a verified VM signature. Captured scopes fail before staging source because insertion into those file/procedure scopes is not implemented. Source declarations and runtime ABI descriptors therefore remain distinct without weakening runtime storage verification.

`Workspace_Status` uses the source `u8` values OK=0 and FAILED=1. A committed FAILED status records a workspace failure; OK clears only that workspace’s retained failure. Reports belong to the trusted source origin’s workspace, and failure recovery preserves the report in the message queue. The scheduler checks remaining failed workspaces after all recipes reach a stable input/settings snapshot, allowing a child’s recipe to recover its status. Fatal ERROR still aborts immediately. Independent source/IR validation diagnostics still prevent checked library publication.

Workspace destruction uses the same atomic transaction. Both roots and children can retire, and creating then destroying a workspace in one recipe is supported. Further requests targeting its handle reject the transaction, including reads and repeated destruction. Rollback restores existing workspaces; committed identities are never reused. Retiring the currently executing workspace does not abort its recipe: requests targeting surviving children, workspace creation, and session console output may continue. Reports remain observable in the session queue, while a retired workspace no longer contributes a final failed status. Fatal reports still roll everything back. Future transactions require a surviving source origin. The [workspace lifecycle](workspace-lifecycle.md) document explains the supported policy where the source declaration does not specify behavior.

Console output follows the same transaction boundary. The host queues owned bytes with a typed stream identifier; rollback discards them, and source-origin replay avoids printing them again after graph rebuild. `write_strings` traverses actual checked slice storage, materializes string views, and applies VM fuel and allocation bounds before sending one request. Descriptor reads charge their metadata and any cold backing conversion before loading or copying the selected string.

Nonempty output slices also prepare their enclosing and selected target layouts within the remaining fuel before validation or descriptor reads. Empty slices do not inspect pointee layouts merely to transfer zero strings.

These are independently authored reduced source declarations, not a claim that the entire supplied Compiler module compiles. Its captured non-null `Code` scopes, complete Build_Options schema, AST/performance interception exports, and other catalog entries remain unsupported and produce diagnostics. No ignored suffix, empty successful response, or fabricated procedure body substitutes for those features. A marked procedure with a runtime fallback body retains that checked body; compile-time execution uses the catalog binding. The [message interception](compiler-message-interception.md) document explains the phase/completion subset and its host scheduling boundary.

Catalog validation includes source parameter evaluation policy. A `#discard` formal cannot disappear from the runtime signature and accidentally turn a different source declaration into a recognized compiler binding.

Private reflection adapters stage exact `get_type` and `compiler_set_type_info_flags` signature checks. The inverse Type lookup requires the adopted nominal header and an actual registered descriptor receipt; plausible header bytes are insufficient. The setter requires canonical `Type` plus the selected source `Type_Info_Flags` u32 enum with values 1, 2, and 4. Its source journal keeps arena-local type identities outside driver replay and retains one staged transaction per actual run. Accepted writes feed a typed immutable read overlay with an exact journal owner and revision. Subsequent reads in that run observe those writes while canonical policy publication remains atomic. RuntimeInfo retains the overlay revision reached by its request, and its descriptors use isolated cache state. A direct type-info expression prebound to a static descriptor still needs a reached execution adapter to honor this ordering. Full source activation also needs a compiler-only static Type operand and a publication handoff that releases the VM's shared type borrow before preparing the exclusive policy commit. These private adapters are not entries in the active supported subset yet.

The private RuntimeInfo service issues a demand token only after execution reaches the API. It retains the actual schema, workspace, target, source frontier, and first-observed record policies through definition waiting. A catalog-bound native fallback without a selected layout retains a checked pending role at library finish; native code generation reports that layout dependency only when the role is reached. Neither pending state substitutes an empty table or a null native publication. The VM provider and source-finish attachment still require coordinated activation.

Source-slot overload candidates retain their caller's genuine declaration or local procedure identity. The generic candidate helper changes only that identity carrier; Code slots, defaults, and parameter evaluation metadata remain the same.

## How to change it

Compile-only Code signature metadata and source argument mapping live in `compiler_intrinsics/code_arguments.rs`. Extend `SourceIntrinsic` and signature dispatch in `jai-sema/src/modules/compiler_intrinsics.rs`. Nominal field and enum checks live in its `compiler_intrinsics/schema.rs` child and `schema/build_options.rs`; integration tests live in `compiler_intrinsics/tests.rs`. Add the typed source adapter in `jai-vm/src/effects/source.rs`; options projection and materialization live in `effects/source_options.rs`. Verify the real source field order and signed representation before mapping to internal requests. Add any additional nominal field metadata at binding time rather than searching field names during execution. Preserve unsupported diagnostics until the driver genuinely handles the typed request and transaction rollback.

## Configuration

The driver's configured import directories determine selected Compiler/Preload origins. `CompilerBindingContext::current_workspace` controls the source `-1` sentinel. The VM's normal fuel, stack, allocation, and evaluation-depth limits still apply. Bootstrap options select automatic source modules; `BuildSettings::runtime_support_parameters()` derives runtime flags from each workspace’s output and runtime mode. No environment variable enables reference native execution.

## Dependencies

The binder uses `jai-modules` declaration and module identities, `jai-syntax` compiler annotation metadata, `jai-types` checked signatures, and `jai-vm` typed adapters. `jai-driver::CompilerSession` owns the transactions; [WorkspaceScheduler](workspace-scheduler.md) rebuilds and checks actual graphs from committed inputs. The static `reference/modules/Compiler/Compiler.jai` and Preload sources inform ABI inspection only; no supplied executable or native object is loaded.
