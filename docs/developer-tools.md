# Developer tooling

Implementation follows the reviewed public contracts, with canonical records in public modules and private mechanisms under `stdlib/internal/developer-tools`. [Progress](status/developer-tools-progress.md), [deviations](status/developer-tools-deviations.md), [plan](plans/developer-tools.md) and [contract questions](specs/stdlib/developer-tools-questions.md) describe scope and incomplete paths.

## Generate_C_Header

`Header_Info` retains every reviewed public field and zero/default initialization. Populate `exported_types` with reflected types and their C names, or feed `handle_message` compiler TYPECHECKED messages containing PROGRAM_EXPORT declarations. `generate_header` gathers dependencies, forwards struct/union tags, orders by-value definitions, emits C declarators and checks errors before writing. It excludes `main`.

The supported projection includes scalar types, fixed arrays, recursive pointers, ordinary structs/unions, variants, C-call procedures and runtime support records discovered through Header_Info. Enum output defaults to normal C enums; enum_internal_types selects C23 fixed-underlying syntax. Enum member prefixes use uppercase letters from the emitted type name, and type clashes receive numeric suffixes. Procedure values become void pointers. Every record includes C/C++ static assertions for reflected runtime size, alignment and field offsets; compiling the generated header is required validation. Non-C-call procedures, polymorphic structs and imported/constant/void fields are omitted as reviewed. Other unsupported ABI categories produce errors.

Original tests generate headers from real type descriptors, compile C11/C23/C++17 consumers, and call native helpers through Jai FFI. Tests cover field mutation, enum modes, opaque callbacks, support layouts, collision suffixes, non-C-call omission and multiple-return rejection preserving existing output. Support-layout fixtures use test-only records following reviewed bootstrap shapes, not duplicate production prelude definitions. `python3 tools/check_developer_tools.py` runs interpreter/native O0/O2, formatting/lint and target checks using this worktree's source-built tools. Host dylib construction currently targets macOS; Linux runner adaptation is unfinished.

The module is a supported subset. See deviations for production support-descriptor availability, reserved names, explicit alignment/packing and transactional output limits.

## Performance_Report

`+Performance_Report` requests compiler timing, bytecode counters, run-directive records and polymorph records. It buffers a textual summary, sorts run records by elapsed time, and writes on plugin finish. Counters and durations come from Compiler messages. A missing message produces a compiler warning; missing per-category flags are explicitly identified in the summary. Shutdown frees owned state. There are no public configuration options in the reviewed contract.

## Bindings_Generator and staged C parser

`tools/check_developer_bindings.py` builds an independently authored private C generator against the installed official libclang C API. It parses original C headers, emits real Jai bindings with layout assertions, compiles the original native implementation, and exercises generated bindings in interpreter/native O0/O2. Malformed headers and unsupported constructs fail with source diagnostics while preserving existing output. The two-target test verifies LP64/LLP64 C `long` differences and checks generated declarations under matching Jai targets.

The public facade retains reviewed option/model shapes and defaults, exact compatibility arrays, target parameter and literal conversion rules. Both generate_bindings overloads validate a supported one-header/one-library configuration and invoke the source-built backend. It discovers official Clang include paths, unwraps reviewed typedefs, preserves named C parameters/documentation, supports common enum prefixes/aliases and outputs real callable bindings. Malformed input and unsupported options fail with diagnostics and preserve existing output. Returned builders are caller-owned.

Standalone declaration visitors and enum/argument/return-type mutation helpers operate on caller-supplied public model records. Traversal snapshots child pointers, visits shared declaration pointers once and preserves stored parent links. Generation also materializes a C model for both visitor forms and the custom argument-printing hook. Callbacks can rename declarations/parameters, change types and omit output. Generated references follow record names and foreign functions retain original native symbols. Original fixtures rename a record, function and parameter, compile the result and execute C callbacks. Invalid callback output fails and preserves the destination. During generation, parsed nodes/strings/arrays are borrowed until return: do not free or retain them. Caller-created replacement CType records remain caller-owned. Empty include guards and reviewed ignored macros are handled.

Model equivalence helpers support the clarified finite scalar/alias/pointer/reference/nominal/function cases and non-raw literal values. Distinct nonliteral expressions remain unequal; signed/unsigned categories stay distinct, signed zeros compare equal, distinct NaNs compare unequal, strings compare bytes and nominal declarations retain identity. Source spelling/location does not affect these comparisons. Raw-token payload mapping and remaining type edges are tracked in question10 and diagnosed explicitly; comparison does not silently invent structural cyclic-graph semantics.

Object-like numeric macros are evaluated by official Clang using an independently generated unsaved C probe. Output preserves native integer signedness/width and floating type, including arithmetic expressions and target-specific sizeof. No macro expression is executed. The public callback model exposes evaluated Literal nodes and respects renamed names and DISCARD decisions. Macro-to-enum callbacks can create or extend named enum groups when native integer widths/signedness match; incompatible groups fail and preserve the destination. Grouping precedes prefix processing and declaration visitors in the current supported path. Function-like, string and nonfinite macros fail explicitly. Evaluation currently reparses the header for each numeric macro, a documented performance limitation.

Run `python3 tools/build_developer_bindings.py --llvm-prefix <official-sdk>` to build the helper beside its private stdlib sources, configure its include-probe compiler and link the native API to the installed SDK through a private symlink. The helper, compiler-path file and symlink must be rebuilt for the destination SDK; shared build integration remains coordinator-owned. Configured-SDK tests inspect production helper/native links and runtime search paths, record actual compiler invocation and execute generated bindings. The [official libclang C API documentation](https://clang.llvm.org/doxygen/group__CINDEX.html) and installed public headers are the only native parser compatibility inputs. The [SDK evidence](native/developer-tools-clang-evidence.json) identifies them. Verification uses libclang23 against the reviewed version21 constant. Callback generation currently parses twice; broader C++ bridges, preprocessing models and remaining helpers remain unfinished.

`generate_bridge` writes a supported global C++17 adapter subset. The caller supplies declarations through options.header and compiles/links the output. Scalar/pointer functions use C linkage, POD aggregate returns use a leading out pointer, and lvalue reference arguments/results become pointers. Adapters live in an independently chosen private C++ namespace so unmangled C symbols can coexist with original global C++ names. Original C++ implementations execute through interpreter/native O0/O2 consumers after generation; C++ O0/O2 builds are checked separately. Deprecated, hidden, method, namespace and unsupported declarator/variadic forms are omitted; colliding output names fail and preserve the destination. Scope paths and printf adapters remain unfinished; customized global mappings are described below.

For supported global C++ signatures, generate_bindings emits Jai foreign declarations matching those C symbols. Generated POD records retain native size/alignment/field-offset assertions; aggregate results expose the leading out pointer, and lvalue references expose pointers. The public workflow generates both outputs, compiles original implementations and imports generated Jai declarations. It executes 8/16/24-byte aggregate arguments/results, zero-argument returns, mutable/const reference storage identity and an out-parameter name collision. Non-POD records fail with diagnostics while preserving the destination. Native long calls cover values above32 bits; Linux/Windows generated declarations separately check LP64/LLP64 widths. C++ parsing is selected through extra_clang_arguments. Recognized native linkage forms follow the [Itanium external-name ABI](https://itanium-cxx-abi.github.io/cxx-abi/abi.html#mangling-structure) and [Microsoft decorated-name documentation](https://learn.microsoft.com/en-us/cpp/build/reference/decorated-names); native mangled names are not constructed.

Repeated prototypes of the same canonical native C++ function emit one adapter/declaration. Distinct overloads can be assigned unique output names through declaration visitors. Customized generation retains native cursor signatures and chooses the original overload with an exact typed C++ function pointer. FOREIGN_FUNC_DECLARATION and INNER_WRAPPER_CALL callbacks select boundary and call argument order. Tests rename records/fields/functions, reorder parameters, omit declarations, execute POD/reference adapters and preserve destinations after duplicate-name errors. Customized hidden/unavailable functions must be omitted or generation fails. Namespace/method/template and arbitrary ABI-changing mappings remain unfinished.

`append_cpp_literal` and `append_cpp_expression` emit a C++17 subset from public model nodes. Tests compile and execute generated consumers at O0/O2 after interpreter/native emitter runs. They verify integer limits, precise floats, binary strings, native enum names, casts, sizeof and precedence. Unsupported nodes fail without changing existing builder text. This is fragment rendering, not C++ header parsing or bridge generation. Native declarations must exist in the supplied scope; width-only scalar casts do not establish C++ overload identity. Syntax follows the [C++17 draft](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2017/n4659.pdf).

The binding-model void/bool predicates follow explicit scalar flags and typedef links, excluding pointers, arrays, functions, records/enums and references. Alias cycles/depth failures produce diagnostics. Location comparison uses file-handle identity plus line/column; cross-translation-unit file equivalence is not claimed. Original fixtures inspect actual parsed bool/void aliases and call the generated native signatures.

`fill_location` fills the reviewed file/line/column record from native cursor spelling locations, clearing a previous value for a null cursor. `get_clang_type_alignment` preserves libclang alignment/error results; the parsed declaration model uses both helpers. `create_null_literal` returns an initialized caller-owned Literal in the active allocator; generated C++ consumers verify its null pointer effect. Diagnostic range getters and signed evaluation now have direct native invocation coverage, including highlighted operand bytes and resource cleanup.

The native token API now exposes reviewed token kinds, spelling, locations/extents and cursor annotations, plus cursor kind/lookup/equality. Keep the translation unit alive while using tokens/cursors, dispose token arrays with libclang and dispose returned CXString spellings individually. Annotation arrays are caller-owned. Tests match every token to original header bytes and verify declaration annotations; Windows/Unix enum signedness follows the reviewed native ABI.

The reviewed virtual-overlay and module-map descriptor APIs now invoke libclang's real build-system utilities. Overlay mappings reject relative virtual paths; generated case-insensitive overlays are consumed by native header parsing. Generated framework module maps are imported by native Clang consumers at O0/O2 after each interpreter/native emitter run. Descriptor handles and returned buffers use their matching native disposal APIs, following the [official build-system API](https://clang.llvm.org/doxygen/group__BUILD__SYSTEM.html). This does not implement the unrelated public generate_bridge path.

The reviewed native records/enums/aliases and all360 direct native functions are now exported. `clang_getFileTime` uses the reviewed POSIX.time_t dependency or a private Windows s64 alias; no Bindings_Generator time_t is exported. Real future timestamps above32 bits and pre-epoch values verify signed64 effects and canonical return identity. An independent public-header C probe supplies1,176 size/alignment/offset/enum-value comparisons for interpreter/native O0/O2 consumers. All360 native function names resolve in the installed SDK; most newly added functions still have source and symbol-availability evidence only. Symbol lookup does not establish argument/callback invocation correctness. The [native ABI evidence](native/developer-tools-native-abi-evidence.json) and per-API inventory preserve this distinction. General generator algorithms and C++ bridges remain incomplete.

Source-query coverage now directly invokes physical and presumed-location readers, file identity/real-path queries, range construction/comparison and native cursor sets. An original `#line` header separates physical line3 from presumed line100; four location readers are called through native function pointers. File IDs remain opaque; tests compare repeated queries rather than interpret platform words. Native cursor sets retain their native-owned insertion/deduplication/disposal behavior.

The direct native C++ AST queries now have constructor/assignment/method/class, linkage/TLS/mangling and visitor-callback effects against an original C++17 hierarchy. An independent C probe verifies class visitor returns and counts. The installed SDK returns1 for both complete and stopped visits, contrary to its header's return comment; the binding preserves native results, with early termination verified through the callback count. This query fixture does not execute class method bodies; the separate bridge fixture executes global C++ function bodies.

## Print_Vars

`print_vars_to`, `print_vars` and `log_vars` expand over caller expressions. They retain caller scope, use Program_Print for source names, evaluate each expression once, render values/types and align name/value columns. The helper accepts the exact reviewed fixed Code array; the variadic entry points create that array at compile time. `Print_Vars_Config` controls fields, delimiters, indentation and line separators. Logging forwards the caller location. Widths currently count UTF-8 bytes; see questions and deviations for display-cell and source-whitespace limits.

## Rewrite

Initialize a `My_Plugin` through `init`, feed its `gather` hook compiler messages, and call `finish`. Default mode reports edits; explicit `write` enables mutation. No public factory absent from the reviewed contract is added. Deprecated `<<expr` becomes `(expr).*` using the original source expression span. Source snapshots are reread and compared before writes. Overlapping/invalid edits and stale files are refused with diagnostics. Public edit helpers also support independently supplied edits with multiline/CRLF data. Plugin-owned resources are released by its shutdown hook; direct helper callers retain ownership of their input records and strings.

## Debug_Info frame parsing

The initial subset decodes DWARF call-frame instructions and common information entries. It bounds every fixed/LEB128 read, rejects overflow/truncation/unsupported operands, and returns no partial successful result. It supports DWARF32 CIE versions 1/3/4 and little-endian integer operands. Augmentation string/data views borrow input; decoded instruction arrays belong to the active allocator. Operand formats follow the [official DWARF5 specification](https://dwarfstd.org/doc/DWARF5.pdf); public names/records/opcodes follow the reviewed module spec. The fixture parses .eh_frame from an original Clang-built C object and rejects every truncated CIE prefix. Other Debug_Info parsers remain unfinished.

`parse_frame_description_entry` additionally parses DWARF32 `.debug_frame` entries associated with version4 CIEs with empty augmentation and explicit 4/8-byte addresses. It recovers the address width from the supplied section bytes, verifies the absolute CIE pointer and bounds, and returns caller-owned decoded instructions. Original x86/x64/arm64 C O0/O2 objects verify ranges and opcode sequences against LLVM, plus every truncated prefix. Segmented addresses, full DWARF64 and other augmentation encodings remain unsupported. The explicit-width format follows [DWARF4 sections6.4.1 and7.4](https://dwarfstd.org/doc/DWARF4.pdf).

The required reviewed `.eh_frame` path is now implemented: version1/id0 CIEs, resolved backward CIE references, absolute8-byte/default encoding and signed4-byte PC-relative addresses with unsigned4-byte ranges. CIE strings and FDE augmentation bytes borrow input; decoded opcodes belong to the caller. CIE extended-length markers are read without claiming full DWARF64. Sixteen real linked/native-format frames exercise both relative signs and absolute/default forms, with exact SDK range/opcode oracles, truncation, unsupported encoding and arithmetic bounds checks. The earlier `.debug_frame` support remains an independently designed addition. Other augmentation payload kinds, segmented/full-DWARF64 forms and expression opcodes remain unsupported.

CodeView line and register-relative flag helpers retain reviewed records/signatures. Their packed fields follow [Microsoft's public cvinfo.h](https://github.com/microsoft/microsoft-pdb/blob/master/include/cvinfo.h). Original C fixtures compiled for Windows x64/arm64 supply data for host-side decoding tests. These helpers allocate nothing; complete CodeView symbol/type parsing remains unfinished.

Codeview_Debug_Info and its required string/checksum/line context records now support bounded NUL-terminated string lookup and filename lookup by stored checksum ID. Results borrow the supplied string-table bytes; missing/unterminated data returns false and duplicate matching IDs are diagnosed. Four original C Windows x64/arm64 O0/O2 C13 sections match SDK filename/file-ID oracles and SDK/source MD5 checksums. This is actual lookup over native-produced data, with no full Jai symbol/type-parser claim. The refreshed reviewed public enum sentinels and dependent aliases are implemented exactly; borrowed-string/derived-record storage precision remains in questions12–13.

DWARF line-address queries now expose the reviewed Line_Info/File_Info/Line_Info_Sequence/Line_Mapping records and Dwarf_File_Id alias. Point queries select the final row at a repeated address and exclude end-sequence boundaries. Range queries return nonempty intersecting rows in table order; callers free the returned array. Queries reject malformed arrays, reversed ranges and covered overlapping sequences with diagnostics. An original C program supplies real DWARF4 x64/arm64 O0/O2 line tables; LLVM-decoded rows form an independent oracle for every covered byte and interval boundary. Filename rendering/index conventions and full line-byte parsing remain pending.

Canonical Debug_Info/Compilation_Unit/Debug_Type/Subprogram/Declaration/Lexical_Block records now use the reviewed fields, declaration-kind values and existing canonical Bucket_Array dependency. Required DWARF language/tag/base-type enum values come only from the reviewed spec. get_type(cu, type) finds a stored Debug_Type.offset and returns a borrowed pointer into cu.types; missing offsets return null, and duplicate offsets are diagnosed. Six original C x86/x64/arm64 O0/O2 objects supply SDK-decoded type metadata for unsorted-table/all-offset checks. This is a model-query effect; the actual DWARF compilation-unit and line byte parsers remain unfinished.

`Int_Set`, `cardinality` and `is_set` retain the reviewed borrowed u32-word view. Membership rejects negative/out-of-range indices; cardinality counts stored bits without allocating.

A private staged MSF7 reader decodes stream directories and validates duplicate page ownership/reachable-page free-map consistency. Separately, canonical public Msf/Free_Page_Map records and read helpers now retain reviewed contextual storage privately. Public is_msf/is_pdb identify the signature, stream/page predicates check bounds, and get_stream_data returns an owned copy after layout/page validation. These support4096-byte MSF7 pages. Original Clang/LLD Windows x64/arm64 PDBs have every stream compared against official llvm-pdbutil exports; malformed descriptors and copied-buffer mutation isolation are tested. The wire-format input is [LLVM's official MSF documentation](https://llvm.org/docs/PDB/MsfFile.html). Public parse_msf, FPM algorithms and integrity integration remain pending; missing derived parameter policies and PDB map field names are precise questions. Native-format host decoding is distinct from Windows execution.

## Debug native helpers

The macOS/Linux/Windows subset captures and symbolizes stacks, checks debugger presence, probes one byte through kernel APIs, writes text, aborts with reviewed exit codes and traps only when a debugger is present. Symbol text and its array share one native allocation; release the original complete array with `free_backtrace`. Capture is bounded at4096 physical frames, with256 slots in the convenience overload. Actual macOS interpreter/native effects remain separate from Linux source-only support, Windows cross-build evidence and Android/WASM target checks. Unix signal lifecycle and non-graphics assertions are now implemented as described below; Windows lifecycle, dialogs, minidumps and attachment remain unfinished.

On macOS/Linux, init installs the five reviewed signal actions and changes the runtime assertion callback only while it remains default. Enable/disable are idempotent and restore the saved action, mask and flags. Normal print_assert/trace_assert helpers report source location/message and actual stack symbols; installed genuine assertion failures exit Assert3. Fatal native callbacks receive one borrowed actual fault-PC string. The native signal handler uses stack storage and OS write/exit operations, avoiding allocation and symbolization; caller callbacks must be signal-safe. Returning callbacks terminate Exception4 as an independent safety choice pending reviewer precision. This intentionally limits fatal trace detail; normal backtrace remains fully symbolized. Signal installation/restoration follows [Apple's official sigaction documentation](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/sigaction.2.html). Report mode storage is separate from the enable argument; graphics consumption remains pending.

The Windows backend uses SDK stack capture, DbgHelp symbols, kernel memory reads and UTF-8 console/pipe output. `python3 tools/check_developer_debug_windows.py` cross-builds x64 DLL/test executables, checks exports and compiles arm64 code with warnings denied. Its [evidence](native/developer-tools-windows-debug-evidence.json) does not claim Windows execution. `tools/build_developer_debug.py` also has a native Windows clang/SDK build path. DbgHelp calls in this helper are serialized with per-call initialization/cleanup and a separate process handle; shared serialization with other DbgHelp clients is an integration dependency. See [Microsoft's API documentation](https://learn.microsoft.com/en-us/windows/win32/api/dbghelp/nf-dbghelp-syminitializew).

MSF free-page helpers query/clear/set bits in caller-supplied initialized maps, using the standard [MSF free-page bit meanings](https://www.llvm.org/docs/PDB/MsfFile.html). `is_fpm_page_number` supports MSF7 big maps with4096-byte pages. Original x64/arm64 PDBs and official SDK FPM byte exports verify every bit; boundary mutation tests restore owned copies and preserve native inputs. Maps must currently have iwMac==rgw.count and sufficient storage. Invalid bounds and unsupported reserved-page layouts fail explicitly. Initialization/growth/rover/fill policy remains open; this does not claim parse_msf construction.

The staged private DWARF4 line decoder now reads actual original x86/x64/arm64 C O0/O2 section bytes and matches official SDK rows, following [DWARF4 sections6.2 and7.21](https://dwarfstd.org/doc/DWARF4.pdf). It retains raw file/directory IDs, borrows path bytes, owns decoded arrays and rejects malformed/unsupported records without partial results. Canonical Line_Program_Header has the reviewed packed fields. This is a tested parser dependency; public compilation-unit/DIE parsing and filename/index integration remain unfinished.

## Iprof report output and Codex inspection

Iprof reports display stored seconds as milliseconds, write an informational command line followed by name/self (ms)/hier (ms)/calls CSV columns, and log file-write failures. Text filtering applies positive self/hier thresholds independently; nonpositive thresholds are disabled. CSV quoting is an independent improvement beyond the reviewed escaping guarantee. These tests supply measured-row values explicitly; runtime instrumentation and history sampling remain pending.

History_Scalar retains the reviewed three values/variances and128 stored samples. set_smoothing clamps the public slot to0–2, default1; get_value reads that selected observation and clear zeroes the scalar record. Module instances retain their own selector storage. Canonical tracker/stack records now support count_recursion_depth over zone pointer identities, preserving caller-owned nodes and diagnosing cycles. These are actual storage/inspection helpers, with no timer sampling or variance-update claim.

Manual clients now have measured init_runtime, Stack_Push, zone_begin and zone_end. Initialize each used zone explicitly, retain its address, and balance begin/end calls. Native monotonic clocks supply POSIX nanoseconds or Windows performance-counter ticks, with the matching timestamps_to_seconds factor. Actual node fields accumulate self/hierarchical ticks, entry counts and recursion depth. A private zone/parent map preserves node addresses through growth and validates cached parent identity. Storage uses the persistent default allocator and survives temporary-arena reset. Unbalanced ends, excessive nesting and altered stack state diagnose failure. Sampling, smoothing updates, automatic instrumentation and create_report remain unfinished; a test manually composes report rows from measured counters and verifies genuine millisecond CSV output.

TO_INSERT now supplies actual generic context-alias client setup, and prepend_main/Prepend_To_Main initialize the runtime before inserted main work. All eight MANUAL_MODE/USE_GRAPHICS/DO_HISTORY combinations are preserved. The setup strings are independent source templates with reviewed purpose, not promised literal formatting. Actual generated O0/O2 clients verify their parameter values and measured-node entry effects. This does not provide the still-pending automatic instrumentation plugin.

Iprof's initial subset writes caller-supplied report rows to logs or properly quoted CSV. It omits zero-call rows and uninitialized zones in manual mode, retains conditional zone-history storage, and applies requested text-report minimums. The actual runtime profiler and graphics are unfinished; report tests supply original explicit values rather than claim measured zones.

Codex retrieves code-node file/import metadata and inspects resolved declarations' IS_GLOBAL flags. Its Math import retains canonical identity. The canonical Metrics record and collect_metrics count resolved/unresolved calls, exclude resolved type instantiations, compare file/module identity, recognize assignment operators, count global identifier reads/direct writes and measure nested for/while depth. Global procedure identifiers also count as global reads. Original intercepted procedure bodies and native public-node models exercise these effects.

Conditional forms fail explicitly until their exact if_points weights are reviewed; calls into Basic fail until its fixed allocation/free name set is reviewed. Binary writer/reader/plugin integration remains pending precise canonical relative-string encoding and inline placement. See the per-function remaining matrix and deviations.

## Check

The Windows-only subset exposes the reviewed settings and checks compiler records for array/pointer misuse and small-operand integer promotion risks. It supports manual body invocation and compiler messages, follows module skip settings, and reports continuable compiler errors. Original tests include a real intercepted small-integer procedure and manual array-assignment records. Mangled binding verification now parses official LLVM Itanium/MSVC ASTs and compares canonical Jai scalar/pointer/reference/function/array/nominal types, skipping method receivers. It does not look up libraries or external symbol existence. Same-name/non-ELSEWHERE checks skip, unsupported targets log once, and mismatches produce continuable errors plus false. Explicit print-format checking remains outside the implemented porting subset. Two general producer/contract observations are preserved under compiler-requests and listed in progress/questions, separate from the supported passing suite.


Check's source-built demangler helper uses the [official LLVM demangler interface](https://llvm.org/doxygen/Demangle_8h.html) and installed SDK AST headers, with configured SDK library links. Run tools/build_developer_check.py before using the supported mangled-signature workflow. Real normalized type storage is reused and reports peak/cumulative in-band bytes when debug accounting is enabled; default finish is silent. Tests stage unchanged NEW code on Mac while retaining the Windows-only production facade. Windows execution, broader mangled type forms and renamed nominal mapping remain pending. Actual Compiler headers currently omit the reviewed ELSEWHERE flags; the preserved minimal producer request identifies this integration gap without changing Check's contract.
