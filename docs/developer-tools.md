# Developer tooling

Implementation follows the reviewed public contracts, with canonical records in public modules and private mechanisms under `stdlib/internal/developer-tools`. [Progress](status/developer-tools-progress.md), [deviations](status/developer-tools-deviations.md), [plan](plans/developer-tools.md) and [contract questions](specs/stdlib/developer-tools-questions.md) describe scope and incomplete paths.

## Generate_C_Header

`Header_Info` retains every reviewed public field and zero/default initialization. Populate `exported_types` with reflected types and their C names, or feed `handle_message` compiler TYPECHECKED messages containing PROGRAM_EXPORT declarations. `generate_header` gathers dependencies, forwards struct/union tags, orders by-value definitions, emits C declarators and checks errors before writing. It excludes `main`.

The supported projection includes scalar types, fixed arrays, recursive pointers, ordinary structs/unions, variants, C-call procedures and runtime support records discovered through Header_Info. Enum output defaults to normal C enums; enum_internal_types selects C23 fixed-underlying syntax. Enum member prefixes use uppercase letters from the emitted type name, and type clashes receive numeric suffixes. Procedure values become void pointers. Every record includes C/C++ static assertions for reflected runtime size, alignment and field offsets; compiling the generated header is required validation. Non-C-call procedures, polymorphic structs and imported/constant/void fields are omitted as reviewed. Other unsupported ABI categories produce errors.

Original tests generate headers from real type descriptors, compile C11/C23/C++17 consumers, and call native helpers through Jai FFI. Tests cover field mutation, enum modes, opaque callbacks, support layouts, collision suffixes, non-C-call omission and multiple-return rejection preserving existing output. Support-layout fixtures use test-only records following reviewed bootstrap shapes, not duplicate production prelude definitions. `python3 tools/check_developer_tools.py` runs interpreter/native O0/O2, formatting/lint and target checks using this worktree's source-built tools. Host dylib construction currently targets macOS; Linux runner adaptation is unfinished.

The module is a supported subset. See deviations for production support-descriptor availability, reserved names, explicit alignment/packing and transactional output limits.

## Performance_Report

`+Performance_Report` requests compiler timing, bytecode counters, run-directive records and polymorph records. It buffers a textual summary, sorts run records by elapsed time, and writes on plugin finish. Counters and durations come from Compiler messages. A missing message produces a compiler warning; missing per-category flags are explicitly identified in the summary. Shutdown frees owned state. There are no public configuration options in the reviewed contract.

## Bindings_Generator and staged C parser

`tools/check_developer_bindings.py` builds an independently authored private C generator against the installed official libclang C API. It parses original C headers, emits real Jai bindings with layout assertions, compiles the original native implementation, and exercises generated bindings in interpreter/native O0/O2. Malformed headers and unsupported constructs fail with source diagnostics while preserving existing output. The two-target test verifies LP64/LLP64 C `long` differences and checks generated declarations under matching Jai targets.

The public facade retains reviewed option/model shapes and defaults, exact compatibility arrays, target parameter and literal conversion rules. Both generate_bindings overloads validate a supported one-header/one-library configuration and invoke the source-built backend. It discovers official Clang include paths, unwraps reviewed typedefs, preserves named C parameters/documentation, supports common enum prefixes/aliases and outputs real callable bindings. Malformed input and unsupported options fail with diagnostics and preserve existing output. Returned builders are caller-owned.

Standalone declaration visitors and enum/argument/return-type mutation helpers operate on caller-supplied public model records. Traversal snapshots child pointers, visits shared declaration pointers once and preserves stored parent links. Generation also materializes a C model for both visitor forms and the custom argument-printing hook. Callbacks can rename declarations/parameters, change types and omit output. Generated references follow record names and foreign functions retain original native symbols. Original fixtures rename a record, function and parameter, compile the result and execute C callbacks. Invalid callback output fails and preserves the destination. During generation, parsed nodes/strings/arrays are borrowed until return: do not free or retain them. Caller-created replacement CType records remain caller-owned. Empty include guards and reviewed ignored macros are handled.

Object-like numeric macros are evaluated by official Clang using an independently generated unsaved C probe. Output preserves native integer signedness/width and floating type, including arithmetic expressions and target-specific sizeof. No macro expression is executed. The public callback model exposes evaluated Literal nodes and respects renamed names and DISCARD decisions. Macro-to-enum callbacks can create or extend named enum groups when native integer widths/signedness match; incompatible groups fail and preserve the destination. Grouping precedes prefix processing and declaration visitors in the current supported path. Function-like, string and nonfinite macros fail explicitly. Evaluation currently reparses the header for each numeric macro, a documented performance limitation.

Run `python3 tools/build_developer_bindings.py --llvm-prefix <official-sdk>` to build the helper beside its private stdlib sources and link the native API to the installed SDK through a private symlink. It neither copies SDK binaries nor depends on the repository target directory. The helper and symlink must be rebuilt for the destination SDK; shared build integration remains coordinator-owned. The [official libclang C API documentation](https://clang.llvm.org/doxygen/group__CINDEX.html) and installed public headers are the only native parser compatibility inputs. The [SDK evidence](native/developer-tools-clang-evidence.json) identifies them. Native APIs also cover diagnostics, source locations, unsaved files and type queries. The reviewed CXIndexOptions record and three bit-view setter/getter pairs preserve reserved bits and match an official C layout probe, including real native index creation. Verification uses libclang23 against the reviewed version21 constant. Callback generation currently parses twice, and C++ bridges, preprocessing models and remaining helpers/reexports are unfinished.

`append_cpp_literal` and `append_cpp_expression` emit a C++17 subset from public model nodes. Tests compile and execute generated consumers at O0/O2 after interpreter/native emitter runs. They verify integer limits, precise floats, binary strings, native enum names, casts, sizeof and precedence. Unsupported nodes fail without changing existing builder text. This is fragment rendering, not C++ header parsing or bridge generation. Native declarations must exist in the supplied scope; width-only scalar casts do not establish C++ overload identity. Syntax follows the [C++17 draft](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2017/n4659.pdf).

The binding-model void/bool predicates follow explicit scalar flags and typedef links, excluding pointers, arrays, functions, records/enums and references. Alias cycles/depth failures produce diagnostics. Location comparison uses file-handle identity plus line/column; cross-translation-unit file equivalence is not claimed. Original fixtures inspect actual parsed bool/void aliases and call the generated native signatures.

`fill_location` fills the reviewed file/line/column record from native cursor spelling locations, clearing a previous value for a null cursor. `get_clang_type_alignment` preserves libclang alignment/error results; the parsed declaration model uses both helpers. `create_null_literal` returns an initialized caller-owned Literal in the active allocator; generated C++ consumers verify its null pointer effect. Diagnostic range getters and signed evaluation now have direct native invocation coverage, including highlighted operand bytes and resource cleanup.

The native token API now exposes reviewed token kinds, spelling, locations/extents and cursor annotations, plus cursor kind/lookup/equality. Keep the translation unit alive while using tokens/cursors, dispose token arrays with libclang and dispose returned CXString spellings individually. Annotation arrays are caller-owned. Tests match every token to original header bytes and verify declaration annotations; Windows/Unix enum signedness follows the reviewed native ABI.

The reviewed virtual-overlay and module-map descriptor APIs now invoke libclang's real build-system utilities. Overlay mappings reject relative virtual paths; generated case-insensitive overlays are consumed by native header parsing. Generated framework module maps are imported by native Clang consumers at O0/O2 after each interpreter/native emitter run. Descriptor handles and returned buffers use their matching native disposal APIs, following the [official build-system API](https://clang.llvm.org/doxygen/group__BUILD__SYSTEM.html). This does not implement the unrelated public generate_bridge path.

The remaining reviewed native records/enums/aliases and direct native functions are now exported, with `clang_getFileTime` held pending its undefined reviewed `time_t` dependency. An independent public-header C probe supplies 1,176 size/alignment/offset/enum-value comparisons for interpreter/native O0/O2 consumers. All 359 implemented native function names resolve in the installed SDK; most newly added functions have source and symbol-availability evidence only. Symbol lookup does not establish argument/callback invocation correctness. The [native ABI evidence](native/developer-tools-native-abi-evidence.json) and per-API inventory preserve this distinction. General generator algorithms and C++ bridges remain incomplete.

Source-query coverage now directly invokes physical and presumed-location readers, file identity/real-path queries, range construction/comparison and native cursor sets. An original `#line` header separates physical line3 from presumed line100; four location readers are called through native function pointers. File IDs remain opaque; tests compare repeated queries rather than interpret platform words. Native cursor sets retain their native-owned insertion/deduplication/disposal behavior.

The direct native C++ AST queries now have constructor/assignment/method/class, linkage/TLS/mangling and visitor-callback effects against an original C++17 hierarchy. An independent C probe verifies class visitor returns and counts. The installed SDK returns1 for both complete and stopped visits, contrary to its header's return comment; the binding preserves native results, with early termination verified through the callback count. This is native parser-query evidence, with C++ method-body execution and high-level bridge generation still pending.

## Print_Vars

`print_vars_to`, `print_vars` and `log_vars` expand over caller expressions. They retain caller scope, use Program_Print for source names, evaluate each expression once, render values/types and align name/value columns. The helper accepts the exact reviewed fixed Code array; the variadic entry points create that array at compile time. `Print_Vars_Config` controls fields, delimiters, indentation and line separators. Logging forwards the caller location. Widths currently count UTF-8 bytes; see questions and deviations for display-cell and source-whitespace limits.

## Rewrite

Initialize a `My_Plugin` through `init`, feed its `gather` hook compiler messages, and call `finish`. Default mode reports edits; explicit `write` enables mutation. No public factory absent from the reviewed contract is added. Deprecated `<<expr` becomes `(expr).*` using the original source expression span. Source snapshots are reread and compared before writes. Overlapping/invalid edits and stale files are refused with diagnostics. Public edit helpers also support independently supplied edits with multiline/CRLF data. Plugin-owned resources are released by its shutdown hook; direct helper callers retain ownership of their input records and strings.

## Debug_Info frame parsing

The initial subset decodes DWARF call-frame instructions and common information entries. It bounds every fixed/LEB128 read, rejects overflow/truncation/unsupported operands, and returns no partial successful result. It supports DWARF32 CIE versions 1/3/4 and little-endian integer operands. Augmentation string/data views borrow input; decoded instruction arrays belong to the active allocator. Operand formats follow the [official DWARF5 specification](https://dwarfstd.org/doc/DWARF5.pdf); public names/records/opcodes follow the reviewed module spec. The fixture parses .eh_frame from an original Clang-built C object and rejects every truncated CIE prefix. Other Debug_Info parsers remain unfinished.

`parse_frame_description_entry` now parses DWARF32 `.debug_frame` entries associated with version4 CIEs with empty augmentation and explicit 4/8-byte addresses. It recovers the address width from the supplied section bytes, verifies the absolute CIE pointer and bounds, and returns caller-owned decoded instructions. Original x86/x64/arm64 C O0/O2 objects verify ranges and opcode sequences against LLVM, plus every truncated prefix. `.eh_frame`, implicit-width CIEs, segmented addresses, DWARF64 and augmentation encodings remain unsupported. The explicit-width format follows [DWARF4 sections6.4.1 and7.4](https://dwarfstd.org/doc/DWARF4.pdf).

CodeView line and register-relative flag helpers retain reviewed records/signatures. Their packed fields follow [Microsoft's public cvinfo.h](https://github.com/microsoft/microsoft-pdb/blob/master/include/cvinfo.h). Original C fixtures compiled for Windows x64/arm64 supply data for host-side decoding tests. These helpers allocate nothing; complete CodeView symbol/type parsing remains unfinished.

DWARF line-address queries now expose the reviewed Line_Info/File_Info/Line_Info_Sequence/Line_Mapping records and Dwarf_File_Id alias. Point queries select the final row at a repeated address and exclude end-sequence boundaries. Range queries return nonempty intersecting rows in table order; callers free the returned array. Queries reject malformed arrays, reversed ranges and covered overlapping sequences with diagnostics. An original C program supplies real DWARF4 x64/arm64 O0/O2 line tables; LLVM-decoded rows form an independent oracle for every covered byte and interval boundary. Filename rendering/index conventions and full line-byte parsing remain pending.

`Int_Set`, `cardinality` and `is_set` retain the reviewed borrowed u32-word view. Membership rejects negative/out-of-range indices; cardinality counts stored bits without allocating.

A private staged MSF7 reader now decodes stream directories, copies scattered stream data and validates bounds, duplicate page ownership and reachable-page free-map consistency. It supports 4096-byte blocks; other block sizes and nil streams return explicit errors. Parsed views borrow immutable file bytes and own their stream/page arrays; copied stream bytes belong to the caller. The wire-format input is [LLVM's official MSF documentation](https://llvm.org/docs/PDB/MsfFile.html). Original Clang/LLD Windows x64/arm64 PDBs have every stream compared against official llvm-pdbutil exports. A synthetic multi-block directory exercises reversed, nonadjacent data pages and malformed ownership. Missing reviewed Msf dependency shapes prevent a public parser facade; this private evidence is staged, not public API completion.

## Debug native helpers

The macOS/Linux/Windows subset captures and symbolizes stacks, checks debugger presence, probes one byte through kernel APIs, writes text, aborts with reviewed exit codes and traps only when a debugger is present. Symbol text and its array share one native allocation; release the original complete array with `free_backtrace`. Capture is bounded at4096 physical frames, with256 slots in the convenience overload. Actual macOS interpreter/native effects remain separate from Linux source-only support, Windows cross-build evidence and Android/WASM target checks. Signal/assert/dialog/minidump/attachment paths remain unfinished.

The Windows backend uses SDK stack capture, DbgHelp symbols, kernel memory reads and UTF-8 console/pipe output. `python3 tools/check_developer_debug_windows.py` cross-builds x64 DLL/test executables, checks exports and compiles arm64 code with warnings denied. Its [evidence](native/developer-tools-windows-debug-evidence.json) does not claim Windows execution. `tools/build_developer_debug.py` also has a native Windows clang/SDK build path. DbgHelp calls in this helper are serialized with per-call initialization/cleanup and a separate process handle; shared serialization with other DbgHelp clients is an integration dependency. See [Microsoft's API documentation](https://learn.microsoft.com/en-us/windows/win32/api/dbghelp/nf-dbghelp-syminitializew).

## Iprof report output and Codex inspection

Iprof's initial subset writes caller-supplied report rows to logs or properly quoted CSV. It omits zero-call rows and uninitialized zones in manual mode, retains conditional zone-history storage, and applies requested text-report minimums. The actual runtime profiler and graphics are unfinished; report tests supply original explicit values rather than claim measured zones.

Codex's initial helpers retrieve a code node's file/import and inspect a resolved declaration's IS_GLOBAL flag. Its public Math import retains canonical module/type identity. The binary metadata format and metrics semantics require refinement before the remaining APIs can be implemented without invented compatibility answers.

## Check

The Windows-only subset exposes the reviewed settings and checks compiler records for array/pointer misuse and small-operand integer promotion risks. It supports manual body invocation and compiler messages, follows module skip settings, and reports continuable compiler errors. Original tests include a real intercepted small-integer procedure and manual array-assignment records. Native binding/symbol and print-format checks remain pending. Two general producer/contract observations are preserved under compiler-requests and listed in progress/questions, separate from the supported passing suite.
